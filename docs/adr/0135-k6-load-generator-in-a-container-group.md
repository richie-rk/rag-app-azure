# ADR 0135: k6 load generator in a container group

- **Status:** Accepted
- **Date:** 2026-10-21; amended 2026-10-30 (the job's runner from the CI path of ADR 0122)
- **Decided by:** Architect
- **Specified in:** 84-testing.md, 01-repository.md, 83-infrastructure.md, 86-operations.md
- **Related ADRs:** 0010, 0019, 0122, 0126, 0131, 0134, 0151

## Context

ADR 0134 sets the scenarios: an open-model arrival rate for the cheap endpoint (its rate must not fall when the API slows), up to 100 concurrent NDJSON streams, a scale-out phase of up to 60 turns per second, and machine-checked pass criteria. The 200 ms p95 criterion is client-side, so the generator must sit close to the API, or the number measures the internet path rather than the API. The generator also holds test tokens, so it must need nothing built, scanned or kept between runs, and no Azure rights of its own.

Vendor facts: under `restartPolicy: 'Never'` a container that exits 0 is never restarted, but one that exits nonzero "might still be restarted by the platform". A container group that pulls from a network-restricted Azure Container Registry needs the registry's trusted services enabled. Anonymous Docker Hub pulls are rate-limited per IP address, and Azure services such as Container Instances share addresses. A secret volume is read-only once deployed, backed by tmpfs so its contents never reach nonvolatile storage, and takes Base64 values in the template. k6's arrival-rate executors are open-model, its thresholds exit 99 when crossed, and it ships as one static binary per release with a checksums file. Azure Load Testing runs only JMeter and Locust scripts.

## Decision

1. **k6 2.3.0, pinned by checksum.** `tests/load/k6.lock.json` = `{"version": "2.3.0", "url": "https://github.com/grafana/k6/releases/download/v2.3.0/k6-v2.3.0-linux-amd64.tar.gz", "sha256": "39c3117b6af817592dcd0ce4242105c0a7af10948c2a425306f0be8f7a8a8ab1", "member": "k6-v2.3.0-linux-amd64/k6"}` (from the release's `k6-v2.3.0-checksums.txt`, read 2026-10-15). `scripts/ci/check_k6_lock.py` fails CI when the lock's SHA-256 differs from the official checksums file of its version.
2. **Scripts.** JavaScript ES modules in `tests/load/k6/`, one file per scenario, each importing only `./lib.js`, so a scenario runs from two flat files. `lib.js` holds the stream reader and validator, the token loader (`open()` of `DOCCHAT_LOAD_TOKENS_FILE` in the init stage), the marker-line printer and the request helper every call uses: on a `429` whose problem `code` is `too_many_requests` or `write_rate_limited` it sleeps `retryAfterSeconds` and retries once, marks that first response expected through the request's `responseCallback` (so it isn't counted in `http_req_failed`) and increments the counter `limit_retries`, which the verdict reports; a `429` with any other code fails the request. k6 buffers response bodies, so each NDJSON stream is validated line by line when it ends. Scripts print three marker lines to standard output and never a header or a token: `K6_SUMMARY_JSON <json>` (from `handleSummary`, with every threshold's `ok` and `limit_retries`), `K6_FAILED_REQUEST {"traceId", "startedAt", "endedAt", "status", "reason"}` and `K6_SESSION {"sessionId", "traceIds": [...]}`.
3. **The container group (S1 to S3).** One per scenario in `rg-docchat-load`, in the `load` region, from `tests/load/aci/loadgen.bicep` (`Microsoft.ContainerInstance/containerGroups@2026-07-01`): name `ci-docchat-loadgen-<scenario>-<run number>`, `osType: 'Linux'`, `sku: 'Standard'`, `restartPolicy: 'Never'`, no virtual network, no inbound IP, no managed identity; one container `k6` with 4 vCPU and 8 GB; image = the template's `image` parameter; command `["python", "/work/run.py"]`, which replaces the image's entrypoint, so the Functions host never starts; environment `K6_URL`, `K6_SHA256`, `K6_MEMBER` (from the lock), `DOCCHAT_LOAD_TOKENS_FILE=/work/tokens.json` and the scenario's non-secret variables; one secret volume `work` mounted read-only at `/work` holding `run.py`, `scenario.js`, `lib.js` and `tokens.json`, each a Base64 value from an `@secure()` parameter.
4. **The image.** `docchat-load aci-params` sets `image` to the reference on the final `FROM` line of `apps/ingestion/Dockerfile` (today `mcr.microsoft.com/azure-functions/python:4.1055.300-3-python3.13@sha256:a7f5fb3a2f98c9f883eaa2b6f2d2f602d9fc44f41a91c450623b6784c2d7b379`, since 2026-11-07) and exits 2 unless it starts `mcr.microsoft.com/azure-functions/python:` and carries a `@sha256:` digest. Microsoft Artifact Registry serves it, so nothing comes from Docker Hub or from the shared registry, whose trusted-services access stays off; it is already scanned with the ingestion image and kept current by Dependabot's `docker` entry.
5. **The bootstrap, `tests/load/aci/run.py`.** Python 3.13 standard library only: download `K6_URL` with `urllib.request.urlopen` (timeout 120 s, 3 attempts 15 s apart); refuse the file unless its SHA-256 equals `K6_SHA256`; read exactly the member `K6_MEMBER` with `tarfile.extractfile` and write its bytes to `/tmp/k6` (no other member is read and nothing is extracted by path, so the archive can't write elsewhere); set mode 0755; run `["/tmp/k6", "run", "--quiet", "/work/scenario.js"]` as a child process with inherited standard output; print `K6_EXIT <k6 exit code>` and exit 0. A download, checksum or extraction failure prints `K6_BOOTSTRAP_FAILED <reason>` (`download_failed`, `checksum_mismatch`, `member_missing`) and exits 0. The container always exits 0, so the platform never runs a scenario twice.
6. **The job around it** (GitHub environment `load-tests`, `id-docchat-citest` on the test runner of ADR 0122: a standard `ubuntu-24.04` runner by default, `docchat-ci-private` under the private-networking option). `k6 inspect` parses the script with the locked k6; `docchat-load tokens` writes the token file with mode 0600 after printing `::add-mask::` for every token; `aci-params` writes the parameters file with mode 0600 (non-secret `name`, `location`, `image`, `k6Url`, `k6Sha256`, `scenarioEnv`; secure `runPyBase64`, `scenarioJsBase64`, `libJsBase64`, `tokensJsonBase64`); `az deployment group create` deploys the template, and the parameters file is deleted; `az container show` is polled every 15 s until the state is `Succeeded` or `Failed` (timeout = scenario length + 15 minutes), and the container's start time is the scenario's T0, so pull time never counts; `az container logs` saves `load-results/<scenario>/k6.log`; `az container delete --yes` runs with `if: always()`. The identity's DocChat Load Test Operator role (`Microsoft.Resources/deployments/write` and `validate/action`, `Microsoft.ContainerInstance/containerGroups/write` and `delete`, `Microsoft.Insights/autoscalesettings/write`) and Log Analytics Reader at `rg-docchat-load` cover every step.
7. **Reading the result.** `docchat-load verdict` fails the scenario when the log holds `K6_BOOTSTRAP_FAILED` or no `K6_EXIT` line, and reads k6's exit code from `K6_EXIT`: 0 every threshold passed, 99 a threshold failed, any other code a k6 error.
8. **S4 on the runner.** The ingestion scenario isn't an arrival profile and its criteria are server-side durations, so it runs on the GitHub-hosted runner as `docchat-load ingest` on `DeployedApiClient`, whose one retry after `retryAfterSeconds` follows the same rule as `lib.js`; it re-acquires its admin token by ROPC within 5 minutes of expiry during a run of up to 350 minutes.
9. **CI and updates.** The `lint` job runs `check_k6_lock.py`, installs k6 from the locked tarball, runs `k6 inspect` on each scenario and the `lib.js` self-test (`k6 run tests/load/k6/selftest.js` against `scripts/ci/k6_selftest_server.py` on 127.0.0.1). Dependabot has no ecosystem for the lock, so it is updated by hand through a reviewed pull request each quarter (runbook R17).

## Alternatives considered

- **Locust.** Rejected: an open-model arrival rate needs a custom load shape, pass criteria need hand-written logic, and reaching 60 turns per second would need distributed workers; k6's executors and declarative thresholds make the criteria code, and one static binary carries no dependency tree.
- **Azure Load Testing.** Rejected: it runs only JMeter and Locust scripts, so it brings Locust's costs above with a managed service on top.
- **k6 on the GitHub-hosted runner for S1 to S3.** Rejected: the client-side p95 would include the path from the runner's network to the `load` region; a generator in that region measures the API.
- **The official k6 image from Docker Hub.** Rejected: anonymous pulls from Azure's shared addresses are rate-limited, a Docker Hub login would add a credential, and the image would sit outside the set this repository scans.
- **A custom generator image in the shared registry.** Rejected: a container-group pull from the network-restricted registry needs trusted-services access, which stays off, and the image would need building, scanning and a pull identity.
- **A container group joined to a virtual network with a managed identity.** Rejected: the API's public endpoint behind platform authentication is what users reach, so nothing needs a private path, and an identity on a container that holds test tokens adds rights without a use.
- **Letting the container exit with k6's code.** Rejected: a nonzero exit can be restarted by the platform even under `Never`, which would run a scenario twice; the marker line carries the code instead.

## Consequences

- Nothing is built, scanned or kept for the generator between runs; each container group exists only for its scenario, and teardown empties `rg-docchat-load` in any case.
- Tokens reach the container only through the tmpfs-backed secret volume; the token and parameters files on the runner have mode 0600 and the parameters file is deleted after deployment.
- A k6 upgrade is a quarterly manual change checked against the release's checksums; a base-image upgrade arrives with the ingestion image's Dependabot pull request and changes the generator with it.
- A GitHub release download outage fails a scenario with `K6_BOOTSTRAP_FAILED download_failed` after 3 attempts; the scenario is re-run.
- Tests (84-testing.md): `check_k6_lock.py` against a recorded checksums file; `run.py` always exits 0, prints the bootstrap markers and writes nothing but `/tmp/k6`; `verdict` fails a log with neither marker; `aci-params` refuses a reference without a digest; `lib.js`'s retry rule against the self-test server; `DeployedApiClient`'s retry rule.
