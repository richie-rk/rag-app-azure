# ADR 0014: Metadata-only telemetry and logging

- **Status:** Accepted
- **Date:** 2026-10-18
- **Decided by:** Product owner and architect
- **Specified in:** 85-observability.md, 82-security.md, 84-testing.md, 12-chat-pipeline.md, 14-ingestion.md, 10-web-client.md
- **Related ADRs:** 0002, 0009, 0012, 0024, 0029, 0059, 0060, 0088, 0107, 0137, 0138

## Context

Logs and traces carry metadata only: the operation, the user's object ID, project, session, turn, document and run IDs, the outcome, latency and token counts. They never carry prompts, answers, retrieved text, document content, file names, memory facts, email addresses, display names, tokens, keys or connection strings. A turn is investigated by following its session and turn IDs into the conversation store under just-in-time access (ADR 0024), never by reading telemetry. A scrubbing filter in `packages/core` redacts token-shaped and key-shaped strings as a safety net, and a test proves it. Query cost and token usage are recorded from the first version.

Telemetry is read by more people, and kept longer, than the stores it describes: anyone with read access to Application Insights would hold, for the whole retention period, every key, password, conversation or document extract that a log line carried. Questions and documents must never reach a processor outside the organisation's own Azure services through a telemetry or analytics path, and the browser console must not show account names, conversation payloads or access decisions.

The hard part is that content reaches telemetry by paths no call site chooses: an exception message quotes a question, a duplicate-key value or a service's error body; instrumentation records URLs with query strings, SQL text and headers; framework access logs record request lines; and a host's own logging can bypass the app's processors.

Vendor facts (checked 2026-10-14): `azure-monitor-opentelemetry` 1.8.11 is Production/Stable, its `configure_azure_monitor` takes `logger_name`, `instrumentation_options` and `resource`, and it bundles the `azure_sdk`, `django`, `fastapi`, `flask`, `httpx`, `psycopg2`, `requests`, `urllib` and `urllib3` instrumentations; custom events are log records carrying the attribute `microsoft.custom_event.name`. The Python 3.13 Functions worker, when `PYTHON_APPLICATIONINSIGHTS_ENABLE_TELEMETRY` is true, calls `configure_azure_monitor(connection_string=…, logger_name=…)` itself. The Functions host's `telemetryMode: OpenTelemetry` is in preview.

## Decision

1. **What telemetry may carry.** Allowed: the operation, `enduser.id` (the caller's `oid`), project, session, turn, document, version, run, run item, logical and physical index and chunk set IDs, outcome, error code, latency, token counts, byte sizes and counts. Never recorded: prompts, answers, retrieved text, document content, file names, titles, heading paths, memory facts, feedback comments, email addresses, display names, tokens, keys, connection strings, URL query strings, request or response bodies, and headers other than `content-type`, `content-length` and `traceparent`. Telemetry leaves a process only through the Azure Monitor exporters to the environment's own workspace-based Application Insights (ADR 0137); no other telemetry processor, SDK, beacon or analytics endpoint exists in either app or in the web client (ADR 0088).
2. **Records only through registered attributes.** Application log records are emitted only through `docchat_core.telemetry.log_event(logger, event, level, **attributes)`: `event` is a static snake_case name and the record's whole message, and every attribute key must be registered in `docchat_core.telemetry.attributes` with a type (UUID string, enum member, integer, float, boolean or duration) and its allowed values. In tests an unregistered key raises; in production it is dropped and counted in `docchat.telemetry.dropped_attributes`. Ruff's `G` rules forbid f-strings and `%` formatting in logging calls. Custom events are emitted only by `emit_event(name, **attributes)` as a log record carrying `microsoft.custom_event.name` (stored in `AppEvents`); `docchat_core.telemetry.attributes.EVENTS` declares every event with its exact lowerCamelCase properties (`runId`, `projectId`, `outcomeCode`, `oid`) and their types; an undeclared event or property raises in tests and in production is dropped (the whole event, or the property) and counted.
3. **Names.** Spans `docchat.<area>.<operation>` (instrumentation spans keep semantic-convention names such as `POST /v1/chat/turns`); metrics `docchat.<area>.<name>` with UCUM units (`ms`, `s`, `By`, `{token}`, `{request}`, `{item}`, `{stream}`, `{run}`, `1`) and no `_total` suffix; every millisecond histogram uses the buckets `[5, 10, 25, 50, 100, 200, 400, 800, 1600, 3200, 6400, 12800, 25600, 51200, 102400]` through one view. Span and log attribute keys are OpenTelemetry semantic-convention keys where one exists (`enduser.id`, `http.route`, `error.type`, `db.system.name`), otherwise `docchat.<snake_case_name>` for cross-cutting identifiers and outcomes (`docchat.project_id`, `docchat.session_id`, `docchat.outcome`, `docchat.error_code`) and `docchat.<area>.<snake_case_name>` for area fields, lower-case, at most three segments after `docchat`. Metric dimension keys come from a closed set (`outcome`, `reason`, `deployment`, `call`, `kind`, `state`, `stage`, `operation`, `status`, `error_code`, `phase`, `client`, `trigger`, `area`, `key`, `service`, `content_type`, `method_key`, `priority`, `result`, `action`, `rating`, `category`, `pass`, `broadened`, `model`, `error_number`, `outcome_code`, `code`, `source`, `parse_command`); user, project, session, turn, document and run IDs are allowed on spans and events only, never as metric dimensions.
4. **The user and failures.** `enduser.id` is set once, on the server span, by the authentication step; child spans don't repeat it. A failure is logged once, at the boundary, as `request_failed`, `activity_failed` or `job_failed`, with `error.type` (the qualified type name, `module.QualName`) and `docchat.error_code`, never `str(exc)`. Spans record failures through `record_failure(span, exc, code)`: one `exception` event with `exception.type` (the qualified type name), `exception.message` = the code's catalogue message, `docchat.error_code` = the code and `exception.stacktrace` reduced by `safe_traceback(exc)` (item 6); the span status is error with the code as its description.
5. **The scrubbing safety net.** `docchat_core.telemetry.scrubbing` provides `scrub(text) -> str` and three attach points: `ScrubbingLogFilter` (the standard-library filter on the `docchat` logger and the stderr handler: `msg`, `args` and string `extra` values), `ScrubbingLogRecordProcessor` (OpenTelemetry log body and string attributes) and `ScrubbingSpanProcessor` (`on_end`: string attributes of the span and its events). Rules, in order:

   | # | Matches | Replacement |
   |---|---|---|
   | 1 | JWT: `eyJ[A-Za-z0-9_-]{8,}\.[A-Za-z0-9_-]{8,}\.[A-Za-z0-9_-]*` | `[redacted:jwt]` |
   | 2 | Bearer or Basic credentials: `(?i)\b(bearer\|basic)\s+[A-Za-z0-9._~+/=-]{8,}` | `$1 [redacted]` |
   | 3 | Connection-string secrets: `(?i)\b(AccountKey\|SharedAccessKey\|SharedAccessSignature\|Password\|Pwd\|ClientSecret)\s*=\s*[^;"'\s]+` | `$1=[redacted]` |
   | 4 | Signed or secret query parameters: `(?i)([?&](sig\|skoid\|sktid\|code\|token\|access_token\|id_token\|refresh_token\|client_secret)=)[^&#\s"']+` | `$1[redacted]` |
   | 5 | 512-bit base64 keys: `\b[A-Za-z0-9+/]{86}==` | `[redacted:key]` |
   | 6 | Named secret assignments: `(?i)\b(api[-_]?key\|secret\|password\|passwd\|token\|client[-_]?secret\|private[-_]?key\|ocp-apim-subscription-key)(["']?\s*[:=]\s*["']?)[^"'\s,;&}]{4,}` | `$1$2[redacted]` |
   | 7 | PEM private keys: `-----BEGIN [A-Z ]*PRIVATE KEY-----[\s\S]*?-----END [A-Z ]*PRIVATE KEY-----` | `[redacted:private-key]` |
   | 8 | Email addresses: `\b[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}\b` | `[redacted:email]` |

   (`\|` is the alternation `|`, escaped for the table.) Attribute rules: `url.full`, `http.url` and `http.target` lose everything from `?`; `url.query`, `db.query.text`, `db.statement` and every `http.request.header.*` and `http.response.header.*` attribute other than the three allowed headers are removed, so an `Authorization` value is never exported. The rules never change UUIDs, 32-hex trace IDs, 64-hex SHA-256 values, ISO timestamps or numbers. An exception inside a processor replaces the affected value with `[redacted:error]` and counts `docchat.telemetry.scrub_errors`, so a record is never exported unscrubbed.
6. **Exceptions are reduced to frames and type names.** `safe_traceback(exc) -> str` renders an exception from its frames alone: for the exception, each chained cause and context (honouring `__suppress_context__`) and each exception-group member, the header `Traceback (most recent call last):`, the `traceback.format_tb()` lines and the qualified type name, joined by Python's two chaining sentences. `ScrubbingLogFilter` sets `record.exc_text` to it for records with `exc_info`. `ScrubbingSpanProcessor` (every span event named `exception`, whoever recorded it) and `ScrubbingLogRecordProcessor` (every record with `exception.*` attributes) replace `exception.message` with the catalogue message of the `docchat.error_code` when one is set, otherwise with the qualified type name, and keep from `exception.stacktrace` only header, frame, source and position-marker lines, the chaining sentences, exception-group box lines and the qualified type name of each final line; every message continuation line and note is dropped. A stack trace with no header is replaced whole by `[redacted:stacktrace]` and counted in `docchat.telemetry.scrub_errors`.
7. **Loggers, workers and hosts.** Logger `docchat` at `DOCCHAT_TELEMETRY_LOG_LEVEL` with `propagate = False` and a stderr handler at `WARNING` carrying the scrubbing filter; loggers `azure`, `azure.core.pipeline.policies.http_logging_policy`, `httpx`, `httpcore`, `httpx2`, `openai`, `opentelemetry` and `uvicorn.error` at `WARNING`; `uvicorn.access` disabled. `apps/api/gunicorn.conf.py` sets `accesslog = None`, `errorlog = "-"`, `loglevel = "warning"` and `capture_output = False`; the worker class `DocChatUvicornWorker` sets `access_log=False` and `server_header=False` (ADR 0012). The ingestion `host.json` sets `logging.logLevel` `default` `Warning` (`Host.Results` and `Host.Aggregator` `Information`, `Function`, `DurableTask.AzureStorage` and `DurableTask.Core` `Warning`), Application Insights sampling off and dependency tracking off, and the Durable tracing options `distributedTracingEnabled`, `traceInputsAndOutputs` and `traceReplayEvents` all `false`. `PYTHON_APPLICATIONINSIGHTS_ENABLE_TELEMETRY` stays unset, because the worker's own configuration would bypass the scrubbing processors, and the preview host `telemetryMode: OpenTelemetry` isn't used.
8. **Telemetry that is never collected.** The diagnostic settings exclude `AppServiceHTTPLogs` (it records the signed-in user name, client IP and query string) and `AppServiceConsoleLogs`; Live Metrics is off; Application Insights keeps its default client-IP masking; Cosmos DB full-text query logging stays at its GA default (off), because turning it on needs a preview API; no instrumentation records SQL statement text (`pyodbc` is uninstrumented and the scrubber removes `db.statement`).
9. **The web client.** ESLint `no-console` is an error; the only console output is `devLog` in `src/platform/devLog.ts`, which writes `{ code, referenceId }` and MSAL errors only when `import.meta.env.DEV` is true and is a no-op in production builds. The browser emits no spans, metrics, events, logs or beacons; its only telemetry is the `traceparent` header on API calls (ADR 0088).
10. **Query cost and token usage from the first version.** Every Azure OpenAI call the API makes produces a `ModelCallUsage` record (`call`, `deployment`, `model`, `promptTokens`, `completionTokens`, `reasoningTokens`, `cachedTokens`, `cacheWriteTokens`, `totalTokens`, `estimated`, `estimatedCostMicros`, `durationMs`, `outcome`), appended to the turn's `usage.calls` and added to the caller's day and month counters; `estimatedCostMicros` is priced from `pricing.model_rates` in micro-units of `pricing.currency`; the counter `docchat.openai.estimated_cost` (dimensions `deployment`, `model`) and the turn's non-model billable counts (`semanticQueries`, `shieldCalls`, `shieldCharacters`) are recorded too (ADRs 0059, 0060). Ingestion run items record `embedding_tokens`, `summary_input_tokens`, `summary_output_tokens` and `docintel_pages`, and the metric `docchat.ingestion.tokens` carries the same counts by deployment; ingestion cost isn't priced in the first version. These are counts and IDs, so they obey items 1 to 3.
11. **Proof across the whole suite.** During every integration session the test plugin installs in-memory span, log and metric exporters through `configure_telemetry(exporters=…)`. Every content value in tests comes from `builders.canary(kind)`, which embeds `cnry-<kind>-<8 hex>` (kinds `question`, `answer`, `chunk`, `filename`, `fact`, `email`, `displayname`, `instruction`, `comment`, `title`, `summary`). At session end the plugin serialises every exported span (name, attributes, event attributes, `exception.message` and `exception.stacktrace` included), log record and metric data-point attribute set, and fails the session when any string contains `cnry-`, an email-shaped value or a JWT-shaped value, naming the item.

## Alternatives considered

- **Log bodies and prompts at debug level and rely on access control.** Lost: content in logs reaches everyone who can read telemetry, for the whole retention period. The conversation store, under just-in-time access, is the only place content can be read.
- **Rely on the scrubbing patterns alone.** Lost: no pattern recognises a question, a file name or a memory fact. Registered attributes keep content out by construction; the patterns only catch secrets that slip into an allowed string.
- **Log exceptions with their messages (`logging.exception`, `str(exc)`).** Lost: exception messages quote input values, duplicate keys and upstream error bodies. The type name, the error code and the frames identify the failure; the IDs lead to the data.
- **The Functions worker's built-in Azure Monitor configuration, or the host's OpenTelemetry mode.** Lost: the first configures the exporter without the scrubbing processors; the second is in preview.
- **App Service HTTP logs and framework access logs.** Lost: they record user names, client IPs and query strings. Request telemetry comes from spans, which pass the scrubber.
- **A browser telemetry SDK.** Lost: it would send page and user data to a second collector; the `traceparent` header already ties a reported error to its server trace.

## Consequences

- A support engineer can find any failing request, run or turn from its correlation ID and IDs, and can't read content from telemetry; reading content needs just-in-time access to the conversation store, which is audited (ADR 0024).
- Obligations: a pull request that adds an attribute, an event or an event property registers it with its type in the same change, and adds its row to the telemetry catalogue (85-observability.md); every new failure path maps to an error code.
- Tests: T-QUAL-23 (unregistered keys raise in tests and are dropped and counted in production), T-QUAL-24 to T-QUAL-28 (each scrubbing rule, the unchanged values, the three attach points, the attribute rules, processor errors), T-QUAL-29 (secrets and a canary exception message pass the full pipeline redacted from a route, a background task and an activity), T-QUAL-30 (no identifier is a metric dimension), T-QUAL-89 (no exception path exports a canary), the session-wide canary audit, and the API test that an unmapped exception yields exactly one `request_failed` record with no sentinel text.
- Accepted cost: debugging works from type names, codes, frames and IDs, never from exception messages; a failure that needs its message is reproduced from the stored inputs under just-in-time access.
- Risk: `ScrubbingSpanProcessor` replaces attribute values through the SDK span's attribute store, an SDK internal; a unit test fails if that internal changes, and the exporter pin moves only through a reviewed Dependabot pull request (ADR 0009).
- Risk: a secret shape the patterns don't know could pass inside an allowed string attribute. Allowed strings are typed (UUIDs, enum members, codes), which leaves little room, and the canary audit runs on every integration session.
