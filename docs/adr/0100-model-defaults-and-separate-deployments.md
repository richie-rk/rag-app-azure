# ADR 0100: Model defaults and separate deployments

- **Status:** Accepted
- **Date:** 2026-10-21
- **Decided by:** Product owner and architect
- **Specified in:** 83-infrastructure.md, 81-config.md, 12-chat-pipeline.md, 13-conversations-and-memory.md, 14-ingestion.md, 84-testing.md, 86-operations.md
- **Related ADRs:** 0044, 0045, 0053, 0059, 0061, 0066, 0067, 0068, 0095, 0097, 0099, 0101, 0112, 0138, 0140, 0147

## Context

The product calls Azure OpenAI for answers; for small tasks (question rewrites, search passages, follow-ups, conversation summaries and memory extraction); for ingestion's table summaries; and for query and chunk embeddings. Deployment names, models and versions are Bicep parameters, never constants in code, and every version is pinned, because a deployment whose version is omitted gets a default that may change. Ingestion uses its own deployments, one for table summaries and one embedding deployment per embedding model matching the query deployment's model and version, so a bulk upload can never starve chat; each deployment's tokens-per-minute limit is the backstop behind the per-user limits. Every deployment type defaults to `GlobalStandard` (ADR 0099).

The chat models must be GA reasoning models that run on Chat Completions with `reasoning_effort: none` and `prompt_cache_options` (ADR 0068), with the latest published retirement among the models offered as Global Standard, so that upgrades are planned rather than forced. Embeddings must fit the search tier's vector quota while keeping retrieval quality, and an embedding deployment must never change model or version under a live index.

Vendor facts (Microsoft Learn and PyPI, checked 2026-10-14; the GPT-5.6 entries re-read 2026-10-21):

- GA chat models: `gpt-5.6-sol`, `gpt-5.6-terra` and `gpt-5.6-luna`, version 2026-07-09, each with a 1,050,000-token context (922,000 in, 128,000 out), reasoning models on Chat Completions and Responses with structured outputs; `gpt-5.5` (2026-04-24); `gpt-5.4` (2026-03-05); `gpt-5.4-mini` and `gpt-5.4-nano` (2026-03-17) with 400,000 tokens. The GPT-6 models (`gpt-6-astra`, `gpt-6-sol`, `gpt-6-luna`, `gpt-6.1-sol`, September 2026) carry no preview label but are absent from the retirement schedule dated 2026-09-21.
- Retirement dates: the gpt-5.6 models 2028-01-11; gpt-5.5 2027-10-26; gpt-5.4 2027-09-02; gpt-5.4-mini and -nano 2027-09-21; `text-embedding-3-large` 1 2028-02-09, with no replacement named. GA versions are deprecated for new subscriptions 12 months after launch and retire 18 months after it. Global Standard, Data Zone Standard and Standard deployments are upgraded automatically at retirement unless `versionUpgradeOption` is `NoAutoUpgrade`, under which the deployment stops working at retirement.
- The reasoning how-to lists the gpt-5.6 versions as 2026-06-25 while the models and retirement pages say 2026-07-09; the Models API decides (ADR 0101).
- `text-embedding-3-large` has 3,072 dimensions, accepts the `dimensions` parameter, takes 8,192 tokens per input and at most 2,048 inputs and 300,000 tokens per request; moving to another embedding model needs re-embedding.
- A deployment's capacity is counted in units of 1,000 tokens per minute (TPM) for these models. Tier-1 Global Standard defaults are 1,000,000 TPM for the gpt-5.6 models and for `text-embedding-3-large`; since 2026-05-07, Global Standard deployments of one model and version share one pool per subscription across regions. GPT-5.6 deployments may need a quota request below Tier 5. The TPM limiter estimates each request on arrival from its prompt plus `max_completion_tokens`.
- `tiktoken` 0.14.0 maps `gpt-5*` names to `o200k_base` and `text-embedding-3-*` to `cl100k_base`, and has no GPT-6 entry.

## Decision

1. **Five deployments in each environment with an account.** `dev` and `prod` declare the Azure OpenAI account through AVM `avm/res/cognitive-services/account` 0.19.1 with its `deployments` parameter empty (ADR 0097); the local module `infra/modules/ai/openai-deployments.bicep` declares the two content filter policies first (ADR 0066) and then every deployment on `Microsoft.CognitiveServices/accounts/deployments@2026-07-01` with `@batchSize(1)`, so deployments are written one at a time, each depending on its policy. `load` has no account (ADR 0112). The defaults in `infra/env/<env>.json`:

   | Role | Name | Model | Version | Type | `versionUpgradeOption` | Content filter policy | Encoding | Capacity `dev` / `prod` (units) |
   |---|---|---|---|---|---|---|---|---|
   | Chat | `chat` | `gpt-5.6-sol` | `2026-07-09` | `GlobalStandard` | `OnceCurrentVersionExpired` | `docchat-text-guard` | `o200k_base` | 30 / 500 |
   | Chat small | `chat-small` | `gpt-5.6-terra` | `2026-07-09` | `GlobalStandard` | `OnceCurrentVersionExpired` | `docchat-text-guard` | `o200k_base` | 30 / 530 |
   | Table summary (ingestion) | `ingest-summary` | `gpt-5.6-terra` | `2026-07-09` | `GlobalStandard` | `OnceCurrentVersionExpired` | `docchat-table-summary-guard` | `o200k_base` | 30 / 150 |
   | Query embedding | `embed-query-te3-large-v1` | `text-embedding-3-large` | `1` | `GlobalStandard` | `NoAutoUpgrade` | none (ADR 0067) | `cl100k_base` | 30 / 100 |
   | Ingestion embedding | `embed-ingest-te3-large-v1` | `text-embedding-3-large` | `1` | `GlobalStandard` | `NoAutoUpgrade` | none (ADR 0067) | `cl100k_base` | 60 / 250 |

2. **Parameter objects.** `openAi.deployments` holds `chat`, `chatSmall` and `tableSummary`, each of the user-defined type `openAiDeployment` `{name, model, version, type, capacity, versionUpgradeOption, raiPolicyName, encoding}`: `name` 2 to 64 letters, digits, `-`, `_` or `.`; `version` never omitted; `type` per ADR 0099; `capacity` 1 to 10,000 units; `encoding` `o200k_base` or `cl100k_base`. Embedding models form the array `openAi.embeddingModels` of `{key, model, version, queryType, ingestionType, queryCapacity, ingestionCapacity, defaultDimensions, allowedDimensions, maxInputTokens, encoding}`; each entry produces the pair `embed-query-<key>` and `embed-ingest-<key>`, both `NoAutoUpgrade` with no policy. The default entry is `{key: 'te3-large-v1', model: 'text-embedding-3-large', version: '1', queryType: 'GlobalStandard', ingestionType: 'GlobalStandard', queryCapacity: 30 (dev) | 100 (prod), ingestionCapacity: 60 | 250, defaultDimensions: 1024, allowedDimensions: [256, 1024, 3072], maxInputTokens: 8192, encoding: 'cl100k_base'}`.
3. **What the apps receive.** App settings, never constants in code: `DOCCHAT_OPENAI_CHAT_DEPLOYMENT`, `DOCCHAT_OPENAI_CHAT_MODEL`, `DOCCHAT_OPENAI_CHAT_MODEL_VERSION` and `DOCCHAT_OPENAI_CHAT_ENCODING`; the same four as `DOCCHAT_OPENAI_SMALL_*`; `DOCCHAT_OPENAI_TABLE_SUMMARY_DEPLOYMENT` and `DOCCHAT_OPENAI_TABLE_SUMMARY_ENCODING`; and `DOCCHAT_OPENAI_EMBEDDING_MODELS`, a JSON array of 1 to 8 entries `{model, modelVersion, queryDeployment, ingestionDeployment, dimensions, defaultDimensions, maxInputTokens, encoding}` built from `openAi.embeddingModels`, while `key`, the two types and the two capacities stay in Bicep. A new physical index copies its model, version, dimensions, encoding, input limit and both deployment names into its row, so a later setting change never alters an existing index (ADR 0045). The `chat` and `chat-small` capacities also become the azd outputs `DOCCHAT_OPENAI_CHAT_CAPACITY` and `DOCCHAT_OPENAI_SMALL_CAPACITY` (never app settings, empty in `load`) for the capacity check of ADR 0147.
4. **Model choice.** `gpt-5.6-sol` is the GA general-purpose flagship with the latest published retirement (2028-01-11) offered as Global Standard. `gpt-5.6-terra` is the GA small tier with the same retirement, later than gpt-5.4-mini's 2027-09-21; it serves chat small and the table summary, on separate deployments. Both accept `reasoning_effort: none` on Chat Completions and `prompt_cache_options`, which the model capability table records and the deployed model check verifies, with the tokenizer check of each deployment's encoding (ADR 0068).
5. **Embeddings at 1,024 dimensions.** `text-embedding-3-large` version 1 runs at 1,024 dimensions by default, with 256 and 3,072 selectable per index (`allowedDimensions`); every embedding call sends `dimensions` (ADR 0044). A 1,024-dimension vector takes 4 KiB, so a Basic search partition's 5 GB vector quota holds about 1.2 million chunks; 3,072 dimensions hold a third of that.
6. **Upgrade behaviour.** Chat-model deployments use `OnceCurrentVersionExpired`, so a deployment keeps serving at retirement, while the preflight fails 183 days before a pinned version retires so that the parameter changes first (ADR 0101). Embedding deployments use `NoAutoUpgrade` and are never changed in place: a new embedding model or version is a new `openAi.embeddingModels` entry with a new key, hence a new deployment pair and a new physical index (ADR 0045); the old pair is removed only when no physical index names it.
7. **Separate deployments.** Ingestion calls only `ingest-summary` and `embed-ingest-<key>`; the API calls only `chat`, `chat-small` and `embed-query-<key>`. Each deployment has its own capacity, so ingestion's throttling (`429`) stays on its own deployments and is retried there (ADR 0053), while chat keeps its full limits.
8. **Capacities.** All environments share one Tier-1 subscription (ADR 0095). Per model and type, `dev` plus `prod` use 530 units of `gpt-5.6-sol`, 740 of `gpt-5.6-terra` (30 + 30 + 530 + 150) and 440 of `text-embedding-3-large` (30 + 60 + 100 + 250), each under the 1,000-unit Global Standard pool. `prod`'s `chat` capacity of 500 units admits about 12 answers a minute at the full 40,000-token turn budget (`chat.context_token_budget`), because the limiter counts the prompt plus `max_completion_tokens`. `chat` 500 and `chat-small` 530 are the capacities against which one user's worst-case charge stays at or below 25% (24% and 24.8% at the default limits, ADR 0147). `embed-ingest-te3-large-v1`'s 250 units take the two embedding requests of up to 60,000 tokens that a document keeps in flight at the default parallelism of 1, 120,000 of its 250,000 TPM (ADR 0053). A turn sends at most two embedding inputs to `embed-query-te3-large-v1` (the search query and, on low confidence, the search passage, ADR 0061). Raising a capacity is a parameter change that the preflight's quota check validates.

## Alternatives considered

- **`gpt-5.5` or `gpt-5.4` for chat.** Rejected: both are GA but retire earlier (2027-10-26 and 2027-09-02) than the gpt-5.6 models' 2028-01-11, so the first forced upgrade would come sooner.
- **`gpt-5.4-mini` or `gpt-5.4-nano` for chat small and the table summary.** Rejected: they retire on 2027-09-21, almost four months before `gpt-5.6-terra`.
- **`gpt-5.6-luna` for chat small.** Not chosen: the model capability table and the deployed model check cover `gpt-5.6-sol` and `gpt-5.6-terra`; `gpt-5.6-luna` has the same retirement date and can replace `gpt-5.6-terra` by a parameter change once a capability-table row for it passes the same check.
- **A GPT-6 model.** Rejected for now: absent from the retirement schedule, so neither the preflight nor the nightly watch can check a retirement date, and `tiktoken` 0.14.0 maps no encoding to GPT-6 names, so the token counts the prompt budget relies on can't be confirmed before a stage gate.
- **One deployment shared by chat small and the table summary.** Rejected: a bulk upload's table summaries would consume the capacity that question rewrites, follow-ups, summaries and memory extraction need.
- **3,072 or 256 dimensions by default.** Rejected: 3,072 triples vector storage and fits about 400,000 chunks in a Basic partition; 256 keeps one twelfth of the model's 3,072 dimensions against 1,024's one third. Both stay selectable per index.
- **`OnceNewDefaultVersionAvailable` on chat-model deployments.** Rejected: the service would move a deployment to a new default version whenever Microsoft names one, months before retirement and without a pull request, so the running model would differ from the pinned parameter, the capability table and the price table.
- **`NoAutoUpgrade` on chat-model deployments.** Rejected: a deployment would stop answering at retirement; with `OnceCurrentVersionExpired` a missed retirement becomes an unreviewed upgrade rather than an outage, and the preflight's 183-day rule and the nightly watch make that case unlikely.
- **Automatic upgrade on embedding deployments.** Rejected: an in-place version change would mix vectors of two model versions in one physical index, which the index design forbids (ADR 0045).
- **Larger default capacities.** Rejected: deployments of one model and version in the subscription share the 1,000-unit Tier-1 pool, and `dev` plus `prod` already use 530, 740 and 440 units; a subscription with a higher tier raises capacities by parameter.

## Consequences

- Easier: one parameter object per deployment carries everything that varies (model, version, type, capacity, upgrade option, policy, encoding); the apps read names and encodings from settings, so a model change touches `infra/env/<env>.json` and, for chat models, the capability table (ADR 0068) and the price rows `pricing.model_rates` (ADR 0059).
- The pinned `2026-07-09` disagrees with the reasoning page's 2026-06-25; the preflight's Models API check settles it at the first provision (`model_version_not_offered` names the deployment), and the remedy is a one-line parameter change.
- Quota: a subscription below Tier 5 may need a quota request before the first GPT-5.6 deployment; the preflight reports a shortfall in units (`quota_insufficient`). Capacities beyond the Tier-1 pool need a higher tier or a quota increase.
- An embedding model change always means a new physical index and a re-ingest of every logical index that uses the old pair (ADR 0045); the next forced one is `text-embedding-3-large` 1's retirement on 2028-02-09.
- Risk: a version becomes undeployable for subscriptions that never deployed it 12 months after launch (2027-07-09 for the gpt-5.6 defaults), so the template in a fresh subscription can lose a pinned version with no change in this repository; the nightly model watch reports it (ADR 0140).
- Obligations: `83-infrastructure.md` lists the five deployments with every field; `81-config.md` lists the parameters, app settings and azd outputs; `12-chat-pipeline.md`, `13-conversations-and-memory.md` and `14-ingestion.md` name the deployment each call uses; `86-operations.md` holds the model version upgrade runbook (choose the replacement version and type, edit the parameter object, pass the preflight in `dev`, run the deployed model and tokenizer checks, set prices before traffic, never change an embedding deployment in place) and the throttling response (raise capacity, or lower `chat.answer_max_completion_tokens`).
- Tests (`84-testing.md`): the deployed model check per deployment and reasoning effort with the tokenizer check (ADR 0068); `docchat-ops chat capacity-check` on every deploy (ADR 0147); the preflight's model and quota checks (ADR 0101); the nightly model watch (ADR 0140); the PSRule rule that embedding deployments carry `NoAutoUpgrade` and no policy (ADR 0067).
- Monitoring: Azure OpenAI throttling and model-call latency alerts per deployment (ADR 0138).
