# ADR 0114: Bootstrap outside the pipeline

- **Status:** Accepted
- **Date:** 2026-10-21; amended 2026-10-30 (no paid GitHub plan required: the CI network, runner group and larger runner only under the private-networking option, and the test identity's runner-rule right by default, ADR 0122)
- **Decided by:** Product owner and architect
- **Specified in:** 83-infrastructure.md, 86-operations.md, 82-security.md
- **Related ADRs:** 0095, 0111, 0115, 0116, 0117, 0118, 0120, 0122, 0142

## Context

Every resource of this product is declared in Bicep and deployed from GitHub Actions, but some objects can't come from the pipeline: creating resource groups and custom role definitions, assigning policies and granting a Microsoft Graph application permission all need rights above an environment's Contributor, and Entra groups, Entra diagnostic settings and GitHub environment protection sit outside Azure Resource Manager. More important, the deploy identities are privileged operators of their environments (ADR 0115), so the identities themselves, their federated credentials, the policies that bound them and the alerts that watch them must be objects no pipeline identity can change. A tenant administrator creates them once, from scripts in the repository.

Vendor facts:

- Contributor has Actions `*` with NotActions `Microsoft.Authorization/*/Write` and `Microsoft.Authorization/*/Delete`, so it creates no role assignment, role definition, policy assignment or lock; neither Contributor nor Role Based Access Control Administrator can create role definitions; Contributor or Owner can create a user-assigned identity's federated credentials (checked 2026-10-14).
- A resource provider must be registered before the first deployment of its types, by a caller allowed to register it (checked 2026-10-14).
- A user-assigned identity holds at most 20 federated credentials, each issuer and subject pair unique; creating several credentials under one identity at the same time fails with `409 Conflict`, so templates create them one after another; a new credential takes several minutes to propagate, during which a token exchange can fail with `AADSTS70021` (checked 2026-10-21).
- GitHub: "By default, administrators can bypass the protection rules and force deployments to specific environments", unless an environment disallows it; larger runners, which only the private-networking option of ADR 0122 uses, need GitHub Team or Enterprise Cloud (checked 2026-10-15).

## Decision

1. **The script and its operator.** `scripts/bootstrap/bootstrap.py` (Python 3.13 standard library, `az`, `gh`), driven by `scripts/bootstrap/bootstrap.config.json`: tenant ID; subscription IDs; region; GitHub organization and repository; `ciPrivateNetworking` (default `false`) and `ciNetworkLocation` (ADR 0122); `operators` (the operators, and every maintainer, release approver or directory administrator who runs Azure reads); `approverObjectIds` per environment, at least two people each; `groupOwners`, at least two people, the owners of every `sg-docchat-<env>-users` and `sg-docchat-<env>-admins` group; `securityAlertEmails`; the test-user aliases; `allowedRoleAssigneePrincipalIds` and `templateCosmosAssignmentIds` (extended later by `tighten_conditions.py`, ADR 0115). It runs once per tenant and subscription, by a person holding Owner on the subscriptions and the Entra roles Privileged Role Administrator, Groups Administrator and Security Administrator, with `gh` signed in as an owner of the repository's GitHub organization (environments need it, and under the private-networking option runner groups, network configurations and hosted runners). Every step is idempotent and runs alone with `--step <name>`; a failed step stops the script with its code and leaves earlier steps in place. Every role assignment it makes sets `principalType` to `ServicePrincipal` for an identity and `Group` for a group.
2. **The fifteen steps, in order.**
   1. `prerequisites`: `az` 2.76.0 or later, Bicep 0.47.16 or later, the `gh` sign-in, the caller's roles; no `approverObjectIds` entry is in `operators`; `groupOwners` holds at least two object IDs.
   2. `providers`: register Microsoft.Web, Microsoft.Sql, Microsoft.DocumentDB, Microsoft.Storage, Microsoft.Search, Microsoft.CognitiveServices, Microsoft.KeyVault, Microsoft.ContainerRegistry, Microsoft.Network, Microsoft.OperationalInsights, Microsoft.Insights, Microsoft.ManagedIdentity, Microsoft.Security, Microsoft.EventGrid, Microsoft.AlertsManagement, Microsoft.ContainerInstance and, when `ciPrivateNetworking` is `true`, GitHub.Network, and wait until each is `Registered`.
   3. `resource-groups`: `rg-docchat-identity`, `rg-docchat-shared`, `rg-docchat-dev`, `rg-docchat-prod` and `rg-docchat-load` with their tags (ADR 0095).
   4. `roles`: validate every action with `az provider operation show --namespace <namespace>`, then deploy `infra/bootstrap/roles.bicep`, the custom roles with constant GUIDs (DocChat Search Index Manager, Blob Tag Reader, Template Validator, Defender Scanner Enabler, Registry Firewall Editor, Registry Endpoint Approver, Shared Deployment Operator, Test Secret Writer, Test Vault Firewall Editor, Preflight Reader, Cosmos Data Access Granter, Load Test Operator).
   5. `identity`: compare the issuer and subject pairs of every planned federated credential, then deploy `infra/bootstrap/identity.bicep` into `rg-docchat-identity`: the five pipeline identities (`id-docchat-deploy-dev`, `-prod`, `-load`, `id-docchat-pr`, `id-docchat-citest`) and their federated credentials one at a time (`@batchSize(1)`; a `409` retried up to 6 times, 20 s apart), the workspace `log-docchat-security` and the action group `ag-docchat-security`.
   6. `shared`: deploy `infra/shared.bicep` into `rg-docchat-shared`: the registry (ADR 0118), the test-credential vault and, when `ciPrivateNetworking` is `true`, the CI network with the vault's private endpoint and DNS zone (ADR 0122).
   7. `groups`: through Microsoft Graph, `sg-docchat-operators` (members: the people in `operators` and in every `approverObjectIds` list, so every person who runs Azure reads holds its Reader rights); per environment `sg-docchat-<env>-sql-admins` (member: that environment's deploy identity), `sg-docchat-<env>-users` and `sg-docchat-<env>-admins` (owners: the people in `groupOwners`) and the three just-in-time groups `sg-docchat-<env>-conversation-readers`, `-user-data-operators` and `-config-operators` (owners: the approvers); all `securityEnabled: true`, `mailEnabled: false`, `isAssignableToRole: false`.
   8. `graph-permission`: grant each deploy identity `Application.ReadWrite.OwnedBy` (`18a4783c-866b-4cc7-a460-3d5e5662c884`) through `POST https://graph.microsoft.com/v1.0/servicePrincipals/<Graph service principal ID>/appRoleAssignedTo`, retried for up to 5 minutes on replication delay.
   9. `assignments`: deploy `infra/bootstrap/assignments.bicep`: the deploy identities' rights with the initial conditions (ADR 0115), the pull-request identity's Reader and DocChat Template Validator on `rg-docchat-dev` and `rg-docchat-shared` and DocChat Preflight Reader at the subscription, the operators' Reader on `rg-docchat-shared` and on `rg-docchat-load` (named as `main.bicep` names the same `load` assignment, so a provision finds it in place and complete-mode teardown keeps it), Log Analytics Reader on `log-docchat-security` and DocChat Test Secret Writer on the test vault, three roles for `sg-docchat-dev-config-operators` at `rg-docchat-dev`, which exist only in `dev`, where every account and service holds test data: Cognitive Services User (`a97b65f3-24c7-4388-baec-2e87135dc908`), for the Azure OpenAI and Content Safety calls of the `dev` operator check `docchat-ops --env dev chat model-check` (ADR 0068 and ADR 0062) and the Prompt Shields and Document Intelligence live contract suites, and Search Service Contributor (`7ca78c08-252a-4471-8644-bb5ff32d4ba0`) with Search Index Data Contributor (`8ebe5a00-799e-43f5-93ac-243d3dce84a7`), for the AI Search live contract suite, which creates its own `contract-` index, fills it, and deletes it in a `finally` block; and `id-docchat-citest`'s Key Vault Secrets User on the test vault, its DocChat Test Vault Firewall Editor on the test vault while `ciPrivateNetworking` is `false` (ADR 0122), its Log Analytics Reader and DocChat Load Test Operator at `rg-docchat-load` and, once `dev`'s first provision has created it, its Log Analytics Reader on `log-docchat-dev` (the step's run before that leaves this one out; the first provision's post-provision steps run the step again).
   10. `policies`: read every built-in definition with `az policy definition show --name <ID>` and check that its `effect` parameter allows `Deny`, then deploy `infra/bootstrap/policies.bicep`: the Deny assignments and the custom definitions of ADR 0116 and the delete-deny assignment of ADR 0111.
   11. `security`: deploy `infra/bootstrap/security.bicep` and `activity-log.bicep` (the alerts and their parameters, the subscription Activity Log setting, ADR 0115) and create the Entra diagnostic setting `docchat-security` (`PUT https://management.azure.com/providers/microsoft.aadiam/diagnosticSettings/docchat-security?api-version=2017-04-01`).
   12. `config`: write the tenant-specific IDs into `infra/env/<env>.json` and print the diff for the operator to commit.
   13. `github`: `scripts/bootstrap/configure_github.py` writes the six environments `dev`, `prod`, `load`, `load-access`, `dev-tests` and `load-tests` with their branch rules, reviewers and variables, `prevent_self_review: true` and `can_admins_bypass: false` on `prod` and `load-access`, and the repository variable `DOCCHAT_CI_PRIVATE_NETWORKING` from `ciPrivateNetworking`, and reads each back (ADR 0120, ADR 0122).
   14. `ci-runner`: only when `ciPrivateNetworking` is `true`, the GitHub network settings, network configuration, runner group and larger runner of the CI network, each created only when absent and read back; otherwise it reports `skipped` and changes nothing (ADR 0122).
   15. `checklist`: print the post-provision steps of item 4.
3. **Refusals, all before the step changes anything** (each exits 2 with one JSON line `{"code", "message", "detail"}` on standard error and in the job summary): `missing_prerequisite` (a tool version or caller role), `approver_is_operator`, `unknown_action` (a custom role's action unknown to its provider), `oidc_subject_shared` (two identities would trust one issuer and subject pair), `graph_permission_failed`, `policy_definition_missing` (a built-in definition absent or unable to deny), `oidc_subject_customised` (the repository's OIDC subject template customised beyond an immutable prefix), `github_protection_mismatch` (an environment read back without its reviewers, `prevent_self_review: true` or `can_admins_bypass: false`), and, under the private-networking option only, `ci_region_unsupported`, `ci_private_networking_unavailable` (the organization can't create the larger runner: the operator sets `ciPrivateNetworking` to `false` and re-runs `shared`, `assignments`, `github` and `ci-runner`) and `ci_runner_mismatch`.
4. **Post-provision steps it prints** (after an environment's first provision): `scripts/identity_post_provision.py` (consent, first admins, test groups); `scripts/bootstrap/tighten_conditions.py --env <env>` in `dev` and `prod`; `scripts/bootstrap/lock_prod.py` in `prod` (ADR 0111); the first clean scanner canary before uploads open (runbook R12); the first test-user passwords; the Entra diagnostic setting `docchat-prod-audit` in `prod` (Security Administrator); DocChat Cosmos Data Access Granter for each approver only when `cosmosGroupDataAccess` is `false`; PIM for Groups on the just-in-time groups where the tenant has Entra ID P2 or ID Governance; the host account in the `notScopes` of `docchat-deny-storage-shared-key` only under content-share fallback 1.
5. **Out of the pipeline's reach.** No pipeline identity holds any role in `rg-docchat-identity`; in `rg-docchat-shared` the deploy identities hold only deployments, AcrPull delegation, endpoint approval and, for `dev`, the registry rights of ADR 0118. Contributor and Role Based Access Control Administrator can't create role definitions, policy assignments or locks, so every object of steps 4, 5, 7 to 11, 13 and 14 changes only when the bootstrap operator runs its step again.
6. **The test identity's rights** are exactly Key Vault Secrets User on the test vault, DocChat Test Vault Firewall Editor on the test vault while `ciPrivateNetworking` is `false` (its own transient runner rule, ADR 0119 and ADR 0122), Log Analytics Reader and DocChat Load Test Operator at `rg-docchat-load`, and Log Analytics Reader on `log-docchat-dev` alone, granted by the product owner on 2026-11-06 so the deployed suites' health, memory and trace readings run in `dev`; it holds no other network right, and none at all under the private-networking option.

## Alternatives considered

- **The pipeline creates these objects through a subscription-scope deployment.** Rejected: it would need rights that also remove its own bounds (role definitions, policy assignments, the alerts in `rg-docchat-identity`), plus Entra and Graph rights no pipeline should hold.
- **Pipeline identities in their environment's resource group.** Rejected: Contributor there could add a federated credential for any subject to a deploy identity and delete the alerts that watch it.
- **One subscription-scope Bicep deployment for the whole bootstrap.** Rejected: Entra groups, the Graph app-role grant, the Entra diagnostic setting and the GitHub objects aren't Resource Manager resources of that deployment, and a repair must be able to re-run one step alone.
- **Portal steps written in a runbook.** Rejected: hand steps drift and can't be reviewed in a pull request; the script's templates and configuration are in the repository.

## Consequences

- A compromised pipeline can't change the identities it runs as, their federated credentials, the policies and conditions that bound them, or the alerts that watch them.
- Every change in `rg-docchat-identity`, to a custom role, a policy, an Entra group or GitHub protection needs the bootstrap operator, not only a pull request.
- Prerequisites: Entra ID P1 (the Entra diagnostic settings and the test users' Conditional Access exclusion). No paid GitHub plan: GitHub Team or Enterprise Cloud is needed only for the private-networking option's larger runners (ADR 0122).
- Runbooks: R21 runs the bootstrap, with `gh` signed in as a GitHub organization owner, and its check of `id-docchat-citest` expects exactly the rights of item 6; R31 runs `identity` and `assignments` again after a suspected compromise; R34 runs `shared` and `ci-runner` again under the private-networking option.
- Tests (84-testing.md): unit tests that the bootstrap stops with `oidc_subject_shared` for a plan in which two identities trust `environment:dev`, with `approver_is_operator` for an approver listed among the operators, that `configure_github.py` stops with `github_protection_mismatch` when an environment reads back with `can_admins_bypass: true`, and the `ci-runner` step's `skipped` report by default and its refusals under the private-networking option; deployed `dev` tests that `prod` and `load-access` read back with their reviewers, `prevent_self_review: true` and `can_admins_bypass: false`, and that `id-docchat-citest`'s federated credentials name only `dev-tests` and `load-tests`.
