# ADR 0049: Parsing isolation in child processes

- **Status:** Accepted
- **Date:** 2026-10-18
- **Decided by:** Architect
- **Specified in:** 14-ingestion.md, 82-security.md, 81-config.md, 84-testing.md, 85-observability.md, 01-repository.md, CONTEXT.md
- **Related ADRs:** 0003, 0043, 0047, 0048, 0053, 0109, 0113, 0144, 0145, 0152

## Context

All document parsing happens in the ingestion app, with a time and memory limit per document. Parallelism comes from processes or instances, never threads, because the parser is CPU- and memory-heavy and renders PDF pages under one process-wide lock. The parsing stack is large native code fed with files written by other people: `unstructured` and `unstructured-inference` (Beta), pdfminer, Pillow, OpenCV, ONNX Runtime, torch, Tesseract, poppler and qpdf through `pikepdf`. The ingestion identity holds write rights on `documents`, `renditions` and `ingestion-work`, on every search index and on the ingestion tables, so a flaw that runs code inside a parser must not reach that identity.

On Elastic Premium the managed identity is reached through `IDENTITY_ENDPOINT` with the secret `IDENTITY_HEADER`, both in the environment of the host and worker processes. A Python 3.13 worker on Elastic Premium runs `async def` functions on one event loop, and the Durable Functions concurrency settings apply per worker (ADR 0053).

Every unit of parsing work needs its own bound: a parse that never ends would hold one of the instance's activity slots until the host's timeout, and a large document split into many parts could otherwise parse for hours. Concurrent activities must share no mutable state, so one document's parse can never mark another document's results.

One instance runs several children at once whenever worker processes or parse slots exceed 1 (EP2 runs 2 worker processes), and two concurrent children can be parsing documents of different indexes and projects. A parser flaw that runs code in one child must therefore reach neither a sibling's files nor its memory, and must not carry what it reads anywhere: the app has no network namespace to give a child, and the Durable extension's loopback endpoint answers any local caller.

Vendor facts:

- `setpriv` (util-linux 2.38.1, Debian 12, checked 2026-10-18): `--reuid` and `--regid` set the real and effective IDs; a primary group change requires `--clear-groups`, `--groups`, `--keep-groups` or `--init-groups`; `--no-new-privs` sets the bit with which `execve` grants no new privileges; `--inh-caps` sets the inheritable set; setting a UID doesn't change capabilities, but the final `exec` can.
- `prlimit` (util-linux 2.38.1): `--fsize`, `--nofile` and `--nproc`; a single value sets the soft and hard limits; given a command, it runs the command with those limits.
- `setrlimit(2)` (Debian 12): `RLIMIT_NPROC` counts the processes, on Linux the threads, of the caller's real user ID and isn't enforced for real UID 0 or holders of `CAP_SYS_ADMIN` or `CAP_SYS_RESOURCE`; exceeding `RLIMIT_FSIZE` raises `SIGXFSZ`, which ends the process by default; `RLIMIT_AS` caps virtual address space.
- Python's audit hooks "are not suitable for implementing a sandbox" (checked 2026-10-18).
- The Durable Functions extension's internal RPC listener binds `http://127.0.0.1:17071/durabletask/` (or a port from 30000 to 31000) and checks no key, token or header on its routes (extension source, checked 2026-10-18). The routes are those of the Durable Functions HTTP API, whose operations are, at most: list instances and read their status (instance IDs and activity outputs, which hold document titles), start, restart, rewind, terminate, suspend, resume and purge instances, raise events, signal, read and list entities, and make the app its task hub's primary (Microsoft Learn, "HTTP APIs in Durable Functions", checked 2026-10-25); the census of decision 16 records which of them the deployed listener allows.
- Elastic Premium memory: EP1 3.5 GB, EP2 7 GB, EP3 14 GB.
- `seccomp(2)` (checked 2026-10-25): `SECCOMP_SET_MODE_FILTER` needs `CAP_SYS_ADMIN` or the `no_new_privs` bit, and fails with `EACCES` otherwise; a child process is bound by its parent's filters, and filters are kept across `execve`; `SECCOMP_RET_ERRNO` returns the given error without running the call; a deny list must check the architecture, because the x86-64 and x32 interfaces share one architecture value.
- `ptrace(2)` (checked 2026-10-25): `PTRACE_ATTACH` and `process_vm_writev` need the target's real, effective and saved user IDs to match the caller's, or `CAP_SYS_PTRACE`, and a target whose dumpable attribute isn't 1 refuses a caller without `CAP_SYS_PTRACE`; `/proc/<pid>/environ` uses the same check.
- `RLIMIT_NPROC` counts per real user ID (`setrlimit(2)` above), so children under different UIDs don't share one limit.
- Debian 12 ships `libseccomp2` 2.5.4-1+deb12u1 (checked 2026-10-25), the maintained C library that builds seccomp filters. The Python bindings on PyPI are either built for one system Python or, like `pyseccomp` 0.1.2 (2021-01-02), a `ctypes` wrapper with no release since 2021 (checked 2026-10-25). A security boundary can't rest on an unmaintained package, and the seven library calls the filter needs fit in a first-party module.
- `seccomp(2)` (checked 2026-10-25): `SECCOMP_FILTER_FLAG_TSYNC` (libseccomp's `SCMP_FLTATR_CTL_TSYNC`) applies a new filter to every thread of the process, and a thread that already runs is otherwise left unfiltered; a filter sees a system call's arguments as numbers and can't read memory a pointer argument names, so the flags of `clone3`, passed in a structure, can't be checked, while those of `clone`, passed in a register, can.
- Office Open XML part names and content types compare case-insensitively (ECMA-376 Part 2, checked 2026-10-25), so `VBAPROJECT.BIN` names the same part as `vbaProject.bin`.
- Microsoft's App Service documentation doesn't state whether an unprivileged process in an Elastic Premium Linux custom container can install a seccomp filter, so a spike decides it (decision 16).

## Decision

1. **What runs in a child.** Every `inspect` (the signature, ZIP, encryption, Office type and PDF checks of ADR 0043 and the page count, for both methods), every `convert` of a DOCX or PPTX to PDF (ADR 0152), every `verify-render` (decision 17), every page-wise `partition` of one part (ADR 0047), every `render` of single-page PDFs (ADR 0145) and every `assemble` of the whole-document rendition (ADR 0152) runs in a fresh child process, started for that one command and never reused. The parent process parses no source document bytes. It handles exactly these inputs: each child's `result.json` and the `partition` child's `partition.json`, opened and validated as decision 6 requires; the `converted.pdf` of a `convert` child, opened the same way, which it hashes, uploads and hands to an `inspect` child as bytes; the page files of a `render` child and the `document.pdf` of an `assemble` child, opened the same way, which it hands to a `verify-render` child, uploading only the verified files that child writes; and Document Intelligence's JSON result (ADR 0048).
2. **Command.** With `<uid>` the parse user the parent took for the child (decision 14), the parent runs `asyncio.create_subprocess_exec("setpriv", "--reuid=<uid>", "--regid=<uid>", "--clear-groups", "--no-new-privs", "--inh-caps=-all", "--", "prlimit", "--fsize=2147483648", "--nofile=256", "--nproc=64", "--", "/opt/venv/bin/python", "-I", "-m", "docchat_ingestion.isolation.parse_worker", <request path>, start_new_session=True)` with `stdin`, `stdout` and `stderr` set to `DEVNULL`, so document text can't reach logs, and `cwd` set to the child's directory.
3. **User and privileges.** The image creates the parse users and groups `docchat-parse-0` to `docchat-parse-15` (UIDs and GIDs 10002 to 10017, home `/nonexistent`, shell `/usr/sbin/nologin`; decision 14). The child runs as the one the parent took for it, with no supplementary groups and the `no_new_privs` bit. `setpriv` keeps capabilities across the UID change, and its `exec` of `prlimit` under that UID with an empty inheritable set (which also empties the ambient set) and no file capabilities leaves the permitted and effective sets empty, so the child holds no capability and can gain none. Under another UID the child can't read `/proc/<parent pid>/environ` or `/proc/1/environ`.
4. **Environment.** The child's environment is built from an allowlist: `PATH`; `HOME`, `TMPDIR`, `TMP` and `TEMP` set to its own directory, so a parser that takes its temporary directory from one of them writes no predictable name to the shared `/tmp`; `LANG`; the model and telemetry variables of the image (`HF_HOME`, `HF_HUB_OFFLINE`, `HF_HUB_DISABLE_TELEMETRY`, `DO_NOT_TRACK`, `SCARF_NO_ANALYTICS`, `UNSTRUCTURED_DEFAULT_MODEL_INITIALIZE_PARAMS_JSON_PATH`, `TIKTOKEN_CACHE_DIR`); and `OMP_NUM_THREADS=1`. It holds no `IDENTITY_ENDPOINT`, `IDENTITY_HEADER` or `MSI_*` variable, no endpoint and no connection setting, so code in the child can't obtain a token.
5. **Files.** Each activity invocation that needs local files creates, for each parse user whose child needs one, `tempfile.mkdtemp(prefix="docchat-", dir="/run/docchat-scratch")` and opens a descriptor to it. The image creates `/run/docchat-scratch` owned by root with mode 0711, so no parse user can list, create or rename a directory in it. The parent writes `source.bin` and `request.json`, for `convert` the converter profile `lo-profile/user/registrymodifications.xcu`, and for `verify-render` the batch's page files or `document.pdf`, itself, owned by root with mode 0644 and created with `O_CREAT | O_EXCL | O_NOFOLLOW` relative to that descriptor, and only then hands the directory to the child's UID with `os.fchown` and mode 0700: the child reads its inputs but can't change them, and no other parse user can enter. Every file inside is named from IDs only (`source.bin`, `request.json`, `result.json`, `partition.json`, `converted.pdf`, `{n}.pdf`, `document.pdf`, and their `.verified.pdf` forms), and the parent removes the directory in a `finally` block after ending every process of the child's UID (decision 14). No admin-supplied name becomes a path.
6. **Protocol.** The child exchanges data with its parent only through files in its scratch directory. `request.json`: `{"command": "inspect" | "convert" | "partition" | "render" | "assemble" | "verify-render" | "probe", "contentType", "sourcePath", "pages": {"first", "last"} | null, "mode": "pages" | "document" | null, "parameters", "limits": {"maxPages", "maxZipEntries": 10000, "maxZipBytes": 536870912, "convertMaxBytes": 209715200, "renderMaxPageBytes": 20971520, "renderMaxTotalBytes": <max(10 × PDF size, 524288000)>, "renderMaxPagesOnDisk": 4, "renderMaxDocumentBytes": 104857600}, "failOnNetwork": true}`, with `failOnNetwork` true for every child: its audit hook ends a child that resolves a name or connects a socket with exit code 3, a cheap second layer behind the system-call filter of decision 15 (ADR 0047). The parent treats every file a child wrote as hostile. It opens only these names (`result.json`; `partition.json` for `partition`; `converted.pdf` for `convert`; `document.pdf` for `assemble`; for `render`, `f"{n}.pdf"` with `n` from 1 to the version's page count, which matches `^[0-9]{1,4}\.pdf$`; for `verify-render`, `f"{n}.verified.pdf"` with `n` a page of the batch, which matches `^[0-9]{1,4}\.verified\.pdf$`, or `document.verified.pdf` in document mode) with `os.open(name, os.O_RDONLY | os.O_NOFOLLOW | os.O_NONBLOCK, dir_fd=<the scratch directory's descriptor>)`, and accepts a file only when `os.fstat` on the open descriptor shows a regular file owned by the child's UID with `st_nlink` 1 and within its limit (`result.json` 1 MiB, `partition.json` 128 MiB, `converted.pdf` `convertMaxBytes`, a page `renderMaxPageBytes`, `document.pdf` and `document.verified.pdf` `renderMaxDocumentBytes`), so a symbolic link to another directory's `source.bin` or to `/proc/1/environ`, a hard link and a FIFO are all refused. `result.json` is validated with its command's Pydantic model in `docchat_ingestion.isolation.results`, with `extra="forbid"`: success is `{"ok": true}` with the command's integer fields in range (`pageCount` for `inspect`, null for a DOCX or PPTX source, and for `render` and `assemble`), failure `{"ok": false, "code": "<one of the command's item codes>"}`; `partition.json` is validated with `ExtractPartV1` or `ExtractDocumentPagewiseV1` the same way. No text from either file other than validated codes and numbers reaches SQL, a log record or telemetry. Exit code 0 with a valid result file is success; any other exit, a missing or invalid file, or a failed file check is `parse_failed` (`convert_failed` for `convert`; `render_failed` for `render`, `assemble` and `verify-render`; `render_too_large` for a page above its cap; a `document.pdf` above its cap skips the whole-document rendition). Exit code 4 is a child that couldn't install its filter, or found a second thread before loading it, and stopped before reading its request.
7. **Limits.** Files of at most 2 GiB (2,147,483,648 bytes; a larger write ends the child with `SIGXFSZ`), 256 open files, and 64 processes and threads for the child's UID, which no other running child shares. Memory: an `asyncio` task sums `VmRSS` from `/proc/<pid>/status` over every process whose real UID is the child's UID (the `tesseract` and `pdftoppm` processes the parser starts, and any process that left the child's session with `setsid`, included) every 500 ms and, above `DOCCHAT_INGESTION_PARSE_MEMORY_LIMIT_MB` (app setting, default 2,048, range 512 to 6,144, also for `convert`, `assemble` and `verify-render` in document mode), or above 256 MB for `verify-render` in page mode, ends every process of that UID (decision 14) with `parse_memory_exceeded` (`convert_memory_exceeded` for `convert`; `render_failed` for `assemble` and `verify-render`). Wall clock, through `asyncio.wait_for(process.wait(), timeout)`: `inspect` 120 seconds; `convert` min(900 seconds, the document's remaining parse budget); a `partition` part min(`DOCCHAT_INGESTION_PARSE_TIMEOUT_SECONDS` (default 1,200, range 60 to 2,400), the document's remaining parse budget); `render` min(`DOCCHAT_INGESTION_PARSE_TIMEOUT_SECONDS`, 1,200 seconds), inside Render's 2,400-second deadline; `verify-render` 120 seconds per batch and 300 seconds in document mode; `assemble` 300 seconds. On expiry every process of the child's UID is ended and the item fails with `parse_timeout` (`convert_timeout` for `convert`; `render_failed` for `assemble` and `verify-render`); when the activity reaches its own deadline first, its cancellation ends them too and the activity ends with `activity_timeout` (ADR 0144). `parse_memory_exceeded`, `parse_timeout`, `parse_failed`, `convert_timeout`, `convert_memory_exceeded` and `convert_failed` are not retried.
8. **Parse budget per document.** A build may spend at most `ingestion.max_parse_seconds_per_document` (`ops_config`, default 7,200, range 900 to 43,200) seconds of child wall-clock time. Extract adds each child's seconds (`inspect`, `convert` and `partition`, rounded up, failed attempts included) with `UPDATE app.chunk_sets SET parse_seconds_used = parse_seconds_used + @seconds WHERE id = @cs`, starts a `partition` child only while at least 1 second of budget remains, and fails the item with `parse_timeout` when the budget is spent. The budget belongs to the chunk set: a retry of the item reuses it, and a re-ingest after a failure builds a new chunk set with a new budget. Without it, a 2,000-page document could parse for 50 parts of 1,200 seconds, about 16.7 hours; 7,200 seconds allow about 3.6 seconds a page at the page cap.
9. **Concurrency.** A semaphore of `DOCCHAT_INGESTION_PARSE_SLOTS_PER_PROCESS` (default 1, range 1 to 4) per worker process bounds concurrent activities that parse, and each slot holds two parse users at a time (decision 14); parallelism comes from worker processes and instances (ADR 0053: 1, 2 and 4 worker processes on EP1, EP2 and EP3), so the parser's render lock never limits it.
10. **UID 0 or nothing.** `setpriv` can change user only from root, and the Functions base image runs the host and worker as UID 0. `docchat_ingestion.function_app` raises at import when `os.geteuid()` isn't 0, so the host loads no function and ingestion fails closed if a base image ever changes its user; the image's isolation checks and the stage-1 offline-models spike confirm UID 0.
11. **Network.** The app has no network namespace to give the child, so the child's system-call filter closes the network (decision 15): it opens no socket, so it reaches neither an internet host nor a listener on the instance's loopback interface. With no token, no identity header and no readable parent environment it also holds nothing that would reach Azure data. Egress filtering for the apps is outside the first version (ADR 0109).
12. **No shared state.** A fresh child per command carries no parser state, cache or per-document marker from one document to the next, and activity code keeps no module-level mutable state (ADR 0144); a per-table page number travels in the typed result as a warning's `page`.
13. **Telemetry.** The runner emits span `docchat.ingestion.parse` (`docchat.ingestion.parse_command`, `docchat.ingestion.content_type`, `docchat.ingestion.pages`, `docchat.ingestion.parse_peak_rss_mb`, `docchat.ingestion.parse_exit` `ok`, `timeout`, `memory` or `error`) and histogram `docchat.ingestion.parse.peak_rss` (MB, by `parse_command`), the measurement that instance sizing uses (ADR 0053); Extract's conversion call adds the histograms `docchat.ingestion.convert.duration` (s, by content type and outcome `converted`, `reused`, `timeout`, `memory` or `failed`) and `docchat.ingestion.convert.pages` (ADR 0152).
14. **One UID per concurrent child, cleared before reuse.** The image creates a pool of 16 parse users, `docchat-parse-0` to `docchat-parse-15` (UIDs and GIDs 10002 to 10017), and the lock files `/run/docchat-parse/<uid>.lock`, owned by root with mode 0600. Each parse slot holds two users at once: the first runs the activity's `inspect`, `convert`, `partition`, `render` and `assemble` children one at a time, the second its `verify-render` children (decision 17). The pool therefore holds two users for every slot one instance runs: `FUNCTIONS_WORKER_PROCESS_COUNT` × `DOCCHAT_INGESTION_PARSE_SLOTS_PER_PROCESS` is at most 8, and the worker loads no function (`parse_pool_exceeded`) when the product exceeds 8, so EP3's 4 worker processes run at most 2 slots each. Before its first child, an activity takes the first two free UIDs with a non-blocking `fcntl.flock(LOCK_EX | LOCK_NB)` on their lock files and holds each lock until every child under that user has exited, its scratch directories are removed and the user is cleared. To clear a user (when the parent takes it, between two children under it, and before it releases it), the parent runs `setpriv --reuid=<uid> --regid=<uid> --clear-groups -- kill -KILL -1` (`kill` of `procps`) and repeats until a scan of `/proc/<pid>/status` finds no process whose real, effective or saved UID is that UID, at most 10 rounds 100 ms apart. When a process remains after the tenth round, the lock stays held, `parse_uid_quarantined` is logged, and the pool shrinks until the worker restarts. Except between two children, the parent then removes every file and directory that UID owns under `/tmp`, `/var/tmp`, `/dev/shm`, `/dev/mqueue` and `/run/docchat-scratch`, following no symbolic link. Two children under one user always serve the same document within one activity (`inspect` then `partition` in Extract, or the `verify-render` batches of one Render), so between them only the processes are ended and the files are kept; the files are removed before the lock is released, so no file reaches a child of another document. When fewer than two UIDs are free, the parent tries again every 500 ms within the wall clock of the activity's first command, and the item fails with `parse_timeout` when the wall clock expires first; under the start-up check that happens only after a quarantine. `setpriv --reuid/--regid` gives each child its UID, and two children never share one, so file modes and the same-user rule of `ptrace` separate siblings. A child can create files only in its scratch directory and in the world-writable `/tmp`, `/var/tmp`, `/dev/shm` and `/dev/mqueue` (the image removes write access for others from every other path, and the container runtime mounts the shared-memory file system `/dev/shm` and the POSIX message-queue file system `/dev/mqueue`); with its own UID, `umask 077` (decision 15) and the clearing of its user, nothing it leaves there is read by another child or by the parent.
15. **A system-call filter in every child.** The first statements of `parse_worker` install the filter, before any parsing library is imported: until it is loaded, the module has imported only the standard library and `docchat_ingestion.isolation.syscall_filter`. In order, the child calls `os.umask(0o077)` and `prctl(PR_SET_DUMPABLE, 0)`, checks that `/proc/self/task` holds exactly one entry (a thread started before the load would run unfiltered; exit code 4 otherwise), and installs a seccomp filter through `docchat_ingestion.isolation.syscall_filter`, a first-party `ctypes` binding to `libseccomp.so.2` of `libseccomp2` (`seccomp_init`, `seccomp_attr_set`, `seccomp_syscall_resolve_name`, `seccomp_rule_add`, `seccomp_rule_add_array`, `seccomp_load` and `seccomp_release`; it already has `no_new_privs`), with `SCMP_FLTATR_CTL_TSYNC` set so the load applies it to every thread. Its rules: `socket()` and `socketpair()` fail with `EPERM` for every address family; `ptrace`, `process_vm_readv`, `process_vm_writev`, `process_madvise`, `pidfd_getfd`, `kcmp`, `perf_event_open`, `bpf`, `userfaultfd`, `mount`, `unshare`, `setns`, `keyctl`, `add_key`, `request_key`, `io_uring_setup`, `io_uring_enter`, `io_uring_register`, `mq_open`, `msgget`, `semget` and `shmget` fail with `EPERM` (a ring's socket and connect operations would otherwise bypass the `socket` rule, and a System V message queue, semaphore set or shared memory segment has no path, so the clearing of decision 14 couldn't find one that a child left for a later child of another document); `clone` fails with `EPERM` when its flags carry any `CLONE_NEW*` bit (one `SCMP_CMP_MASKED_EQ` rule per bit); and `clone3`, whose flags the filter can't read, fails with `ENOSYS`, on which the C library falls back to `clone`. The filter is built for the native `x86_64` interface: a call through another architecture's interface, and an `x86_64` call whose number carries the x32 bit (`__X32_SYSCALL_BIT`, 0x40000000), meets libseccomp's bad-architecture action, which kills the child. Only then does the child read its request and import the command's modules. The child exchanges data with its parent only through files in its scratch directory. The filter closes the child's outbound network, the Durable extension's loopback listener (`127.0.0.1:17071`) and reading another process's memory, and every process the child starts inherits it. A child that can't install the filter writes no result and exits with code 4 before it reads its request, and the item fails with `parse_failed` (`convert_failed` for `convert`; `render_failed` for `render`, `assemble` and `verify-render`). The `convert` child installs the same filter before it starts LibreOffice, and every LibreOffice process inherits it; only if the converter-sandbox spike's third outcome applies does the `convert` child alone allow `socket` and `socketpair` for the `AF_UNIX` family, every other family still refused (ADR 0152). The ingestion runtime self-check starts one `probe` child, in the image build and at every worker's start-up, that checks the filter's own effect, not the change of user: `socket(AF_INET, SOCK_STREAM, 0)`, `socket(AF_UNIX, SOCK_STREAM, 0)`, `socketpair`, `io_uring_setup(1, <zeroed params>)`, `ptrace(PTRACE_TRACEME)` and a `process_vm_readv` of its own memory each fail with `EPERM` (the last two succeed without the filter), `clone3` fails with `ENOSYS`, and a thread started after the load sees `socket()` refused; start-up fails (`parse_isolation_failed`) when any of these doesn't happen. `failOnNetwork` stays true for every child as a second layer, but the filter, not the audit hook, is the boundary, because native code calls the C library directly and raises no audit event.
16. **Spike: Seccomp filter in the ingestion container.** Whether an unprivileged process in an App Service Elastic Premium Linux custom container can install a seccomp filter isn't documented. Method: deploy the ingestion image to `dev` and run the self-check (the start-up checks, the isolation probe included). The spike also takes a census of loopback listeners (`90-build-order.md` section 2.16): a spike build of the image with the Debian 12 package `iproute2` logs `ss -ltnp`, `ss -lxp` and the listening rows of `/proc/net/tcp` and `/proc/net/tcp6` in `dev`, and the performer records each loopback, wildcard and Unix-domain listener with what an unauthenticated local caller can do with it, the Functions host's gRPC endpoint for the language worker and the Durable extension's listener included; the spike build runs nowhere else and is replaced when the spike ends. Pass: the filter installs and every check of the probe holds. On a fail: stop condition `SC-9` of `90-build-order.md` applies and the build stops for the product owner, who chooses between two outcomes with the census in hand. Either the owner accepts the residual risk (Consequences): a compromised child reaches the network and every listener of the census, with what the census records for each; through the Durable extension's listener it can list instances and read their status, which holds instance IDs and activity outputs with document titles, start, restart, rewind, terminate, suspend, resume and purge orchestration instances, raise events, signal, read and list entities, and make the app its task hub's primary; it holds only its own document; and the managed identity's token is protected only by `IDENTITY_HEADER` not being readable by a parse user. The filter step then leaves the child and the probe, which then checks only that `ptrace(PTRACE_ATTACH)` on its parent fails. Or parsing moves to compute that isolates the network, designed and recorded in an ADR before stage 1 continues. Either way the per-UID pool and the clearing of users (decision 14), the verify children (decision 17) and `failOnNetwork` stay in force.
17. **Second checks by an independent child.** The checks that protect readers run twice, in two children under different UIDs, so one compromised child can't pass an unsafe file on its own. Readers receive renditions only, the page renditions and the whole-document rendition, never a source file or a converted PDF (ADR 0152), so the files that reach a reader are exactly the files `verify-render` checks; a DOCX or PPTX reaches `render` as its converted PDF and gets no second check of its own. Before any rendition page is uploaded, `verify-render`, a fresh child under the second user, opens each page of a batch of at most 4 with `pikepdf` and qpdf's recovery off, refuses it on a qpdf warning, an incremental update, a hybrid cross-reference or trailing data, checks every invariant that `14-ingestion.md` section 15.6 item 14.2 lists for the pages of ADR 0145, writes the page once more as `{n}.verified.pdf` from the objects it checked, and checks that file the same way; that list is the one statement of the checks. The parent uploads `{n}.verified.pdf`, opened as decision 6 requires, and never the `render` child's bytes. Any failure is `render_failed`, and nothing of the batch is uploaded. In document mode `verify-render` checks the `assemble` child's `document.pdf` against the same invariants, with the page count equal to the version's and the document caps, and writes `document.verified.pdf`, the one file uploaded as the whole-document rendition. The verifier runs under the filter, the protocol and the limits of every child: 120 seconds per batch and 256 MB of memory in page mode, because it runs beside its `render` child and opens one page of at most 20 MiB at a time, and 300 seconds and `DOCCHAT_INGESTION_PARSE_MEMORY_LIMIT_MB` in document mode.

## Alternatives considered

- **Parsing in the worker process, on threads.** Rejected: the render lock and the GIL serialise it, a crash or leak takes the worker down, and the parser would run with `IDENTITY_ENDPOINT` and `IDENTITY_HEADER` in its own environment.
- **A long-lived process pool (`ProcessPoolExecutor` or `multiprocessing`).** Rejected: pool workers inherit the worker's UID and environment, can read its `/proc/<pid>/environ`, keep state and leaked memory from one document to the next, and one crash breaks the pool and every task in it.
- **`RLIMIT_AS` as the memory limit.** Rejected: it caps reserved address space, which the inference runtimes reserve far beyond what they touch, and applies per process, so a `tesseract` grandchild escapes the sum; a session-wide resident-memory sum measures what the instance actually spends.
- **A cgroup per child.** Rejected: it needs a writable cgroup hierarchy delegated to the container, which Elastic Premium doesn't document.
- **A separate parsing app with no identity.** Rejected: a fourth deployable, an internal network hop and its own scaling, beside the product's three components (ADR 0003), for isolation a child process gives within the ingestion app.
- **Running the worker itself as an unprivileged user.** Rejected: the worker could then start children only under its own UID, and a child under the same UID can read the worker's environment, identity header included.
- **A time limit per child with no budget per document.** Rejected: a large document split into many parts would still parse for hours.
- **One shared parse user with `PR_SET_DUMPABLE` or Yama's `ptrace_scope` only.** Rejected: either stops `ptrace` between siblings, but under one UID a child still reads a sibling's mode-0600 scratch files and shares one `RLIMIT_NPROC` count.
- **A network namespace per child.** Rejected: `unshare(CLONE_NEWNET)` needs `CAP_SYS_ADMIN` or unprivileged user namespaces, which the container doesn't document; a seccomp filter needs only the `no_new_privs` bit the child already has.
- **One child's verdict on what readers receive.** Rejected: a single parser flaw in `render` or `assemble` would then pass an active rendition to every reader of the index; a second child under another UID, with qpdf reading only the file it is given and writing it anew from the objects it checked, makes that take two independent exploits (decision 17).
- **Scratch directories in `/tmp`, with the child owning its inputs.** Rejected: any parse user can list `/tmp`, and a child that owns `source.bin` could replace it with a link before a later child of its activity reads it; a root-owned 0711 parent and root-owned 0644 inputs remove both.

## Consequences

- Every child pays Python start-up and library imports, and every `partition` child loads its models again; 40-page parts keep that cost small next to the parse itself.
- Sizing: each parse slot reserves `DOCCHAT_INGESTION_PARSE_MEMORY_LIMIT_MB` plus 256 MB for a `verify-render` child beside its `render` child, 2,304 MB at the default; EP2's 2 slots hold 2 × 2,304 MB plus about 1.5 GB for the host and workers inside 7 GB. Raising the limit or the slots first checks that slots × (limit + 256 MB) plus that overhead fits the instance; `docchat.ingestion.parse.peak_rss` shows what documents really use.
- Each slot holds two of the 16 parse users, so one instance runs at most 8 slots: EP3's 4 worker processes run at most 2 each. Each DOCX or PPTX pays for its conversion (up to 900 seconds of its parse budget, at the parse memory limit), each rendition batch for a second open of its pages, and each version for one `assemble` and one document-mode `verify-render` of up to 300 seconds each, which run one after the other and never beside another child of the slot.
- A user whose process survives 10 kill rounds is quarantined for the worker's life, so the instance runs with fewer users until its worker restarts; `parse_uid_quarantined` shows it.
- A document beyond a limit fails without retry. An operator raises the app setting or the ops-config budget and an admin re-ingests the document; nothing retries it in a loop.
- The `--nproc` limit counts the processes and threads of one UID, and no two running children share a UID, so each child has its own 64. A child that reaches it can't start a thread or process and ends with `parse_failed`. The ingestion load scenario runs 2 children per EP2 instance and shows whether 64 suffices.
- A parser flaw that runs code in one child reaches only that child's own document: it can't read a sibling's scratch files or memory, can't leave a process for the next child of its UID or a file for a child of another document (decision 14), can't make the parent follow a link it planted or carry its text into SQL, logs or telemetry (decision 6), can't open a socket to send what it read anywhere, and can't call the Durable extension's internal endpoint on the loopback interface, which answers any local caller (decision 15). Nor can it, on its own, deliver an active file: readers receive only renditions, and a rendition reaches them only when a second child under another UID passes it and writes it anew, so delivery takes two independent parser exploits (decision 17). A flaw in the converter is bounded the same way: it reaches the document it converts and the files a parse user can read, and what it writes reaches readers only through `render` and `verify-render` (ADR 0152).
- Residual risk if the seccomp spike fails and the owner accepts it under `SC-9` (decision 16): without the filter, a compromised child can open connections. It can reach any internet host from the plan's outbound addresses and any loopback service that doesn't authenticate its callers; the census of decision 16 lists every such listener and what it allows, the Functions host's gRPC endpoint for the language worker included. The Durable extension's internal endpoint is one: the child could list instances and read their status (their IDs and activity outputs, which hold document titles), start, restart, rewind, terminate, suspend, resume and purge orchestrations, raise events, signal, read and list entities, and make the app its task hub's primary. It still holds only its own document, can't read or write SQL, Blob, Search or model data, and every activity re-reads SQL and fences on the claim number, so the damage through that endpoint is the disclosure of that one document, stalled, repeated or restarted work, and a disclosure of document titles and IDs; the damage through any other listener is what the census records for it. The managed identity's token is then protected only by `IDENTITY_HEADER` not being readable by a parse user: the identity endpoint on the loopback interface issues a token to any local caller that sends that header, and the child holds it neither in its environment nor through `/proc/<parent pid>/environ` (decisions 3 and 4). `failOnNetwork` then stops a child whose Python code connects; native code isn't stopped.
- The audit hook is a detector, not a sandbox: in the image build the step's `--network=none` is the barrier, and in a deployed instance the system-call filter is.
- Every child pays for building and loading its filter, a few milliseconds beside Python start-up.
- The Functions host and worker keep running as root inside the container, which `setpriv` needs; they never parse document bytes. Trivy's Dockerfile check DS002 reports this as HIGH, and ADR 0153 excepts it on this image alone.
- Tests, run inside the built image as root (CI `images` job and the image's self-check): a memory hog killed with `parse_memory_exceeded`, also when a `tesseract`-like grandchild allocates; a sleeper ended with `parse_timeout`; the child running as a UID of the pool with no supplementary groups; two concurrent children under different UIDs, neither able to `ptrace` the other, read its memory or list its scratch directory; `socket()`, `socketpair()`, `mq_open`, `msgget`, `semget` and `shmget` refused with `EPERM`, `clone3` with `ENOSYS`, a `clone` with `CLONE_NEWUSER` with `EPERM`, an x32 call killing the child, and a thread started after the load filtered; a child whose filter can't load, or that runs a second thread before the load, exiting with code 4; the worker refusing to load when the isolation probe fails or worker processes × slots exceeds 8; a forking process left by a child ended before its UID is reused, and a file it left in `/dev/shm` or `/dev/mqueue` removed before its UID's lock is released; a symbolic link planted as `5.pdf` pointing at another directory's `source.bin` or at `/proc/1/environ`, a hard link and a FIFO refused with nothing uploaded; a `result.json` with an extra field or an unlisted code failing the item; a forged page with an `/OpenAction`, also one hidden in an incremental update, caught by `verify-render`, whose rewritten page is the one uploaded, and a forged `document.pdf` from a stub `assemble` child caught in document mode; the `convert` child under a parse user and the filter, with its limits failing with `convert_timeout`, `convert_memory_exceeded` and `convert_failed`; no `IDENTITY_ENDPOINT`, `IDENTITY_HEADER` or `MSI_*` in its environment, and `TMPDIR`, `TMP` and `TEMP` naming its directory; `PermissionError` on `/proc/<parent pid>/environ` and `/proc/1/environ`; a write anywhere other than its directory, `/tmp`, `/var/tmp`, `/dev/shm` and `/dev/mqueue` failing; a token request without the header to a loopback stand-in for the identity endpoint failing; the worker refusing to load when not UID 0. Also: the parse budget reaching 900 seconds over three parts on a fake clock and failing the item with `parse_timeout`; a forced Extract failure leaving no directory under `/run/docchat-scratch`; ingestion activities under asyncio debug with no callback blocking over 100 ms.
