# ADR 0087: Citation side viewer

- **Status:** Accepted
- **Date:** 2026-10-21
- **Decided by:** Product owner and architect
- **Specified in:** 10-web-client.md, 12-chat-pipeline.md, 82-security.md, 84-testing.md
- **Related ADRs:** 0004, 0064, 0069, 0082, 0083, 0084, 0090, 0145, 0148, 0152

## Context

- Numbered citations open their source through the authenticated API, never through a public viewer, in a side viewer next to the conversation. The client fetches the file with its bearer token and shows it from a local object URL; no storage URL reaches the browser and nothing goes to a third-party viewer. The product owner decided that readers receive only sanitised PDF renditions, for every format: the cited page, and the whole document as one PDF for viewing or saving the entire file; DOCX and PPTX are converted to PDF during ingestion, and no uploaded file is ever served (ADR 0152).
- The API opens a citation only by session ID, turn ID and citation number (ADR 0069). `getCitation` returns `number`, `title`, `pageNumber`, `headingPath`, `contentType`, `openAs` (`pdf_page`, for every format), `fileName`, `documentPdfAvailable` and `documentFileName`; `getCitationContent` returns the cited page's rendition and `getCitationDocument` the whole-document rendition, each as an `attachment` with `Content-Type: application/pdf`, `Content-Length`, `Content-Security-Policy: sandbox` and `no-store`, under the per-user download limits of ADR 0148; `getCitationDocument` answers `409 document_pdf_unavailable` when the version's whole-document rendition was above 104,857,600 bytes and wasn't built.
- Browsers don't display Office formats inline: in Edge 154 a frame pointed at a DOCX blob started a download named `<uuid>.docx` and showed nothing, so a viewer that shows every citation needs a PDF of every format. A file name can't come from `Content-Disposition`, because platform CORS exposes no response headers, so `getCitation` returns both file names in the body.
- Vendor facts: `navigator.pdfViewerEnabled` is true in Edge and Chrome; a fetched PDF wrapped in a `Blob` of type `application/pdf` and shown in an unsandboxed iframe from an object URL renders in the built-in viewer under the site's CSP with zero violations, while a sandboxed iframe shows no PDF viewer; a document loaded from a `blob:` URL inherits its creator's policy (all checked 2026-10-14 in Edge 154 and Chrome 155); `Content-Length` is a CORS-safelisted response header, readable without `Access-Control-Expose-Headers`.

## Decision

1. **Opening.** Activating citation `n` of a turn, either the inline citation button or its entry in the Sources list, opens the viewer at the right-hand end (an `InlineDrawer` of 440 px at 1,280 px and wider, an `OverlayDrawer` of size `medium` from 768 to 1,279 px and `full` below, ADR 0082), titled with the source number (`citation.title`) above the citation's title and locator; focus moves to the title and the client calls `getCitation(sessionId, turnId, n)`. A `404` shows the not-available text, a `410 document_changed` the source-changed state, and any other failure the error text with Try again.
2. **By `openAs`**, whose one value `pdf_page` applies to every format, so a DOCX or PPTX citation shows the cited page of the PDF ingestion converted from it, exactly as a PDF citation does:
   - `pdf_page` when `navigator.pdfViewerEnabled` is true: the client calls `getCitationContent`, requires status `200`, `Content-Type` `application/pdf` and at most 20,971,520 bytes, the largest page rendition, reads the body with `arrayBuffer()`, makes `new Blob([bytes], { type: 'application/pdf' })`, creates an object URL and shows it in an `<iframe>` filling the viewer body, with a `title` naming the source number, title and locator, `referrerPolicy="no-referrer"` and no `sandbox` attribute;
   - `pdf_page` when `navigator.pdfViewerEnabled` is false: the metadata panel (title, type PDF document, Word document or PowerPoint presentation from `contentType`, location, file name), the no-PDF-viewer text and the page-download button (`citation.downloadPage`);
   - below the frame or the panel, for every format, the Download full document button (`citation.downloadDocument`) when `documentPdfAvailable` is `true`, and the caption `citation.documentTooLarge` in its place when it is `false`. No action fetches an uploaded file.
3. **Frames show only PDF blobs.** A frame is never pointed at anything but a PDF blob. The viewer holds one object URL at a time and revokes it on close, on switching citations, on leaving the session and on unmount.
4. **Downloads.** The page-download button calls `getCitationContent` and the Download full document button `getCitationDocument`; each requires status `200`, `Content-Type` `application/pdf` and at most 20,971,520 bytes (a page) or 104,857,600 bytes (the whole document), types the blob `application/pdf`, creates an object URL, appends a temporary `<a download="<safe name>">`, clicks and removes it, and revokes the URL after 30,000 ms. The safe name is `getCitation`'s `fileName` (a page) or `documentFileName` (the whole document) with control characters and `\ / : * ? " < > |` replaced by `_`, cut to 150 characters before the extension, with the extension forced to `.pdf`; an empty name becomes `source-<n>.pdf`. A `409 document_pdf_unavailable` shows a warning with the problem's text, leaves the page shown and replaces the button by `citation.documentTooLarge`.
5. **Cut-short bodies.** A body read that rejects, or that yields fewer bytes than the response's `Content-Length` (the API aborts a download after 300 s, or when the client accepts less than 64 KiB in 30 s, ADR 0148), is the client outcome `download_interrupted`: the frame path shows the error text (`citation.error`) and the download path the download-failed text (`citation.downloadFailed`), each with Try again and the request's trace ID as the reference ID; no object URL is made and no file is saved.
6. **Download limits.** `429 rate_limited` and `429 too_many_downloads` (`retryAfterSeconds` 10) from `getCitationContent` or `getCitationDocument` aren't retried automatically, because a retry transfers the file again and counts against the same limits: the viewer shows `citation.limit.rateLimited` or `citation.limit.tooManyDownloads` with the time now + `retryAfterSeconds` (shown with seconds when less than 60 s away), and a Try again that is disabled until that time and then repeats the refused call (the frame's content, the page download or the whole-document download); the panel's download button is disabled for the same wait. `429 too_many_requests`, the burst limit, is retried automatically at most twice.
7. **Closing.** Escape or the close button closes the viewer, revokes its object URL and returns focus to the button that opened it.

## Alternatives considered

- **A public Office viewer or another third-party viewer.** Rejected: citations open only through the authenticated API, and such a viewer would receive the document.
- **Pointing a frame at an Office blob.** Rejected: browsers download it instead of showing it.
- **Details with a download of the uploaded DOCX or PPTX.** Rejected (ADR 0152): the reader's own Office application would open a file written by someone else, with every feature that loads content from elsewhere or runs code when it opens; the converted PDF's renditions show the same pages with no active content.
- **A sandboxed frame for PDFs.** Rejected: Edge and Chrome show no PDF viewer in a sandboxed frame; the blob document inherits the page's CSP instead, and the rendition, built from the rendition object schema, carries no annotation, link or action (ADR 0145).
- **PDF.js inside the page.** Rejected: it adds a large library (a worker, image decoders, font handling) that the app would have to keep patched, and some of its decoders and its colour management need WebAssembly, which the CSP doesn't allow without `'wasm-unsafe-eval'`; the built-in viewer covers Edge and Chrome, and the page download covers browsers without one.
- **Opening the API URL in a new tab.** Rejected: a navigation can't carry the bearer token.
- **Taking the file name from `Content-Disposition`.** Rejected: cross-origin scripts can't read it; `getCitation` returns it in the body.

## Consequences

- Citations of every format show their exact page wherever the browser has a built-in PDF viewer; elsewhere the page download saves the single page, and the whole document saves as one PDF up to 104,857,600 bytes. A DOCX or PPTX shows the converter's pages, which can differ from Office's pagination; the citation and the page the reader opens always agree, because both come from the converted PDF.
- Every viewer outcome ends in content, a stated wait or Try again, never an endless spinner or a broken file; the API keeps these responses uncompressed with `Content-Length` equal to the blob size.
- Obligations (84-testing.md): browser tests (Chromium and Edge) that a `pdf_page` citation shows the PDF in an iframe without a `sandbox` attribute and with zero CSP violations, that closing revokes the object URL, and that a DOCX and a PPTX citation arrive as `pdf_page` and show their page in the frame; browser tests that Download full document saves a `.pdf` named from `documentFileName` with unsafe characters replaced, that `documentPdfAvailable` `false` and `409 document_pdf_unavailable` show `citation.documentTooLarge`, that no action fetches an uploaded file, that no iframe ever points at a non-PDF blob, that `410 document_changed` shows the source-changed state and that Escape returns focus to the citation button; component tests with fake timers that `429 too_many_downloads` with `retryAfterSeconds` 10 and `429 rate_limited` with 25 disable Try again until the time and then repeat the call, on the frame path and on the whole-document download, with no request before Try again; component tests that a body ending before its `Content-Length`, and a body read that rejects, show the error with Try again and the request's trace ID and create no object URL.
