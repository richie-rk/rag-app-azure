# ADR 0057: Disconnects and shielded finalisation

- **Status:** Accepted
- **Date:** 2026-10-18
- **Decided by:** Architect
- **Specified in:** 12-chat-pipeline.md, 13-conversations-and-memory.md, 11-api.md, 10-web-client.md, 84-testing.md, 85-observability.md
- **Related ADRs:** 0006, 0007, 0055, 0056, 0058, 0060, 0065, 0070, 0072, 0081, 0085, 0129

## Context

- After the answer streams, the pipeline sends the `citations` event (the client re-enables input when it arrives), saves the turn and its usage, sends follow-ups and `done`, and starts the after-response work (summary and memory), which the next turn re-checks, so a crash only delays it. When the client disconnects, the API must cancel the model call and save the turn as cancelled with the partial answer. A stream stops counting toward the user's concurrency cap once its citations are sent, because the user can ask again from that point.
- If the turn were saved after `citations`, a disconnect between the two would lose a complete answer or save it `cancelled`, which keeps it out of history, and the session's active turn (ADR 0056) would still be set when the client sends its next question at `citations`.
- A closed tab must stop spending model capacity and worker resources at once, and one slow or abandoned stream must never hold a worker thread.
- A streamed ASGI response learns of a disconnect when the server reports it: the body iterator is cancelled, or its next write fails. Any `await` in that iterator can be interrupted, and the code after it then never runs. `asyncio.shield` keeps an inner task running when its awaiting caller is cancelled, and the event loop holds only weak references to tasks, so an unreferenced task can be garbage-collected before it finishes (Python documentation, checked 2026-10-18).
- App Service's front end ends a request idle for 230 s to 240 s (about 240 s on Linux) and waits at most 120 s after the stop signal (`WEBSITES_CONTAINER_STOP_TIME_LIMIT`, the platform maximum) before it kills the container; the API's Gunicorn graceful timeout is 110 s. Every I/O call is async, and no instance keeps state between requests.

## Decision

1. **Turn task.** After the pre-stream checks the route creates the turn's `asyncio.Task`, registers it in the process-wide registry `docchat_api.chat.tasks`, which holds strong references until each task ends, and returns a `StreamingResponse` whose iterator reads events from an `asyncio.Queue` fed by the task and writes lines and heartbeats. The pipeline never runs inside the iterator. When the iterator ends without having written a terminal event, its `finally` block calls `turn.client_disconnected()`.
2. **Finalise when generation ends.** When the answer stream ends, the task releases the held-back marker text as the last `delta` and reads `finish_reason` and `usage`. When the answer is complete (finish reason `stop`, or `length` with visible text, ADR 0072), it starts the follow-ups call when follow-ups apply (ADR 0065) and calls the conversation store's `finalize_turn(handle, outcome)` with status `completed`: one transactional batch that replaces the turn (answer, `answerTruncated`, `finishReason`, citations, `allowedLinks`, the usage so far), creates its `turn_trace` and clears the session's `activeTurn`. Only then does it write `citations` and release the stream lease. The wire order stays `meta`, `status`, `delta` events, `citations`, `followups`, `done`. When `finalize_turn` returns `saved = false` or raises, the stream ends with `error` `turn_save_failed` (retryable) and no `citations` event, and the follow-ups call is cancelled. A `content_filter` finish (`answer_filtered`) or a `length` finish with no visible text (`answer_incomplete`) is not complete: the turn ends `failed` through the finaliser of rule 6.
3. **Disconnect before the model stream ends.** Within 1 s the API cancels the answer call, closing its HTTP stream to Azure OpenAI, and every other in-flight call of the turn (retrieval, screening, small-model calls). The turn is saved `cancelled` with the text released so far (citation tokens included), the citations of the markers already converted, and `finishReason` `cancelled`. Usage is recorded, estimated when the usage chunk hadn't arrived (ADR 0060); the lease is released and `activeTurn` cleared; no follow-ups and no after-response work.
4. **Disconnect once the model stream has ended.** The answer is complete, so `finalize_turn` runs to its end under the shield and the turn stays `completed`; a disconnect after finalisation never changes it. A running follow-ups call is cancelled and no follow-ups are stored; an `attach_followups` that has already started runs to its end, and its follow-ups appear only in later session reads. No further event is written, and the after-response work is triggered.
5. **Replay.** A disconnect during a replay (ADR 0056) changes nothing, because a replay writes nothing; the finaliser releases its lease.
6. **One shielded finaliser.** Every path of the turn task ends in one finaliser that runs under `asyncio.shield` with a 15-second budget. It calls `finalize_turn` when step 2 wasn't attempted (`failed` and `cancelled` turns), awaits the usage counter writes (each a shielded task, ADR 0058), releases the lease if still held and, for a `completed` turn, calls the conversation store's `schedule_post_turn_work(oid, session_id, turn_id)`, which registers one post-turn task through `docchat_api.chat.tasks.register_background_task` and returns at once. `failed` and `cancelled` turns trigger no after-response work. A finaliser failure is logged and never alters the stream. When finalisation can't commit within the budget, the turn stays `streaming` until its `deadlineAt` (receipt + `chat.max_turn_seconds` + 30 s) and then reads as `failed` / `turn_abandoned`; the 30 s cover the 15-second budget with 15 s to spare.
7. **Shutdown drain** (ADR 0007). On the first stop signal the API's worker class `docchat_api.http.worker.DocChatUvicornWorker` schedules `docchat_api.chat.tasks.begin_drain()`, a plain function, with `loop.call_soon_threadsafe`; it records the signal time, arms the drain point with `loop.call_later(90, …)` and returns at once. At the drain point each turn task still running is cancelled: an open stream gets `error` `service_restarting` (retryable, `retryAfterSeconds` 5) and the shielded finaliser stores the turn `failed` with that code; a turn already finalised `completed` drops its follow-ups and writes `done`. Registered background tasks are cancelled, and the next turn-start re-check recovers their work; running citation downloads are aborted. Every turn is saved by 105 s after the signal, inside the 110-second graceful timeout.
8. **Telemetry.** Counter `docchat.chat.disconnects` with attribute `phase` (`before_finalisation` or `after_finalisation`, the boundary of rules 3 and 4); counter `docchat.chat.drained_turns`; span `docchat.chat.persist` with `docchat.outcome` and `docchat.attempts`; one warning log record `chat_drained` per worker at the drain point.

## Alternatives considered

- **Run the pipeline inside the response iterator.** A disconnect would cancel it at whatever `await` it had reached, persistence included; shielding parts of a generator is fragile, and the after-response work would depend on the connection.
- **Save the turn after `citations`.** A late disconnect would lose or downgrade a complete answer, and the next question would meet `409 turn_in_progress`.
- **Treat every disconnect as a cancellation.** It throws a complete answer, already generated and paid for, out of history.
- **Keep generating after a disconnect.** It spends tokens on an answer nobody reads, and a disconnect must cancel the model call.
- **A Starlette background task for the after-response work.** It runs only once the response has finished sending, so it is tied to the connection; the trigger in the turn task fires either way.
- **A durable outbox or queue for persistence.** It adds infrastructure and a second store to reconcile; the shielded finaliser plus deadline-based abandonment (ADR 0056) already bounds every crash.

## Consequences

- A complete answer is never lost to a late disconnect, the session is free when `citations` arrives, and the concurrency slot is released at `citations`.
- A user can see a complete answer followed by `turn_save_failed`; its message says the answer wasn't saved to history.
- A closed tab stops the model call within 1 s, so abandoned answers stop consuming capacity and worker resources.
- Every task created on the request path is registered in `docchat_api.chat.tasks`. Ruff rule RUF006, selected through the `RUF` group, flags a `create_task` result that isn't stored; registration itself is a review item.
- Disconnect detection depends on the ASGI server: an integration test proves the 1-second cancel against the stub model, and a deployed test proves that a browser disconnect reaches the API within 2 s through platform authentication and the App Service front end.
- Long Cosmos DB throttling during finalisation can exhaust the 15-second budget; the turn then reads as abandoned after its deadline, and the `docchat.chat.persist` span records the failed attempts.
- Tests: a failure injected at each pipeline step ends the stream with exactly one terminal event and the matching stored status; a disconnect during generation closes the stub model's stream within 1 s and stores `cancelled` with the partial text; a disconnect during finalisation, and again after `citations`, leaves the turn `completed`, stores no follow-ups and schedules the after-response work; the session's `activeTurn` is null when `citations` is written, so a question sent at once is accepted; a stop signal during a long stream ends it with `service_restarting` at 90 s ± 2 s and the worker exits before 110 s; a load test that stops one instance fails only its streams, and every lease expires within 210 s.
