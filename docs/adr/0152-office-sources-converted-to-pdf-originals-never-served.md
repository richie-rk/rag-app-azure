# ADR 0152: Office sources converted to PDF; originals never served

- **Status:** Accepted
- **Date:** 2026-10-25
- **Decided by:** Product owner, 2026-10-25
- **Specified in:** 14-ingestion.md, 12-chat-pipeline.md, 11-api.md, 10-web-client.md, 80-data-model.md, 81-config.md, 82-security.md, 83-infrastructure.md, 84-testing.md, 85-observability.md, 86-operations.md, 90-build-order.md, 00-overview.md, 01-repository.md, CONTEXT.md
- **Related ADRs:** 0002, 0005, 0010, 0029, 0043, 0046, 0047, 0048, 0049, 0069, 0087, 0141, 0144, 0145, 0146, 0148

## Context

- Administrators upload PDF, DOCX and PPTX files, written by other people and untrusted. A reader checks an answer by opening its citation, and every file a reader receives is opened on the reader's own device by software this product doesn't control: a page in the browser's built-in PDF viewer, in an iframe without a `sandbox` attribute (ADR 0087), or a saved file in whatever application the reader chooses.
- A DOCX or PPTX is a ZIP package of XML parts whose features load content from elsewhere or run code when Office opens the file: remote templates, linked images, linked sections and OLE links, fields that include other files, embedded OLE objects and ActiveX controls, macros, and chart data linked to workbooks. Each Office version can add another. A rule set that lets such a file reach a reader's Office application has to name every one of these features, and the list never ends.
- A PDF can carry active content too. Every page of a PDF version is built anew into a single-page rendition from a schema of what draws a page, with its annotations flattened into its content, and checked by a second child under another user before upload (ADR 0145). An Office file converted to PDF inside the ingestion sandbox can take exactly the same path, so one set of rules and one verifier cover every format.
- Readers also need the whole document, to read around a citation or keep a copy. A file joined from the verified pages carries nothing a page rendition doesn't.
- Vendor facts:
  - Debian 12 (bookworm) ships LibreOffice 7.4.7 as `-nogui` packages, built without a graphical toolkit and without an online-update component, at version `4:7.4.7-1+deb12u14` (packages.debian.org, read 2026-10-26).
  - LibreOffice starts headless with `--headless`, `--norestore`, `--nologo`, `--nodefault` and `--nolockcheck` and a user profile named by `-env:UserInstallation` (LibreOffice 7.4 Help, "Starting LibreOffice Software With Parameters", read 2026-10-26). The import filters are `MS Word 2007 XML` and `Impress MS PowerPoint 2007 XML`, the export filters `writer_pdf_Export` and `impress_pdf_Export` (LibreOffice Help, "File Conversion Filter Names", read 2026-10-26). The 7.4 Help gives `--convert-to` only the form `OutputFileExtension[:OutputFilterName[:OutputFilterParams[,param]]]`, with filter parameters documented for the Lotus, dBase, Diff and CSV filters only; the Help page "PDF CLI Parameters", which documents a JSON form of PDF export options, exists in the 7.6 Help and later and not in the 7.4 or 7.5 Help; the 7.4 release notes name improved PDF export options on the command line only through a link to a blog post, with no syntax (help.libreoffice.org and wiki.documentfoundation.org/ReleaseNotes/7.4, read 2026-10-26).
  - The configuration schema at tag `libreoffice-7.4.7.2` defines the profile properties used below, with their defaults, the PDF export options of the group `Filter/PDF/Export` in `Common.xcs` among them (the `officecfg` schema files, read 2026-10-26).
  - `BlockUntrustedRefererLinks` "Blocks the use of linked images by documents not in the trusted locations", which then show a placeholder frame (LibreOffice 7.4 Help, "Security Options and Warnings", read 2026-10-26).
  - Writer updates Author, Sender, Chapter, Date, Time, References and Last printed when it prints or exports a PDF, whatever the field update setting, and ignores the automatic link update settings stored in documents (LibreOffice 7.4 Help, Writer options "General", read 2026-10-26).
  - A tier named at upload overrides the account's default, and a Cool blob deleted or overwritten within 30 days is charged the remaining days, prorated ("Access tiers for blob data", ms.date 2026-04-02, read 2026-10-26); a lifecycle policy change takes up to 24 hours to apply ("Azure Blob Storage lifecycle management overview", ms.date 2025-09-15).

## Decision

1. **Readers receive only renditions, for every format.** The cited page's rendition (`getCitationContent`) and the whole-document rendition (`getCitationDocument`, and `adminGetDocumentPdf` for an administrator) are the only files any API operation streams. No operation and no web client action serves an uploaded file or a converted PDF, for any format; the API's code never reads the container `documents` after an upload's commit (ADR 0069). Every citation of every format is `openAs` `pdf_page` and names a page of its version's PDF (ADR 0087).
2. **DOCX and PPTX are converted to PDF in the sandbox.** Extract runs the Office checks of the `inspect` child (the archive limits, encryption, the refusal of content types that declare macros and the Office type check of ADR 0043), then a `convert` child (`docchat_ingestion.isolation.convert`) under every isolation measure of the parsing children (ADR 0049): a parse user of the pool, the system-call filter that refuses every socket, no identity variable, files of at most 2 GiB, 64 processes and threads, 256 open files. The child runs LibreOffice 7.4.7 from the Debian packages `libreoffice-core-nogui`, `libreoffice-writer-nogui`, `libreoffice-impress-nogui`, `libreoffice-draw-nogui`, `libreoffice-base-core`, `libreoffice-common`, `ure`, `uno-libs-private` and `libreoffice-style-colibre` (`4:7.4.7-1+deb12u14`), `fonts-opensymbol` (`4:102.12+LibO7.4.7-1+deb12u14`) and `libnumbertext-data` (`1.0.11-1`), with the metric-compatible fonts `fonts-crosextra-carlito` (`20220224-1`), `fonts-crosextra-caladea` (`20200211-1`) and `fonts-liberation2` (`2.1.5-1`), about 300 MB in the ingestion image in all (ADR 0010):
   - a fresh profile per child, whose `registrymodifications.xcu` the parent writes, owned by root with mode 0644: `DisableMacrosExecution` `true`, `MacroSecurityLevel` 3, `OfficeBasic` 0, `ExecutePlugins` `false` and `BlockUntrustedRefererLinks` `true`, which blocks linked images only (`/org.openoffice.Office.Common/Security/Scripting`); Writer's `Content/Update/Link` 2 (never updated on load) and `Content/Update/Field` `false`; VBA `Load` and `Executable` `false` for Writer and `Load` `false` for Impress; recovery information, autosave and timed autosave off; and the PDF export options of `/org.openoffice.Office.Common/Filter/PDF/Export`, the same for both export filters: `ExportFormFields`, `ExportNotes`, `ExportNotesPages`, `ExportHiddenSlides`, `ExportPlaceholders`, `ExportBookmarks`, `ExportBookmarksToPDFDestination`, `ConvertOOoTargetToPDFTarget`, `ExportLinksRelativeFsys`, `IsAddStream` and `UseTaggedPDF` all `false`, three of which (`ExportFormFields`, `ExportBookmarks`, `ExportLinksRelativeFsys`) differ from the schema default;
   - the import filter named for the type, never chosen by content, and the export filter `writer_pdf_Export` or `impress_pdf_Export`, named as `--convert-to 'pdf:<export filter>'` with no filter options, because no 7.4 documentation gives a syntax for PDF export options on the command line. No 7.4 documentation states either that the export filters read the profile's options when the command passes none, so SP-15 (decision 8) confirms that each option takes effect. These options reduce what the converted PDF holds and aren't the control: Render builds every page from the rendition object schema whatever the converter wrote (ADR 0145), so an option that doesn't take effect is recorded and changes nothing a reader receives;
   - limits: 900 seconds of wall clock, or the document's remaining parse budget when smaller; 2,048 MB of memory over every process of the child's UID; `converted.pdf` at most 209,715,200 bytes, the largest upload; at most `ingestion.max_pages_per_document` pages (default 2,000). A wall-clock end fails the item with `convert_timeout`, a memory end with `convert_memory_exceeded`, and any other failure, an oversize output included, with `convert_failed`; none is retried, because the same bytes convert the same way. Too many pages fail with `page_limit_exceeded`.
3. **Then exactly as a PDF.** The parent checks `converted.pdf` as it checks every child output, an `inspect` child checks it and counts its pages as for any PDF, and from then on the version is processed as a PDF source: both methods parse the converted PDF (ADR 0047, ADR 0048), every chunk of every format carries a page from 1 to the version's `page_count`, and Render writes its page renditions and its whole-document rendition (ADR 0145). Chunk text comes from the converted PDF's text layer: nothing parses the Office file for text, and no OCR pass runs over page images of an Office file.
4. **One converter version.** `CONVERTER_VERSION` = `"lo-" + LIBREOFFICE_PACKAGE_VERSION + "/" +` the first 12 hexadecimal characters of the SHA-256 of the profile bytes, which hold the export options, at most 34 characters; the image self-check fails the build when `LIBREOFFICE_PACKAGE_VERSION` differs from the installed `libreoffice-core-nogui`. The converted PDF is kept as `documents/{indexId}/{documentId}/{v}/converted.pdf` in the Cool tier, with `document_versions.converter_version` and `converted_sha256`, and a re-ingest reuses it only under the same converter version. A citation opens only when its chunk set's `pdf_sha256` equals the version's PDF hash (the source's for a PDF, `converted_sha256` for a DOCX or PPTX), so a conversion under another converter version never shows a page that holds other text.
5. **The whole-document rendition.** Render joins the verified page renditions into `document.pdf` in an `assemble` child (300 seconds), which copies each page through the rendition object schema and adds only the page tree, and a `verify-render` child in document mode (300 seconds) checks it against the same schema and writes the file that is uploaded. It is built only while the verified pages total at most 104,857,600 bytes (`renderMaxDocumentBytes`); above that the version's `document_pdf_status` is `too_large`, `getCitation` returns `documentPdfAvailable` `false`, and `getCitationDocument` answers `409 document_pdf_unavailable`, while every page still opens. Render's deadline is 2,400 seconds (ADR 0144).
6. **Originals in the Cool tier.** The upload commit names `StandardBlobTier.COOL`, so every uploaded file lands in the Cool tier when it is committed, with no lifecycle rule; ingestion writes each `converted.pdf` in the Cool tier the same way. After its commit an uploaded file is read only by ingestion and by the operator command below.
7. **Operators alone retrieve an uploaded file.** `docchat-ops document fetch-source --version <uuid> --out <path>`, at level `user_data` and with a ticket, downloads the version's source under the operator's own credential, checks its SHA-256, writes it with mode 0600 to a path that must not exist, warns that the file is untrusted and must be opened only in an isolated environment, and records the audit action `document.source_fetched` (runbook R37). It is the supported way to retrieve an uploaded file, for an audit or legal request. The level's Storage Blob Data Reader role at the scope of the container `documents` also permits a direct read of any blob of the container during the activation, which the activation and the `StorageRead` entries of `StorageBlobLogs` record and no alert watches; it is accepted as an operator-trust residual (`82-security.md` section 1.6).
8. **What the build proves first.** Whether LibreOffice converts under the system-call filter, within the child's limits, isn't documented: spike SP-15 runs in stage 1 after SP-14, and its outcomes are decided in advance (the design stands; the child starts `soffice.bin`; the filter allows `socket` and `socketpair` for `AF_UNIX` alone once the census finds no Unix-domain listener a parse user can reach; or stop condition SC-11 for the product owner). It also records, on the fixtures that carry each feature, whether each export option of decision 2 takes effect. Its outcome line is appended here and in ADR 0141.

## Alternatives considered

- **Serving the Office file itself behind allowlist and deny rules.** Rejected: the Office feature surface that loads content or runs code is open-ended, so every rule set leaves the next feature to be found, and a reader's Office application would still open a file written by someone else.
- **OCR of page images of the converted document.** Rejected: the converted PDF's text layer carries the Office file's exact text, and OCR would only add errors and cost.
- **Parsing the Office file for text, beside the conversion for pages.** Rejected: two parsers would read the hostile file, and every chunk's position in the Office file would need mapping onto a page of the converted PDF before a citation could open it.
- **An administrator download of the uploaded file.** Rejected: an administrator's device would open the same hostile file; the operator command keeps the retrieval rare, audited and outside the browser.
- **The converted PDF, or the uploaded PDF, as the whole-document download.** Rejected: neither has passed `verify-render`; the joined verified pages carry nothing a page rendition doesn't.
- **A lifecycle rule that moves sources to Cool.** Rejected: a rule runs periodically and a policy change takes up to 24 hours to apply, so every source would first be stored and billed as Hot.

## Consequences

- No file an uploader supplied reaches a reader as it was uploaded; a reader sees only renditions built from the rendition object schema, which show the page and the flattened appearances of its annotations and hold no link of any kind.
- Residual: one LibreOffice exploit runs code inside the `convert` child. It reaches the document itself and the files a parse user can read, with no network (or, should SC-9's fallback be chosen, what that fallback bounds); the image holds no world-readable secret, which the readable-files check proves at every build.
- Residual: a compromised converter can put any content into the converted PDF. Render builds every rendition from the schema, so a construct outside it reaches readers only through two further exploits, one in `render` and one in `verify-render`, or through a key the schema allows by mistake (ADR 0145); what does reach the reader is misleading text or images, or a font or image crafted against the reader's PDF engine, which the reader's viewer and its sandbox bound.
- Readers see LibreOffice's pagination, which can differ from Office's; the citation and the page it opens always agree, because both come from the converted PDF. Fonts the image doesn't hold are replaced by LibreOffice's fallback, and CJK text keeps its characters in the text layer with fallback glyphs.
- A re-ingest that converts a DOCX or PPTX version under another converter version replaces its page renditions, because the rendition paths name the version only. From that Render on, a citation of an earlier chunk set of the version answers `410 document_changed` (its `pdf_sha256` differs from `converted_sha256`), and the reader asks the question again; this includes the served chunk set until the re-ingest's Flip, which follows Render directly, and, when Render fails or the Flip requeues the item, until a later re-ingest of the version reaches its Flip. Re-ingests under the same converter version reuse the converted PDF and change no page.
- With the export options in effect, comments, speaker notes, hidden slides, form-field widgets and bookmarks stay out of the converted PDF, and links reach no rendition whatever the options do. A field shows the result stored in the file, except the seven fields Writer updates when it exports a PDF (Author, Sender, Chapter, Date, Time, References and Last printed), none of which reads a file; a Date or Time field shows the time of the conversion.
- The ingestion image grows by about 300 MB, Extract's deadline carries a conversion of up to 900 seconds, and Render's deadline is 2,400 seconds; storage adds one converted PDF per Office version and one whole-document rendition per version.
- A version deleted within 30 days of its upload is charged the rest of Cool's 30-day minimum, at most 30 days of storage of that file.
- Telemetry (85-observability.md): `docchat.ingestion.convert.duration` (`content_type`; `outcome` `converted`, `reused`, `timeout`, `memory` or `failed`) and `docchat.ingestion.convert.pages`, and the dashboard panel "Office conversions".
- Obligations (84-testing.md): the converter tests over fields that include `file:///etc/hostname` and a sibling scratch directory, a linked section, linked images named by a UNC path and an `http` URL, an OLE link and a macro that runs on open, each asserting that the converted PDF holds none of the named content and that no macro ran; the converter's limits and codes; the Office path processed exactly as a PDF, with no Extract call after the conversion and no Render call reading the source; the whole-document rendition tests; the citation tests for every format; the `fetch-source` command test; the readable-files check; and SP-15 recorded as a stage-acceptance test.
