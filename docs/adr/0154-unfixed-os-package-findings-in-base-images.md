# ADR 0154: Unfixed OS-package findings in base images

- **Status:** Accepted
- **Date:** 2026-11-07
- **Decided by:** Product owner, 2026-11-07
- **Specified in:** 84-testing.md, 82-security.md, 01-repository.md, 14-ingestion.md
- **Related ADRs:** 0010, 0049, 0136, 0153

## Context

- ADR 0136 makes every high or critical scanner finding fail the build, unfixed ones included, and leaves a finding that nothing in the repository can remove to the product owner through a new ADR (its item 9; runbook R17 step 10; stop SC-7 of `90-build-order.md`). ADR 0153 is the first such decision, for Trivy's DS002 on the ingestion image.
- Trivy 0.76.0 (the `images` job's command, its databases of 2026-11-07) reported in the images built on the earlier pins 46 HIGH or CRITICAL Debian 12 package findings each in the API and model-stub images (`python:3.13.16-slim-bookworm`), 4 of them with a fix, and in the ingestion image (`azure-functions/python:4.1055.150-0-python3.13`) 203 Debian findings, 42 with a fix, plus 18 in the Functions host's .NET 8.0.31 runtime and in the Go binary `/opt/startupcmdgen/startupcmdgen`, all fixed upstream.
- On the newest base digests of 2026-11-07, `python:3.13.18-slim-trixie` (Debian 13.7) and `azure-functions/python:4.1055.300-3-python3.13` (Functions host 4.1055.300.3, .NET 8.0.33, Debian 12.15), every finding with a fix is gone once each runtime stage takes the Debian security updates its digest predates and the ingestion image drops the unused Go binary (decision 1). What remains is HIGH or CRITICAL findings in OS packages for which Debian has published no fixed version: 47 HIGH in the API image and 47 in the model-stub image (18 packages, among them `libsqlite3-0`, util-linux, ncurses, systemd and `perl-base`), and 156 HIGH and 5 CRITICAL in the ingestion image (75 packages, the five CRITICAL in `libglib2.0-0`, `libglib2.0-data`, `libsqlite3-0`, `libxml2` and `zlib1g`). They sit in packages every Debian image carries or that the product needs (the converter's and the OCR tool's libraries, GLib, the ODBC driver's dependencies), so no base-image digest, package removal or dependency replacement clears them, and a distroless or Alpine base was rejected by ADR 0010.
- Trivy's JSON report gives each vulnerability its result's `Class` (`os-pkgs` for the packages of the image's distribution, `lang-pkgs` for language packages and binaries such as Python distributions, the .NET runtime and Go modules), a `FixedVersion` (absent while the distribution has published no fix) and a `Status` (`fixed`, `affected`, `fix_deferred`, `will_not_fix`, `end_of_life` and others). Its database can trail the Debian security archive by days: its database of the morning of 2026-11-07 still listed `zlib1g`'s CVE-2026-85091 without a fix, although Debian's security update `1:1.3.dfsg+really1.3.1-1+deb13u1` of 2026-11-01 fixes it; that evening's database records the fix.

## Decision

1. **Every finding with a fix is fixed.** The base images move to the newest digests above (`01-repository.md` sections 4.4 to 4.6 and 10.1; `14-ingestion.md` section 15.2). Each runtime stage upgrades exactly the base packages whose Debian security fix the pinned digest predates, named in its Dockerfile, with `apt-get install --no-install-recommends --only-upgrade` in its apt layer: `zlib1g` in the API and model-stub images, `apt`, `apt-transport-https` and `libapt-pkg6.0` in the ingestion image. The ingestion image removes `/opt/startupcmdgen`, App Service's startup-command generator, which its start script never runs; the step fails if a script under `/opt/startup` names it. A finding whose report names a fix is never excepted.
2. **One exception kind, named in code.** The security gate passes a Trivy finding under this exception only when all of these hold: it is a vulnerability (never a secret or a misconfiguration); its result's class is `os-pkgs`; it is rated HIGH or CRITICAL; the report gives it no fixed version (no `FixedVersion`, and a `Status` other than `fixed`); and it is in the report `trivy-<image>.json` of the image the entry names, `api`, `ingestion` or `model-stub`. A language package's finding (a Python distribution, the Functions host's .NET runtime, a Go module), a finding with a fix, a secret, a Dockerfile misconfiguration, a finding in `trivy-config.json` and another image's finding still fail. `scripts/ci/security_gate.py` holds the kind `unfixed-os-packages` and the three images it may name in a constant beside ADR 0153's `(DS002, ingestion)`; widening it takes a reviewed change to the gate, the spec and a new ADR.
3. **Where it is written.** `.github/security/exceptions.yaml`, in the form of ADR 0153's entry: one entry per image with exactly `id` (`unfixed-os-packages`), `image`, `reason` (at least 20 characters), `decision` (`ADR 0154`), `added` and `review_by` (dates `YYYY-MM-DD`). An entry naming another image, or with a missing, unknown, repeated or malformed field, fails the gate.
4. **90 days at most.** `added` isn't after the day the gate runs and `review_by` is at most 90 days after `added`. From the day after `review_by` the entry is invalid and every gate run fails (the `images` job, the deploy workflow's `build` job, the nightly `trivy-rescan` and the nightly `--waivers-only` run), so every such finding fails again, until `docchat-security` renews the entry with new dates or removes it. Before renewing, it checks that each base image is at its newest digest and that the image has no finding with a fix. The gate warns 14 days before `review_by` in the job summary and the nightly log. The first entries are dated 2026-11-07 with `review_by` 2027-02-05.
5. **Re-checked every night.** `nightly.yaml` job `trivy-rescan` scans the images `dev` and `prod` run and passes each environment's reports through the same gate (`--job build`). A finding whose report gains a fixed version no longer meets item 2 and fails the next night's run, which opens or updates the rescan issue; runbook R17 then moves the base digest or names the package in the runtime stage's upgrade, and the next release clears it.
6. **What stays.** Every other high or critical finding fails the build whatever any file holds; waivers still exist only below high and name no Trivy finding; ADR 0153's exception is unchanged.

## Alternatives considered

- **Trivy's `--ignore-unfixed` or `--ignore-status`.** Rejected for ADR 0136's reasons: the findings would vanish from the reports with no record, no expiry and no approver, and the flag would hide unfixed language-package findings too.
- **One entry per CVE.** Rejected: about 255 findings at adoption, changing with every Debian advisory, add review work without adding safety, because the gate checks from each report that no fix exists.
- **One entry for all three images.** Rejected: an entry per image names exactly the report it covers and can be removed for an image whose findings are gone while the others stay.
- **Upgrading every package (`apt-get upgrade`) in each runtime stage.** Not adopted: it would change packages that no Dockerfile names; the explicit list keeps every upgrade visible in review, and the base digest's move removes it.
- **Waiting for Debian.** Rejected: every merge and release, security fixes included, would stay blocked by findings Debian may not fix for months.
- **Covering language-package findings too.** Rejected: the product owner scoped the exception to OS packages; a language package with a finding is fixed by the lock, a base-image move or removal.

## Consequences

- The `images` job passes while the only HIGH or CRITICAL findings are unfixed OS-package findings of the three images and ADR 0153's DS002; its summary lists each one as passing under `unfixed-os-packages` on its image, with the review date.
- Accepted risk: known HIGH or CRITICAL vulnerabilities in base-image OS packages that Debian hasn't fixed ship to `dev`, `load` and `prod` for at most 90 days at a time. The API and model-stub processes run as UID 10001, and every parse runs as a parse user under the system-call filter (ADR 0049).
- Obligations: `docchat-security` reviews the entries before each review date (runbook R17); the release's final security pass checks that no exception has passed its review date.
- Tests (84-testing.md, T-527): an unfixed HIGH or CRITICAL OS-package finding passes in each image's report; a finding with a fixed version or status `fixed` fails; a language-package finding, a secret and a misconfiguration fail; an image's entry doesn't cover another image's report; an entry past its review date fails; a `review_by` more than 90 days after `added` and an entry for another image are refused; the nightly run warns 14 days before the review date, and its `build` gate fails once a finding gains a fix.
