# ADR 0086: One build configured at deploy time

- **Status:** Accepted
- **Date:** 2026-10-21
- **Decided by:** Architect
- **Specified in:** 10-web-client.md, 81-config.md, 83-infrastructure.md, 84-testing.md, 86-operations.md
- **Related ADRs:** 0004, 0008, 0016, 0018, 0083, 0092, 0110, 0120, 0121, 0124, 0127

## Context

- The web client's bundle and its configuration file may carry only four public values: tenant ID, client ID, API base URL and API scope. No key, storage URL, service endpoint or source map may reach the browser or the repository, and an environment must never pick up another environment's endpoints. One build serves every environment: the public settings load at start-up from `config.json`, and the deployment writes `config.json` and `staticwebapp.config.json` for each environment.
- The CSP lives in a static header file that names the API origin (ADR 0083), so it is also written per environment.
- Vendor facts (checked 2026-10-14): `staticwebapp.config.json` must sit at the root of the deployed output and is limited to 20 KB, and its header values are static strings; Static Web Apps deploys with a deployment token (recommended) or a GitHub token; azd's Static Web Apps host reads the deployment token through `ListStaticSiteSecrets` and runs `npx -y @azure/static-web-apps-cli@latest deploy`, an unpinned CLI, on the built folder as it is; the current CLI release is 2.0.10.

## Decision

1. **`config.json` holds exactly four public values**, in this order and nothing else: `tenantId` (canonical lower-case UUID); `clientId` (canonical lower-case UUID, the web client registration's application ID); `apiBaseUrl` (the API's origin: `https://`, lower-case host, optional port, no path, query, fragment or trailing slash; `http://localhost:<port>` or `http://127.0.0.1:<port>` only when the page itself is served from that host); `apiScope` (an `api://` URI ending in `/access_as_user`, at most 255 characters). At start-up the client fetches it with `fetch('/config.json', { cache: 'no-store', credentials: 'same-origin', redirect: 'error' })` and parses it with a strict Zod object that rejects unknown members; any failure shows the configuration-error screen with Reload. Nothing else configures the client: `import.meta.env` is read only for `DEV`, and there are no feature flags, endpoints in code or fallback values. The MSAL redirect URI follows the page's own origin (ADR 0018), so a custom domain needs no rebuild.
2. **The generator.** `apps/web/scripts/write-env-config.mjs` (Node 24, no dependencies) is the only way the two environment files are produced. Inputs: the environment variables `AZURE_TENANT_ID`, `WEB_CLIENT_ID`, `API_BASE_URL` and `API_SCOPE`, azd environment values from Bicep outputs; arguments `--dist <dir>` (default `dist`) and `--allow-loopback`, which only the browser-test harness passes. It validates the values by item 1's rules and exits with code 1, naming the failing variable and writing nothing, on any violation. It writes `<dist>/config.json` (compact JSON with the four members in order, UTF-8, one trailing newline) and `<dist>/staticwebapp.config.json` (the template of ADR 0083 with its single placeholder `__API_ORIGIN__` replaced by `new URL(API_BASE_URL).origin`, parsed as JSON, failing when the serialised file exceeds 20,480 bytes). It is idempotent and touches nothing outside `<dist>`.
3. **Build once.** CI builds `apps/web` once per commit with `npm ci` and `npm run build` (`tsc -b`, `vite build`, then `scripts/check-dist.mjs`) and keeps the unconfigured `dist/` as the `web-dist` artifact. Vite builds with `build.sourcemap` false, so no source map exists.
4. **The build-output gate.** `scripts/check-dist.mjs` fails the build when `dist/` contains a `config.json` or `staticwebapp.config.json`; any `*.map` file; an HTML file with an inline `<script>` without `src`, a `<style>` element or a `style=` attribute; any of the strings `AccountKey=`, `SharedAccessSignature`, `sig=`, `x-functions-key`, `-----BEGIN`, `.blob.core.windows.net`, `.azurewebsites.net`, `.search.windows.net`, `.openai.azure.com` or `api-key`; or initial JavaScript (the entry chunk and its static imports) larger than 500 KB gzip-compressed.
5. **The one deploy path.** `scripts/deploy/deploy_web.py --env <env> --dist <artifact directory>` copies the artifact into a fresh directory; runs the generator with exactly the four azd values; reads the Static Web Apps deployment token with `az staticwebapp secrets list --name <static web app> --resource-group rg-docchat-<env> --query properties.apiKey -o tsv`, masks it at once and passes it only as `SWA_CLI_DEPLOYMENT_TOKEN` in the child process's environment; and uploads with `@azure/static-web-apps-cli` 2.0.10, extracted from an archive that a credential-free job built with `npm ci --ignore-scripts`, through `npx --no-install swa deploy <directory> --env production --no-use-keychain`. The deployed smoke tests then run (ADR 0092), and any failure fails the deploy job.
6. **azd refuses.** The `web` service in `azure.yaml` keeps a service-level `predeploy` hook (POSIX `sh` and Windows `pwsh`) that writes a one-line message naming `scripts/deploy/deploy_web.py` to standard error and exits with code 1, so `azd deploy web` and `azd up` can't upload the environment-free build, which has no `config.json` and no CSP; the service stays in `azure.yaml` for `azd show`. Local web deploys run `uv run --frozen python scripts/deploy/deploy_web.py --env <env> --dist apps/web/dist` after `npm ci` and `npm run build`.
7. **Local development.** The Vite dev server answers `GET /config.json` from the git-ignored `config.local.json` (whose `apiBaseUrl` is `http://localhost:5173`) through a serve-only plugin, and proxies `/v1` and `/healthz` to `DOCCHAT_DEV_API_TARGET` (default `http://127.0.0.1:8000`), read only by `vite.config.ts`; so the build never contains a configuration file and no environment needs a localhost CORS rule. `config.example.json` holds the four members with placeholder values.
8. **Order and hygiene.** In every environment the API deploys before the web client, so a web release never calls an operation or field the running API lacks. `.gitignore` lists `apps/web/dist/`, `apps/web/config.local.json`, `*.zip`, `test-results/` and `playwright-report/`.

## Alternatives considered

- **Build per environment with build-time variables.** Rejected: the values would be compiled into the JavaScript, each environment would run a different build, and a missing value could fall back to another environment's.
- **Serve the configuration from the API.** Rejected: the client needs the API's origin and the sign-in values before it can call the API.
- **`azd deploy web`.** Rejected: azd uploads the environment-free build without `config.json` or the CSP, and runs the deployment CLI unpinned.
- **Committing build output.** Rejected: built archives can carry keys and source maps; `.gitignore` and the gate keep them out.

## Consequences

- One artifact is promoted unchanged through `dev` and `prod`; the only differences between environments are four public values and one CSP origin, and a deploy with a bad value stops before upload.
- A key, a service endpoint or a source map that reaches the build fails it, and a deploy takes effect at the next page load, because `config.json` and the shell are served with `no-store`.
- The deploy step reads a deployment token, a key, at deploy time and never stores it; that exception is recorded in ADR 0121.
- Procedures (86-operations.md): rolling back redeploys the last good commit's unconfigured artifact through the same job; a custom domain on the web client needs DNS validation, the SPA redirect URI and the API's CORS origin, and no rebuild; changing the API's origin means deploying the API on the new origin, changing `API_BASE_URL`, redeploying the web client so `config.json` and the CSP change together, running the smoke tests and retiring the old origin.
- Obligations (84-testing.md): unit tests that `loadConfig` accepts the four valid fields and rejects an extra member, a missing member, an upper-case or malformed UUID, an `http:` API origin on a non-loopback page, an origin with a path or trailing slash and a scope not ending in `/access_as_user`; that `write-env-config.mjs` writes `config.json` byte for byte and `staticwebapp.config.json` equal to the template with the origin substituted, exits with code 1 writing nothing for each invalid input, and fails above 20,480 bytes; that `check-dist.mjs` fails on a planted `.map`, a planted `config.json`, an inline script, a `style=` attribute, each forbidden string and an oversized entry chunk; that the Vite proxy targets `DOCCHAT_DEV_API_TARGET` or `http://127.0.0.1:8000` and the production build holds neither; a deployed smoke test that `/config.json` has exactly four members equal to the environment's Bicep outputs.
