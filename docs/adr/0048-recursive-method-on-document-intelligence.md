# ADR 0048: Recursive method on Document Intelligence

- **Status:** Accepted
- **Date:** 2026-10-18
- **Decided by:** Product owner and architect
- **Specified in:** 14-ingestion.md, 12-chat-pipeline.md, 80-data-model.md, 84-testing.md, CONTEXT.md
- **Related ADRs:** 0046, 0047, 0049, 0050, 0061, 0069, 0087, 0145, 0152

## Context

The product owner's second ingestion method chunks the output of Azure AI Document Intelligence's layout model. Its shape is set: Markdown output; splitting by headings, then paragraphs, then sentences, up to a target size with overlap (method parameters starting at 512 tokens with 25% overlap); tables kept whole where they fit and otherwise split by rows with the header repeated; and a citation anchor of the page where the chunk starts plus its heading path. A citation names a page. A DOCX or PPTX reaches the method as the PDF the converter of ADR 0152 made from it, so the layout service always receives a PDF and a slide is one page. Chat serves every citation, of every format, from the version's single-page rendition (ADR 0069), so every chunk needs a page between 1 and the page count that Extract's `inspect` records, which is also the number of renditions Render writes.

A failed analysis must fail its item with a clear code, and the chunker must never index part of a document as if it were all of it: an extraction error is reported, never swallowed.

Vendor facts (checked 2026-10-14 unless noted):

- REST API 2024-11-30 (v4.0) is the latest GA version and the one Microsoft names for new development; `azure-ai-documentintelligence` 1.0.2 is the latest stable SDK and targets it. Its async client (`azure.ai.documentintelligence.aio.DocumentIntelligenceClient`) offers `begin_analyze_document(model_id, body, *, pages, locale, string_index_type, features, query_fields, output_content_format, output)` and `delete_analyze_result(model_id, result_id)`; analyze results are otherwise kept 24 hours. Entra authentication needs the resource's custom subdomain.
- `prebuilt-layout` reads PDF, DOCX and PPTX among others. With `outputContentFormat=markdown`, `result.content` holds Markdown: headings `#` to `######`, paragraphs separated by blank lines, tables as full HTML (`<table>`, `<tr>`, `<th>`, `<td>`, `rowspan` and `colspan`, `<caption>`) so merged cells and multi-row headers survive, figures as `<figure>` with `<figcaption>`, page metadata as `<!-- PageHeader="..." -->`, `<!-- PageFooter="..." -->` and `<!-- PageNumber="..." -->`, and `<!-- PageBreak -->` between pages.
- Page units: a PDF page; up to 3,000 characters of DOCX; a PPTX slide. Section headings are marked in PDF and DOCX but not in PPTX. Embedded or linked images in Office files aren't analysed. Limits: 2,000 pages per analysis, 500 MB per document on S0, 8 million characters per Office file; password-locked PDFs are refused.
- S0 allows 15 analyze transactions per second by default; a `429` carries `retry-after`; results are polled no more than once every 2 seconds.
- `StringIndexType` has the members `TEXT_ELEMENTS`, `UNICODE_CODE_POINT` and `UTF16_CODE_UNIT` (checked 2026-10-15). Python indexes `str` by code point.

## Decision

1. **Engine.** Method key `recursive`, version 1 (ADR 0046), on `prebuilt-layout`, API 2024-11-30, through `azure-ai-documentintelligence` 1.0.2 (async). After the isolated `inspect` child has checked the version's PDF (for a DOCX or PPTX, its converted PDF) and counted its pages (ADR 0049), Extract calls, in the activity process, `begin_analyze_document("prebuilt-layout", <file stream>, content_type="application/octet-stream", output_content_format="markdown", string_index_type=StringIndexType.UNICODE_CODE_POINT)`, polls every 3 seconds (or the service's `retry-after` when longer) for at most 40 minutes, then calls `delete_analyze_result()` (best effort). The client comes from `docchat_core.clients` with the ingestion identity (Cognitive Services User on the account), the custom-subdomain endpoint `DOCCHAT_DOCINTEL_ENDPOINT`, `connection_timeout=10` and `read_timeout=300` seconds. Each document is analysed in one call; `docintel_pages` = `len(result.pages)` is stored on the run item.
2. **Extract file.** `ingestion-work/{runId}/{documentId}/{v}/extract/document.json`: `{"formatVersion": 1, "method": "recursive", "pageCount": n, "markdown": "<result.content>", "pageOffsets": [{"pageNumber": n, "offset": <code points>, "length": <code points>}], "docIntelPages": n}`, one `pageOffsets` entry per span of `pages[].spans` (a page with several spans has several entries). Every offset is a Python `str` index into `markdown`.
3. **Parameters** (`RecursiveParametersV1`, `extra="forbid"`): `targetTokens` (integer 128 to 2,048, default 512); `overlapPercent` (integer 0 to 50, a multiple of 5, default 25; an integer so validation never depends on floating-point remainders); `tableMaxTokens` (integer 256 to 6,000, default 1,600). Tokens are counted with the physical index's encoding (`cl100k_base` for `text-embedding-3-large`).
4. **Blocks.** The Markdown is parsed in order into headings, paragraphs (text separated by blank lines), tables (an HTML `<table>…</table>` block, sanitised by the allowlist of ADR 0047) and figures (only the `<figcaption>` text, kept as a paragraph). The comment markers `PageHeader`, `PageFooter`, `PageNumber` and `PageBreak` are dropped; pages come only from `pageOffsets`, never from counting markers. Every block, and every sentence and table row cut from one, records its start offset in `markdown`.
5. **Sections.** A heading opens a section at its level; the heading path is the stack of open headings, at most 8, each cut to 200 characters; the heading text is the first line of the section's first chunk.
6. **Packing.** Within a section, consecutive paragraphs are packed into a chunk while the total stays at or under `targetTokens`; a paragraph above `targetTokens` splits into sentences (`(?<=[.!?。！？])\s+`) packed the same way; a sentence above `targetTokens` splits at token boundaries.
7. **Overlap.** Each chunk after the first in a section starts with the trailing whole sentences of the chunk before it that fit in `overlapPercent` % of `targetTokens` (one sentence cut to fit when even the last sentence is longer). Overlap never crosses a section boundary or a table, so a chunk holds at most `targetTokens` plus its overlap (640 tokens with the defaults).
8. **Tables.** A table of at most `tableMaxTokens` is one chunk on its own. A longer one splits between `<tr>` rows: the header rows are the `<thead>` rows, or else the leading rows whose cells are all `<th>`; each part is `<table>`, the `<caption>` when present, the header rows and as many body rows as fit within `tableMaxTokens`; a single row above `tableMaxTokens` is its own part, and a part above 8,000 tokens splits at token boundaries. Every parameter limit is at most 6,000 tokens, so no chunk exceeds the 8,000-token cap of the embedding input.
9. **The page rule, for both methods.** Every chunk of every format carries a `pageNumber` from 1 to the version's `page_count`: the page of the version's PDF where the chunk's own text starts, which for a DOCX or PPTX is a page of its converted PDF, the page its rendition shows. For this method, a chunk's start offset is the offset of the first block, sentence or table row the chunk adds, not of the text it repeats (the overlap sentences of item 7 and the header rows of item 8), because a citation points at the text the chunk adds; a section's first chunk starts at its heading. The page is the `pageNumber` of the span holding that offset. An offset in no span (between two pages, where the dropped page break and page header and footer markers sit, or after the last span) takes the nearest preceding page, the page of the span that starts closest before it; an offset before the first span takes the first span's page; a result with no spans gives page 1; a page above `page_count` becomes `page_count`. The page-wise method assigns pages per element (ADR 0047, item 4), so both methods give every citation a rendition to open.
10. **Failures.** `429` or `5xx` after the SDK's retries: retryable `docintel_throttled` or `docintel_unavailable`, carrying `Retry-After` to the orchestrator's backoff (ADR 0050); `400` for a corrupt or password-locked file: `corrupt_document` or `encrypted_document`; any other `400` and analysis status `failed`: `docintel_failed`, not retryable; the 40-minute poll deadline: retryable `docintel_timeout`. A document above `ingestion.max_pages_per_document` (default 2,000, the service's limit) fails with `page_limit_exceeded` before the call. No error is swallowed and no partial result is chunked: Chunk runs only on a complete `document.json`.
11. **Default method.** `adminGetIndexOptions` offers `recursive` version 1 as the default for new indexes, because bounded passages of about 512 tokens suit a prompt that keeps 8 sources, and the method runs on a GA service.

## Alternatives considered

- **Splitting the plain text with a character splitter.** Rejected: it ignores headings and tables, counts characters where the limits are tokens, and can't repeat a table's header rows.
- **Text output, with the structure reconstructed from the JSON result.** Rejected: the method is defined on Markdown output, which already carries headings and HTML tables in reading order; reconstructing them from paragraphs and table cells adds code the Markdown makes unnecessary.
- **Offsets in text elements (grapheme clusters) or UTF-16 code units.** Rejected: neither is a Python `str` index, so offsets drift after a combining mark or emoji (text elements) or after any character outside the Basic Multilingual Plane (UTF-16), and the page lookup would misplace chunks.
- **Pages from counting `<!-- PageBreak -->` markers.** Rejected: the spans in `pages[]` are exact, while markers sit between pages next to header and footer comments.
- **The page of the chunk's first character, overlap included.** Rejected: a chunk whose overlap sentences close page 3 and whose own text opens page 4 would cite page 3, where the new text isn't.
- **A null page for a chunk that starts between spans.** Rejected: every citation must open a single-page rendition, and the text just before a page break belongs to the page that precedes it.
- **Converting table HTML to Markdown before splitting.** Rejected: Markdown tables can't hold merged cells or multi-row headers.
- **Sending the DOCX or PPTX file itself to the layout service.** Rejected (ADR 0152): a DOCX "page" in this API is a 3,000-character unit that matches no page a reader sees, and a second reading of the Office file beside the converter would need its pages mapped onto the converted PDF's pages that the renditions show.

## Consequences

- Passages of about 512 tokens plus up to 128 of overlap fit the prompt's 8 kept sources; that bounded size and the GA service make this the default method.
- Cost and throughput: Document Intelligence bills the pages of the PDF it analyses, the converted PDF for a DOCX or PPTX; each item records `docintel_pages`, and `docchat.ingestion.docintel.pages` feeds the budget workbook. S0's 15 analyze transactions per second bound parallel ingestion, so raising `ingestion.max_parallel_items` follows the quota check in the runbook.
- A DOCX or PPTX is analysed as its converted PDF, whose text layer carries the Office file's text; the method adds no OCR pass of its own. A slide's chunks cite the slide's page, and headings come from what the layout model marks on the converted pages.
- The recorded layout results for the test fixtures are captured with `stringIndexType=unicodeCodePoint`; a recording made with another index type would shift every expected page, so a regeneration is reviewed against the expectation files.
- Tests: on the four recorded results, heading-first splits, chunks of at most 512 tokens plus overlap, 25% overlap inside sections only, `pageNumber` the start page for every format and the expected chunk counts; a table under 1,600 tokens kept whole and a longer one split between rows with the header rows in every part; on a synthetic result, a chunk starting between two spans gets the earlier page, one before the first span gets the first span's page, a chunk whose overlap sits on page 3 and whose own text starts on page 4 gets 4, and a page above the count becomes the count; the analyze call passes `string_index_type=StringIndexType.UNICODE_CODE_POINT`.
