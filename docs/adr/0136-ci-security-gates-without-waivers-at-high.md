# ADR 0136: CI security gates without waivers at high

- **Status:** Accepted
- **Date:** 2026-10-21; amended 2026-11-07 (ADR 0154's exception for HIGH or CRITICAL OS-package findings without a fix, the product owner's second decision under item 9)
- **Decided by:** Architect
- **Specified in:** 84-testing.md, 82-security.md, 01-repository.md, 83-infrastructure.md, 86-operations.md
- **Related ADRs:** 0010, 0011, 0097, 0118, 0124, 0127, 0129, 0141, 0142, 0153, 0154

## Context

The product's quality bar is unconditional: a high or critical scanner finding fails the build. CI scans with CodeQL, pip-audit, npm audit, secret scanning and container image scanning, pre-commit scans for secrets, Dependabot proposes updates, and base images are pinned by digest. A finding with no patched version, such as a CVE in a Debian package of a pinned base image, can't be removed inside this repository; the product accepts that such a finding blocks releases rather than adding an exception path for it, and the cost of that choice is recorded below.

An open-source template must never carry a credential: not in source, not in a committed archive or build output (which hold keys and source maps that a text scanner never reads), and not in an image layer (which can hold a credential file that no source scan sees). Dependencies must be declared, used and pinned, and nothing may install at deploy time.

Vendor facts: pip-audit reports vulnerability IDs without severities and exits 1 when it finds any; an OSV record of a GitHub advisory carries `database_specific.severity` (`LOW`, `MODERATE`, `HIGH`, `CRITICAL`), while a PyPA `PYSEC-` record carries none and lists its `GHSA-` record in `aliases`. npm audit's JSON report lists every advisory with its severity whatever `--audit-level` says. Trivy filters by `--severity` and can hide unfixed vulnerabilities with `--ignore-unfixed`. zizmor rates findings informational, low, medium or high, and `--no-exit-codes` stops findings from setting the exit code. GitHub's code-scanning merge protection blocks a pull request on "Security alerts: High or higher" and "Alerts: Errors"; a code-scanning alert carries `rule.security_severity_level`, and a dismissal takes one of the reasons `false positive`, `won't fix`, `used in tests` or `mitigated`. gitleaks 8.25 and later configures allowlists as `[[allowlists]]`.

## Decision

1. **The rule.** Every finding at high or critical severity fails the build, whether or not anything names it as an exception: no waiver, label, setting, approver or break-glass file turns it off. Waivers exist only for findings below that threshold. The product owner's decisions under item 9 are two exceptions, each admitted by the gate's code alone, recorded in `.github/security/exceptions.yaml` and failing the build again after its review date: ADR 0153's, Trivy's Dockerfile check DS002 on the ingestion image; and ADR 0154's (2026-11-07), a HIGH or CRITICAL vulnerability of an OS package in an image's own Trivy report for which the report names no fix, at most 90 days at a time.
2. **Scanners and thresholds.**

   | Scanner | Runs | Fails the build, never waivable | Fails unless waived |
   |---|---|---|---|
   | CodeQL, `security-extended`; Python, JavaScript/TypeScript, Actions | `codeql.yaml` on pull requests, pushes to `main` and Mondays at 03:00 UTC | merge protection: any open alert of security severity High or Critical, and any alert of severity Error | none (lower alerts don't block) |
   | pip-audit 2.10.1 | `uv export --locked --all-packages --all-groups --no-emit-workspace --format requirements-txt -o build/audit/requirements.txt`; `uv run pip-audit --strict --disable-pip --require-hashes -r build/audit/requirements.txt --vulnerability-service osv --format json -o build/audit/pip-audit.json \|\| test $? -eq 1` | any finding rated `HIGH` or `CRITICAL`, and any unrated finding | findings rated `LOW` or `MODERATE` |
   | npm audit | `npm audit --json > build/audit/npm-<dir>.json \|\| test $? -eq 1` in `apps/web`, `tests/e2e` and `scripts/deploy/swa-cli` (no `--audit-level`) | `high` or `critical` advisories | `low` or `moderate` advisories |
   | Trivy 0.76.0 | `docker save` each image, then `trivy image --input <tar> --scanners vuln,secret --severity HIGH,CRITICAL --format json --exit-code 0 --output build/audit/trivy-<image>.json`; `trivy config --severity HIGH,CRITICAL` on the three Dockerfiles | any HIGH or CRITICAL vulnerability, unfixed included; any secret in any layer; any HIGH or CRITICAL Dockerfile misconfiguration | none |
   | gitleaks 8.30.1 | pre-commit on staged changes; pull requests `gitleaks git --redact --log-opts="<base>..<head>"`; nightly over the full history | any finding | none |
   | zizmor 1.30.1 | `uv run zizmor --format json --min-severity medium --no-exit-codes .github/workflows > build/audit/zizmor.json` | `high` findings | `medium` findings |
   | deptry 0.25.1 | per workspace member, `uv run deptry <member path> --json-output build/audit/deptry-<member>.json \|\| test $? -eq 1`, no `[tool.deptry]` ignores | none | any unused, missing or transitive-only dependency |

3. **Severity of a pip-audit finding.** The gate fetches each reported ID's record from the OSV API (`GET https://api.osv.dev/v1/vulns/<id>`, `urllib.request.urlopen`, 15-second timeout, 3 attempts 15 s apart) and, when that record has no `database_specific.severity`, the record of each `GHSA-` ID in its `aliases`; the rating is the highest severity found. A finding that no record rates, or whose records can't be fetched, is unrated and fails the build like `HIGH`.
4. **One gate, `scripts/ci/security_gate.py`.** It loads `.github/security/approvers.yaml`, `.github/security/waivers.yaml` and `.github/security/exceptions.yaml` (ADR 0153) and fails on any invalid waiver or exception; loads every expected report from `build/audit/` and fails when one is missing or isn't a valid report of its scanner (npm: `auditReportVersion` 2 and a `vulnerabilities` object, so an `error` object from a failed run fails; pip-audit: a `dependencies` array; Trivy: `SchemaVersion` and `Results`; zizmor and deptry: a JSON array); splits the findings into never-waivable and waivable; treats a waivable finding as waived when a valid waiver has the same `scanner` and `id` and its `scope` glob matches the finding's package or path; lists a waiver that names a never-waivable finding as "not applicable: high and critical findings can't be waived", which changes nothing; writes the findings, the waivers and the waivers expiring within 14 days to the job summary; exits 1 on any never-waivable finding that the exceptions of ADR 0153 and ADR 0154 don't cover, unwaived waivable finding, invalid report, or invalid waiver or exception. It runs in `ci.yaml`'s required jobs `security` (pip-audit, npm audit, zizmor, deptry) and `images` (Trivy) on every pull request, and in the deploy workflow's `build` job on the Trivy output before anything is pushed, so no image with a high or critical finding is pushed or deployed. npm audit runs only in the gated `security` job.
5. **Waivers below high.** Fields: `id` (GHSA, PYSEC or OSV ID, npm advisory ID, zizmor rule ID or deptry rule code), `scanner` (`pip-audit`, `npm-audit`, `zizmor` or `deptry`), `scope` (package or path glob), `reason` (at least 20 characters), `ticket` (URL), `added`, `expires` (at most `added` + 90 days, and not in the past) and `approved_by` (a handle listed in `approvers.yaml`). `approvers.yaml` holds `approvers: [GitHub handle]`, the members of `docchat-security`, kept equal to the team by runbook R16, because a workflow token can't read organisation team membership; CODEOWNERS routes `/.github/security/` to `docchat-security`, so only that team can add a waiver or an approver.
6. **CodeQL dismissals.** A High or Critical alert may be dismissed only with the reason `false positive`, by a handle in `approvers.yaml`: the dismissal records that the alert isn't a vulnerability, and a real finding has no dismissal path. `nightly.yaml` job `codeql-dismissals` (`scripts/ci/check_codeql_dismissals.py`, `permissions {contents: read, security-events: read, issues: write}`) lists every dismissed alert (`GET /repos/{owner}/{repo}/code-scanning/alerts?state=dismissed&per_page=100`, all pages) and fails when an alert whose `rule.security_severity_level` is `high` or `critical` has another reason (`won't fix`, `used in tests`, `mitigated`) or an unlisted `dismissed_by.login`; it creates or updates the issue `CodeQL dismissal outside policy: alert <number>`, and a `docchat-security` member reopens the alert (`PATCH /repos/{owner}/{repo}/code-scanning/alerts/<number>` with `state=open`) or confirms it by dismissing it again.
7. **Secrets and committed files.** gitleaks runs as a pre-commit hook (`gitleaks git --pre-commit --redact --staged --verbose`), on every pull request's commit range and nightly over the full history; `.gitleaks.toml` extends the default rules (`[extend] useDefault = true`) and its `[[allowlists]]` entry names exactly two published constants, the Azurite `devstoreaccount1` key and the Cosmos DB emulator key. Any finding means the credential is revoked at its issuer and removed from history (runbook R07). GitHub secret scanning and push protection are on (R16). `scripts/ci/check_forbidden_files.py` fails the `lint` job when any tracked path matches `*.zip`, `*.tar`, `*.tgz`, `*.gz`, `*.7z`, `*.rar`, `*.jar`, `*.whl`, `*.map`, `*.pfx`, `*.p12`, `**/dist/**`, `**/build/**`, `**/node_modules/**`, a final component exactly `.env`, `.azure/**` or `apps/web/config.local.json`, with no allowlist.
8. **Deployed images.** `nightly.yaml` job `trivy-rescan` rescans the digests deployed to `dev` and `prod`, read from what the deploy jobs record and never from a site (`dev`: the `release-manifest` artifact of the newest `deploy.yaml` run whose `deploy-dev` job succeeded; `prod`: the images tagged with the commit of the newest `deploy-prod-*` Git tag, resolved under the `dev` deploy identity's AcrPush), and opens or updates an issue for each finding; Dependabot proposes base-image and dependency updates weekly. Every image built here or run in Azure is scanned, the load generator's included; the compose emulator images used only by local tests are pinned by digest and kept current by Dependabot, and aren't gated.
9. **When a high or critical finding has no fix.** It blocks every merge and every release until the base image's digest moves (Dependabot, runbook R17), the package leaves the image's final stage or its use changes (the dependency that brings it is replaced or dropped). Runbook R17 step 6 tries these in order: merge the Dependabot base-image update that drops it; remove the package from the final stage when the app doesn't need it at run time; move to another pinned base image through a pull request; when none is possible, the product owner decides through a new ADR, because this design has no waiver at high or critical. ADR 0153 is that decision for Trivy's DS002 on the ingestion image, and ADR 0154 for OS-package vulnerabilities for which Debian has published no fix.

## Alternatives considered

- **Time-boxed waivers at high and critical.** Rejected: the quality bar says a high or critical finding fails the build, and a waiver path at that level becomes the normal way to ship.
- **A bounded break-glass exception:** an approver list, a manifest field and a gate rule letting one release through with an unfixed high or critical finding. Not adopted: the bar stays unconditional, and the blocking cost below is accepted instead.
- **Trivy with `--ignore-unfixed`.** Rejected: an unfixed vulnerability is still exploitable, and hiding it removes the pressure to move the base image or drop the package.
- **Unrated pip-audit findings treated as low.** Rejected: an advisory without a rating may be critical; the gate fails closed.
- **npm audit with `--audit-level=high`.** Rejected: its exit code would hide the lower advisories that need a waiver; the JSON report and one gate apply both rules in one place.
- **Each tool's own ignore mechanism** (`.trivyignore.yaml`, pip-audit `--ignore-vuln`, `[tool.deptry]` ignores). Rejected: none carries an approver, most carry no expiry, and they would scatter exceptions across files; one waivers file with expiry and approver is checked by one gate.
- **Dependabot alerts alone.** Rejected: alerts don't block a merge or a release.

## Consequences

- An unfixed HIGH or CRITICAL CVE in a pinned base image (the Debian `bookworm` layers of `python:3.13.16-slim-bookworm`, or the Functions Python base image) blocks every merge and every release, a security fix included, until the base image's digest moves, the package leaves the final image stage or its use changes. This is the accepted cost of the rule; runbook R17 step 6 is the procedure, and the product owner decides when it can't remove the finding. Since 2026-11-07 such a finding in an OS package passes under ADR 0154's exception for at most 90 days at a time, and fails again as soon as its report names a fix; an unfixed finding in a language package still blocks.
- No image with a high or critical finding or a secret in a layer is ever pushed, so nothing deployable carries one; a CVE published after deployment surfaces through the nightly rescan's issue and is cleared by the next release.
- Lower findings stay visible: each waiver expires within 90 days, and the gate lists waivers expiring within 14 days.
- Obligations: R16 keeps `approvers.yaml` equal to `docchat-security`; R07 handles any gitleaks finding; R17 runs the dependency, base-image and tool updates; release acceptance requires zero high or critical findings and zero unwaived lower findings.
- Risk: a `false positive` dismissal by a listed approver is a judgement that the nightly check can't verify; it checks the reason and the approver, and GitHub keeps the dismissal in the alert's history.
- Tests (84-testing.md): the gate fails a HIGH Trivy finding that `waivers.yaml` lists, passes a waived moderate npm finding, and fails expired, over-90-day, short-reason and unlisted-approver waivers; the dismissal check fails a High alert dismissed as `won't fix` or by an unlisted handle and passes a listed approver's `false positive`; the gate rates a `PYSEC-` finding through its `GHSA-` alias, fails an unrated finding even when a waiver names it, and fails an `error` npm report and a missing report.
