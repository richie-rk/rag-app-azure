# ADR 0146: Office files that load external content

> Superseded by [ADR 0152](0152-office-sources-converted-to-pdf-originals-never-served.md): DOCX and PPTX sources are converted to PDF and readers receive only PDF renditions, so none of the rules below is part of the design.

- **Status:** Superseded by 0152
- **Date:** 2026-10-21
- **Decided by:** Architect
- **Specified in:** 14-ingestion.md, 12-chat-pipeline.md, 80-data-model.md, 82-security.md, 84-testing.md, 86-operations.md, 90-build-order.md
- **Related ADRs:** 0034, 0043, 0047, 0048, 0049, 0069, 0087, 0141, 0144, 0145

## Context

- The product owner chose to show a DOCX or PPTX citation as its details with a download action for the uploaded file, and to leave Office-to-PDF previews out of scope for the first version. The API serves that citation's stored source, `documents/{indexId}/{documentId}/{version}/source`, byte for byte (ADR 0069), while every PDF citation is served from a single-page rendition that keeps only passive content (ADR 0145). A stored Office file is therefore the one file a chat user opens outside the browser: in Word or PowerPoint, on their own device, on their own network.
- Uploads are admins only; PDF, DOCX and PPTX are checked by extension and signature; parsing caps a ZIP container's entries and uncompressed size and refuses encrypted files and files whose content types declare macros (ADR 0043). Documents are written by other people, so their content is untrusted, and nothing in a stored file may make a reader's software send data elsewhere. An Office file can still pull content in from another location when it opens, so this check closes that path.
- Office Open XML facts. A package relationship's `TargetMode` is `Internal` (a part inside the package) or `External` (a resource outside it, named by a relative or absolute URI), so a DOCX or PPTX can point at remote templates, remote images, linked objects and frames, or UNC paths that Office resolves when the file opens or its links update. Word fields such as `INCLUDETEXT`, `INCLUDEPICTURE` and `LINK` insert text, pictures and objects from other files; `DDE` and `DDEAUTO` link to other applications; `IMPORT` inserts a picture from a file. Embedded OLE objects (part content type `application/vnd.openxmlformats-officedocument.oleObject`, Packager objects included) carry other files and programs inside the document. An `oleObject` relationship can also reach an embedded binary Office 97–2003 file stored under its own content type, such as `word/embeddings/*.xls` (`application/vnd.ms-excel`), `*.doc` (`application/msword`) or `*.ppt` (`application/vnd.ms-powerpoint`), each able to carry VBA or XLM macros; ActiveX controls live in `*/activeX/` parts (content types containing `activeX`, with binary `.bin` parts) reached by `control`, `activeXControl` and `activeXControlBinary` relationships. An embedded Office Open XML package (a relationship type ending in `/package`, which charts use for their data) is a complete package of its own, with its own relationships, content types and fields. In Word a hyperlink opens on Ctrl+click by default. In a PowerPoint slide show a text hyperlink opens on a click on its text, a shape's click action opens on a click anywhere on the shape, which can cover the slide, and a hover action (`hlinkHover`, `hlinkMouseOver`) opens when the pointer rests on its shape or text, with no click.
- Further Office Open XML facts (ECMA-376, checked 2026-10-25). Part names compare as case-insensitive ASCII strings, and media types are case-insensitive, so `VBAPROJECT.BIN` names the same part as `vbaProject.bin` and two ZIP entries can name one part. An `aFChunk` relationship, placed by a `w:altChunk` element, imports another document (RTF, HTML, MHT or another package) that Word converts as it opens the file. A workbook's XLM macro sheets, `externalLink` parts, data connections (`connections.xml`), query tables and `ddeLink` elements run macros or fetch data without any external relationship. [MS-OI29500] Part 1 section 21.1.2.3.5 (page updated 2026-08-18, checked 2026-10-25) reserves PowerPoint's action values: `ppaction://program` runs an application, `ppaction://macro?name=` a macro and `ppaction://ole?verb=` an OLE verb, `ppaction://hlinkfile` opens a file and `ppaction://hlinkpres?slideindex=` a presentation outside the package, while `ppaction://hlinksldjump`, `ppaction://hlinkshowjump?jump=`, `ppaction://customshow?id=`, `ppaction://noaction` and `ppaction://media` stay inside the presentation. Field codes `DATABASE` and `RD` read other files, and fields can sit in any XML part, headers, footers and notes included. A binary embedding starts with the compound-file signature `D0 CF 11 E0 A1 B1 1A E1` whatever content type the package declares for it.
- Field, object and add-in facts (ECMA-376 Part 1, [MS-OWEXML], checked 2026-10-25). A `HYPERLINK` field names its target inside its own instruction, so a UNC or `file:` target needs no relationship. A tracked deletion keeps a field's code in `delInstrText`, which becomes a live field again when the reader rejects the deletion, and a field inside tracked-change markup (`w:ins`, `w:del`, `w:moveFrom`, `w:moveTo`) reads as one instruction with the changes accepted and as another with them rejected. Word reads field markup only in the WordprocessingML main namespaces, and reads `\"` inside a field argument as an escaped quote. Markup Compatibility (ECMA-376 Part 3) lets a reader take one branch of an `mc:AlternateContent` and ignore the others, so a field whose parts sit in two branches has no reading in either. A field's type is the instruction's leading word, and nothing in the format requires a space between it and a quoted argument. A relationship without `TargetMode` is internal, and its `Target` is a URI reference that a reader resolves against the package. An OLE object element names, by its program identifier, the program Office starts for the embedded object. A web extension part names an Office add-in that Office loads when the file opens.
- Parser facts: `zipfile` opens a member as a read-only stream without extracting it, and its documentation warns that decompression bombs exhaust resources; `lxml` parser options `resolve_entities`, `no_network` and `huge_tree` control entity replacement, network lookups of external documents and the depth and size restrictions.
- Facts for the allowlists (ECMA-376 Parts 1, 2 and 4, [MS-DOC], [MS-DOCX], [MS-ODRAWXML], [MS-PPTX], [MS-OI29500], [MS-OE376], checked 2026-10-25). ECMA-376 defines, for every part it specifies, the part's content type and the relationship type that reaches it, in a Strict URI under `http://purl.oclc.org/ooxml/officeDocument/relationships/` and a Transitional URI under `http://schemas.openxmlformats.org/officeDocument/2006/relationships/`; [MS-ODRAWXML] and [MS-PPTX] define Office's chart-style, diagram-drawing, comment and revision parts the same way. [MS-DOCX] sections 2.1.2 to 2.1.5 define the four parts Word writes whenever a document has comments, commentsExtended, people, commentsIds and commentsExtensible, which hold comment metadata and the comment authors' contact information, without printing their relationship types or content types. The formats define more relationship types, content types and field types than a deny-list names, and Office adds extensions over time, so a deny-list refuses only what its authors knew of. [MS-DOC] lists Word's field types in its `flt` enumeration, and ECMA-376 Part 1 section 17.16.5 and Part 4 section 14.10.4 state what each computes; a field computed from the document itself, its properties or the date reads and writes nothing outside the file. ECMA-376 Part 1 Annex L.7.2 and [MS-OI29500] give the program identifiers of the three package types. [MS-ODRAWXML] section 2.26 defines `svgBlip`, an image in Scalable Vector Graphics form, embedded in an image part or linked by an external relationship, beside a PNG copy for applications that can't show it; it doesn't state how Office renders it, and SVG 1.1, the format ECMA-376 Part 1 section 15.2.4 names for `image/svg+xml`, defines script. [MS-ODRAWXML] section 2.19.1.1 defines `webVideoPr`, an online video in a Word document, whose own attributes carry the embedded HTML that Word renders for it, the video's web address included, with no relationship. ECMA-376 Part 1 section 17.16 lets a Word form field's `entryMacro` and `exitMacro` name a macro that runs when the reader enters or leaves the field, and leaves the macro's language and location to the application. ECMA-376 Part 4 sections 19.1.2.5, 19.1.2.10, 19.1.2.11, 19.1.2.19, 19.1.2.21 and 19.2.2.30 let the VML `fill`, `image`, `imagedata`, `shape`, `stroke` and `signatureline` elements, and the text-box stroke elements of section 19.2.2, name an image to load, the file an image was taken from, an alternate image, a shape's hyperlink target or a signature provider's download address by URL in their `src`, `o:href`, `o:althref`, `href` and `o:sigprovurl` attributes, which no relationship carries, while `o:oleicon` holds only a true or false value; Part 4 section 8.2 defines the VML Drawing Part with its Transitional relationship type and its content type, and Part 1 defines no Strict form of it. A ZIP archive (PKWARE APPNOTE 6.3.10) holds each entry's local file header beside the central directory that lists the entries, and ECMA-376 Part 2 Annex B allows compression methods 0 and 8 only; a reader that recovers parts from local headers can see an entry that the central directory doesn't name, so two readers can disagree about which parts a package holds.
- Metafile and formula facts (checked 2026-10-25). [MS-EMF] section 2.1.1, the `RecordType` enumeration (page updated 2024-10-30), defines `EMR_CREATECOLORSPACE` (0x00000063), `EMR_SETICMPROFILEA` (0x00000070), `EMR_SETICMPROFILEW` (0x00000071), `EMR_COLORMATCHTOTARGETW` (0x00000079) and `EMR_CREATECOLORSPACEW` (0x0000007A), each a record that specifies a colour profile held in a named file outside the picture; an EMF starts with `EMR_HEADER` (0x00000001) and ends with `EMR_EOF` (0x0000000E). [MS-WMF] section 2.1.1.1, the `RecordType` enumeration, and section 2.1.1.17, the `MetafileEscapes` enumeration, define no record that names a file to load (`STARTDOC` carries a print job's document name), but the escape `META_ESCAPE_ENHANCED_METAFILE` (0x000F) carries an EMF inside a WMF, in segments. [MS-XLSX] section 2.2.2 (revision 30.0 of 2026-10-16) defines the formula grammar: `RTD` and `HYPERLINK` in `function-call`, `WEBSERVICE` in `future-function-call` with the `_xlfn.` prefix, `CALL` in `ref-macro-function-call`, `REGISTER`, `REGISTER.ID` and `EXEC` in `macro-function-call`, and a string literal in double quotes with `""` for a quote; it has no `IMAGE` production. A DDE reference names its application and topic on either side of a `|`.

## Decision

1. **Where the check runs.** In the ingestion app's parsing child process, command `inspect` (120-second limit) of the `extract_document` activity, for every DOCX and PPTX version and every ingestion method, before any parse: the signature, the ZIP caps, entry encryption, duplicate entry names and readability (ADR 0043), the archive's layout (decision 10), the macro declarations, this external-content check, the embedded-content check (decision 6) with the allowlist rules last (decision 9), the embedded-package check (decision 7), then the page or slide count; `verify-office` then repeats every check in a second child (decision 8). The first failing check ends the item with its code. Part names, folder names, content types, relationship types and `TargetMode` values are compared case-insensitively (ASCII case folding), because Office Open XML part names and media types are case-insensitive, and two entries whose names are equal case-insensitively fail the item with `corrupt_document`. A part's content type is the one `14-ingestion.md` section 15.6 item 7 looks up: the `Override` for its part name in `[Content_Types].xml`, else the `Default` for its extension. XML elements and attributes are matched by local name in any namespace, so a file in the Strict form of Office Open XML meets the same rules as a Transitional one; field markup is read only in the two WordprocessingML main namespaces, rules `ext.vml` and `ext.reluse` match by namespace too, and every branch of an `mc:AlternateContent` is read as its own copy of the content. Every rule carries the stable label that `14-ingestion.md` section 15.6 item 7 gives it, and `office_rules.broken_rules` returns the labels of every rule a file breaks, so a fixture can be shown to break one rule alone. The API never opens the archive (ADR 0043).
2. **The rule.** The item fails with `external_content_declared` when any of these holds:
   - any `*.rels` part has an external `Relationship` (a `TargetMode` other than `Internal`, `External` included; an absent `TargetMode` means `Internal`) other than one whose `Type` ends in `/hyperlink` (`http://schemas.openxmlformats.org/officeDocument/2006/relationships/hyperlink`) and whose `Target` has the scheme (the characters before its first `:`, compared case-insensitively) `https`, `http` or `mailto`: remote templates, remote images, linked OLE objects and frames are refused, and so is a hyperlink to a `file:` URI, a UNC path (`\\host\share` or `//host/share`, which has no scheme), a drive-letter path, an `ms-` protocol handler, a `ppaction:` target or any other scheme;
   - any internal `Relationship` (no `TargetMode`, or `Internal`) has a `Target` that, after percent-decoding, holds a `:` in its first segment (the text before its first `/`, or all of it when it has no `/`: a scheme or a drive letter), starts with `//`, holds a `\` (a UNC or Windows path), or leaves the package root when resolved against its source part's folder with its `.` and `..` segments applied; a target inside the package that names no part loads nothing and stays allowed;
   - a part of content type `application/vnd.ms-office.webextension+xml` or `application/vnd.ms-office.webextensiontaskpanes+xml`, or a `Relationship` whose `Type` ends in `/webextension` or `/webextensiontaskpanes`: an Office add-in, which Office loads from a web address when the file opens;
   - a mail merge: a `mailMerge` element or an `odso` element in any XML part, whose connection string and query name a data source outside the file;
   - an online video: an element of local name `webVideoPr` in any namespace (rule `emb.webvideo`), whose own attributes carry the video's embedded HTML and web address, with no relationship for the allowlist to read;
   - a VML attribute that names a file or URL (rule `ext.vml`): in any XML part, a VML drawing part included, an element of namespace `urn:schemas-microsoft-com:vml`, `urn:schemas-microsoft-com:office:office`, `urn:schemas-microsoft-com:office:word` or `urn:schemas-microsoft-com:office:excel` with an attribute whose local name, compared case-insensitively, is `src`, `althref` or `sigprovurl`, or `href` on an image element (`v:fill`, `v:imagedata`, `v:stroke` and the text-box strokes), and whose value isn't empty, so an image or a signature provider named by URL is refused whatever its scheme; `href` on a shape, its hyperlink, in a WordprocessingML or SpreadsheetML package unless it is empty or its scheme is `https`, `http` or `mailto`, as for a hyperlink relationship, and in a presentation package whatever its value, because a click anywhere on the shape opens it in a slide show; or `oleicon` with a value other than `t`, `f`, `true`, `false` and the empty string. An attribute of the relationships namespaces (`r:id`, `r:href`, `r:pict`) and `o:relid` hold a relationship ID, which the relationship rules check, and this rule doesn't read them;
   - in any XML part of the file or of an embedded package, whatever its folder, a field instruction whose keyword isn't on the field-keyword allowlist (decision 9), or whose first character after the skipped characters is neither an ASCII letter, `=` (a formula) nor a nested field, other than an instruction made only of `\* MERGEFORMAT` switches; a field instruction that begins with a nested field, whose keyword is known only when Word evaluates the inner field; or a `HYPERLINK` field whose target isn't allowed. A simple field's instruction is its `fldSimple/@instr`. A complex field's instruction is the concatenation, in document order, of every `instrText` between its `fldChar` `begin` and its matching `separate`, or `end` when it has none, with nested fields tracked on a stack and each checked as a field of its own. The field elements are read only in the two WordprocessingML main namespaces, and one in any other namespace is refused (rule `field.namespace`); any `delInstrText`, and any instruction text, field marker or simple field inside tracked-change markup, is refused (rule `field.tracked`), so an instruction that passes reads the same with the changes accepted or rejected; and a field whose markers and instruction don't all share one nearest `mc:Choice` or `mc:Fallback` ancestor, or none, is refused (rule `field.branch`). The keyword is the longest run of ASCII letters after the skipped characters, which are those of Unicode categories Zs and Cf (Python 3.13 `unicodedata`, Unicode 15.1.0), tab, line feed, vertical tab, form feed, carriage return, U+0085, U+2028 and U+2029, compared case-insensitively, so `INCLUDEPICTURE"url"` gives `INCLUDEPICTURE` and a zero-width space inside a keyword cuts it short to a word that isn't on the list. A `HYPERLINK` field's targets are its arguments (each a quoted string, a nested field or the next white-space-delimited token) other than its switches (`\` and one letter) and the arguments of `\l`, `\o` and `\t`. It is allowed when it has no target and a `\l` switch, a jump to a bookmark in the same file, or when every target's scheme is `https`, `http` or `mailto`, compared case-insensitively; a target that is a nested field or holds one anywhere, between its quotes included, has no scheme, starts with `\\` or `//`, starts with a drive letter or has any other scheme is refused, nested `HYPERLINK` fields included, and a `HYPERLINK` instruction holding `\"` anywhere is refused, so its arguments have one reading. `14-ingestion.md` section 15.6 item 7, in its item 4, states these rules in full;
   - a hover action with an external target (rule `ext.hover`): an `hlinkHover` or `hlinkMouseOver` that names an external relationship, which PowerPoint follows when the pointer rests on the shape or text, with no click;
   - in a presentation package, a click action with an external target anywhere but on a text run (rule `ext.shapelink`): an `hlinkClick` that names an external relationship and whose parent isn't an `rPr` or `endParaRPr`, such as the one under a shape's `cNvPr`, which opens on a click anywhere on the shape;
   - an external relationship named by any element other than `w:hyperlink` and a DrawingML `hlinkClick`, `hlinkHover` or `hlinkMouseOver` (rule `ext.reluse`): the IDs of a part's external relationships may appear only there, so a picture, fill, sound or media file linked through a hyperlink-type relationship is refused;
   - an EMF record that names a colour-profile file (rule `emb.emfprofile`): in every `image/emf` part, and in the EMF that a WMF part's `META_ESCAPE_ENHANCED_METAFILE` records carry, the records are walked from `EMR_HEADER` to `EMR_EOF` at the part's end, and `EMR_CREATECOLORSPACE`, `EMR_SETICMPROFILEA`, `EMR_SETICMPROFILEW`, `EMR_COLORMATCHTOTARGETW` and `EMR_CREATECOLORSPACEW` are refused; a walk that fails is `corrupt_document`.
3. **How parts are read.** Each part, the parts of an embedded package included, is opened as a stream from the archive with `zipfile` (never extracted to disk) and parsed, in `inspect`, with `lxml.etree.iterparse(..., resolve_entities=False, no_network=True, huge_tree=False)`, and in `verify-office` with `xml.etree.ElementTree.iterparse` over the standard library's expat parser (decision 8), inside the ZIP caps (at most 10,000 entries; declared uncompressed sizes summing to at most 536,870,912 bytes; no entry over 10 MiB with a ratio above 200 to 1) and the child's memory and wall-clock limits (ADR 0049).
4. **What stays allowed.** External relationships of the `hyperlink` type whose target's scheme is `https`, `http` or `mailto`, named by a Word hyperlink (`w:hyperlink`, which Word opens on Ctrl+click by default) or by a click action the rules allow (a text-run hyperlink in a presentation, which opens on a click on its text in a slide show), which hand a web or mail address to the reader's browser or mail program and run nothing inside Office; `HYPERLINK` fields whose targets have those schemes, and `HYPERLINK` fields that only jump to a bookmark (`\l`); every internal relationship whose target resolves inside the package and isn't refused by decision 6; embedded media held as parts of the package, and embedded Office Open XML packages that pass decision 7, such as a chart's workbook.
5. **The outcome.** `external_content_declared` and `embedded_content_declared` are non-retryable. The run item ends at stage `extract` with the safe text "Files that load content from other locations aren't accepted." or "Files that contain embedded programs or controls aren't accepted."; the version is never indexed, rendered or served; the Ingestion runs screen shows it as the item's problem and the Documents screen as the version's `failureCode`. Re-ingesting the same bytes fails the same way; the admin removes the link, field, object or control in Office and uploads the cleaned file, which is a new version because its SHA-256 differs.
6. **The embedded-content rule.** The item fails with `embedded_content_declared` when a DOCX or PPTX, or one of its embedded packages, holds any of these:
   - any `Relationship` whose `Type` ends in `/oleObject`, `/control`, `/activeXControl`, `/activeXControlBinary` or `/aFChunk` (an imported chunk), or a `w:altChunk` element in any part under `word/` (an RTF, HTML or MHT chunk that Word converts when the file opens);
   - any part whose content type (the lookup of decision 1) contains `activeX` or equals `application/vnd.ms-excel`, `application/msword`, `application/vnd.ms-powerpoint` or `application/vnd.openxmlformats-officedocument.oleObject`;
   - any part under a folder named `activeX` (`*/activeX/*`);
   - any part under a folder named `embeddings` (`*/embeddings/*`) whose content type is neither one of the Office Open XML package types `application/vnd.openxmlformats-officedocument.wordprocessingml.document`, `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` or `application/vnd.openxmlformats-officedocument.presentationml.presentation` nor one of their macro-enabled forms, which the macro rule refuses (decision 7);
   - any archive entry whose first 8 bytes are the compound-file (OLE2) signature `D0 CF 11 E0 A1 B1 1A E1`, whatever its name or content type;
   - an XLM macro sheet (content type `application/vnd.ms-excel.macrosheet+xml` or `application/vnd.ms-excel.intlmacrosheet+xml`), an `externalLink` part, a `connections.xml` part, a `queryTable` part (each by content type or name) or any `ddeLink` element; in a DOCX or PPTX only an embedded workbook holds these, and it runs macros or fetches data through them without any external relationship;
   - a formula of an embedded workbook (cell, conditional-formatting, data-validation and table formulas and defined names) that names `RTD`, `WEBSERVICE`, `IMAGE`, `CALL`, `REGISTER`, `REGISTER.ID`, `EXEC` or `HYPERLINK` outside its string literals, after any `_xlfn.`, `_xlws.` and `_xludf.` prefixes, or holds a `|` outside them (rule `emb.formula`): these fetch data, open a link or run code, and the `|` makes a DDE reference;
   - an `hlinkClick`, `hlinkHover` or `hlinkMouseOver` in any DrawingML namespace whose `action` is present, isn't empty and isn't on the PowerPoint-action allowlist (decision 9, rule `emb.ppaction`): only the jumps within the presentation, the custom shows `ppaction://customshow?id=<digits>` with or without `&return=true`, `ppaction://noaction` and `ppaction://media` pass, compared case-insensitively, so `ppaction://program`, `macro`, `ole`, `hlinkfile` and `hlinkpres` are refused;
   - a `Relationship` whose `Type` ends in `/package` and whose target's content type is neither one of the three package types above nor one of their macro-enabled forms (decision 7);
   - a program identifier off the program-identifier allowlist (decision 9: `Word.Document.12`, `Excel.Sheet.12` and `PowerPoint.Show.12`, the program identifiers of the three package types, compared case-insensitively): an element of any namespace, Strict included, with an attribute whose local name is `progId` in any letter case and whose value is off the list; an OLE object element (`o:OLEObject` in VML, `w:objectEmbed` in WordprocessingML, `p:oleObj` in PresentationML, `oleObject` in SpreadsheetML) without such an attribute; any `w:objectLink`, which links a file outside the package; a `w:objectEmbed` whose relationship isn't a `/package` relationship; or an `EMBED` field whose class, its first argument, is absent, is or holds a nested field, or is off the list, or whose instruction holds `\"`, Word's escaped quote. The element names the program Office starts when the reader opens the object, so a package that passed decision 7 is never handed to another program: `Package` (the Packager), a macro-enabled form, `PowerPoint.Slide.12` (a slide package, which decision 7 doesn't open) and every other value are refused;
   - a Word form field that runs a macro: a `w:ffData` element with an `entryMacro` or `exitMacro` child (rule `macro.formfield`), which names a macro that Word runs, wherever it finds a macro of that name, when the reader enters or leaves the field, and, under the same rule, a VML form control's non-empty `x:FmlaMacro`, `x:ScriptText` or `x:ScriptExtended` (ECMA-376 Part 4 section 19.4), which names the macro or script Excel runs when the reader uses the control. A VML shape's `o:gfxdata` attribute holds a package of its own in base64; it is decoded, counted toward the archive caps and checked as one more embedded package, and a value that doesn't decode to a ZIP archive is `corrupt_document`. Only the outer file's `gfxdata` values are decoded: a non-empty `gfxdata` inside an embedded package or inside a decoded `gfxdata` package is refused under rule `emb.nested`, so the checks never go deeper than one level;
   - a relationship type or a content type off its allowlist (decision 9), and any `svgBlip` element.
7. **Embedded packages.** A part reached by a relationship whose `Type` ends in `/package`, or a part under `*/embeddings/*`, is opened as an embedded package only when its content type is one of the three package types of decision 6. It is opened from its archive entry in memory, within the outer file's ZIP caps and the child's memory limit, and checked with the same rules: its own ZIP caps, encryption flags, duplicate names and readability (ADR 0043), macro content types (ADR 0043), external relationships and field instructions (decision 2), the refusals of decision 6, its own `*.rels` parts and `[Content_Types].xml` against the allowlists (decision 9) and its layout (decision 10). Each failure gives the code the outer file would get. The macro-enabled forms of the package types (`application/vnd.ms-word.document.macroEnabled.12`, `application/vnd.ms-excel.sheet.macroEnabled.12`, `application/vnd.ms-powerpoint.presentation.macroEnabled.12`) are refused as macro content with `macro_content_declared`, and any other content type behind a `/package` relationship with `embedded_content_declared`. A package nested inside an embedded package is refused with `embedded_content_declared`, so the check reads one level of embedding and no more.
8. **A second check by another parser.** After `inspect` returns `ok`, `verify-office`, a fresh child under another parse user (ADR 0049 decision 17), repeats every check of decisions 1, 2, 6, 7, 9 and 10 and the slide count over the same bytes with the Python standard library only: `zipfile`, `xml.etree.ElementTree.iterparse` over the standard library's expat parser, which expands no external entity, with `lxml` made unimportable, and, for the archive's layout, its own reader of the archive's records, `docchat_ingestion.isolation.zip_records`, built on `struct` and importing no `zipfile`. The rule logic is one module, `docchat_ingestion.isolation.office_rules`, that both commands run, so only the XML parser and the layout reader differ. The version proceeds only when both children return `ok` with the same page count; any disagreement fails the item with `parse_failed` and logs `inspect_disagreement`. Serving a construct that a rule refuses therefore takes one of two things. Either one successful exploit against a C component that both children run on the same bytes, which needs no second exploit because the same bytes reach both: CPython's `zlib` (inflate, through `zipfile`) and `binascii` (base64, through `base64.b64decode` for `gfxdata`). These are the only two: the rule module reads every other structure of the file, the metafile records included, in Python with `int.from_bytes` and `struct`, and imports no other C extension module to read it. Or two independent exploits, one against libxml2 through `lxml` in `inspect` and one against expat in `verify-office`.
9. **Allow, then deny.** The Office checks allow rather than deny. Five allowlists held as constants in `office_rules`, whose entries `14-ingestion.md` section 15.11 names exactly, each confirmed against the specification named beside it with its date: `ALLOWED_RELATIONSHIP_TYPES` (106 URIs: the Strict and Transitional relationship types ECMA-376 defines for document structure, properties, custom XML, thumbnails, images, fonts, charts, diagrams, presentation parts, the parts of an embedded workbook, `hyperlink` and `package`, the Transitional `vmlDrawing` type, the chart-style, diagram-drawing, comment and revision types of [MS-ODRAWXML] and [MS-PPTX], and the types of the four Word comment-metadata parts of [MS-DOCX], whose URIs are the values Word writes, which [MS-DOCX] doesn't print and the Office-saved Word controls prove), `ALLOWED_CONTENT_TYPES` (71: the content types of those parts, the three package types, `image/png`, `image/jpeg`, `image/gif`, `image/tiff`, `image/emf` and `image/wmf`, `application/xml` and the relationships type), `ALLOWED_FIELD_KEYWORDS` (51 keywords whose result Word computes from the document itself, its properties or the date, with `HYPERLINK` and `EMBED` under their own rules), `ALLOWED_PROGIDS` (3) and `ALLOWED_PPACTIONS` (9 values and one custom-show pattern: the actions [MS-OI29500] Part 1 section 21.1.2.3.5 defines as moving within the presentation or doing nothing outside it). Every relationship type in every `*.rels` part, every `Default` and `Override` content type, every field keyword, every program identifier and every PowerPoint action, in the file and in each embedded package, must be on its list, and anything not on it is refused: `rel.type` and `ct.type` with `embedded_content_declared`, `field.keyword` with `external_content_declared`, `emb.progid` and `emb.ppaction` with `embedded_content_declared`. An entry joins a list only when a specification of that list defines it and describes no loading of external content and no running of code for its construct; an entry no specification confirms stays off, so a missing entry refuses a harmless file, which the admin sees as an item failure under the rule's label, and never serves a file that loads or runs something. SVG is refused, `image/svg+xml` and every `svgBlip` element: no specification of the list states that Office renders an SVG image without running its script, and SVG 1.1 defines script. VML drawing parts are allowed, because rule `ext.vml` (decision 2) refuses every VML attribute that names a file or URL, which no relationship carries, and the part's own relationships meet every relationship rule; only the Transitional `vmlDrawing` type is on the list, because ECMA-376 defines the VML Drawing Part in Part 4 section 8.2 alone and no specification of the list defines a Strict form of it. A passing control refused under `rel.type` or `ct.type` is stop condition SC-10 (ADR 0141): when the specification that defines the part names the relationship type and content type the control needs, the entry is added through `14-ingestion.md` section 15.11 and this record with that reference, and the build continues; when no vendor specification names it, the product owner chooses between refusing files that carry that part and allowing the entry on the evidence of the Office-saved file. An Office-saved passing control refused under a deny rule stops stage 1 in the same way, and the product owner chooses between refusing files that carry that construct and narrowing the rule on specification text that says the construct loads no external content and runs no code. The deny rules of decisions 2 and 6 stay beside the lists: they give precise labels and codes, and they refuse constructs inside allowed parts, such as `w:altChunk`, `ddeLink`, `webVideoPr`, a VML attribute that names a file or URL, a form field's entry or exit macro, a field inside tracked-change markup, a hover action with an external target, an EMF colour-profile record and a workbook formula that fetches or runs something; a construct that breaks both comes first under its deny rule, so its code is the one reported.10. **The archive's layout.** The archive's records must tile the file (rule `zip.layout`, `corrupt_document`): the first local header at offset 0; each entry's local header, name, extra field, compressed data and data descriptor ending where the next entry's local header begins; after the last entry the central directory, an optional ZIP64 end record and locator, and the end record, with no byte after its comment; each local header agreeing with its central-directory entry in name, method, checksum (CRC) and sizes; and no local-header signature followed by method 0 or 8 at an offset the central directory doesn't name, except inside the stored data of an embedded package, whose own layout this rule checks. Every byte of a passing archive belongs to an entry that the other rules read, so no part hides from them for a reader that recovers parts from local headers. In `verify-office` the rule also breaks when `zip_records` and `zipfile` list different entries.
11. **Re-inspection when the rules change.** `office_rules.RULES_VERSION`, an integer imported from `docchat_core.ingestion.models.OFFICE_RULES_VERSION` and raised by 1 in the pull request that changes any rule of `14-ingestion.md` section 15.6 item 7 or any list of its section 15.11 (a unit test holds the SHA-256 values of `office_rules.py` and `zip_records.py` beside it, so a change without a raised constant fails CI), names the rules a check ran under. Every DOCX and PPTX version records in `document_versions.office_rules_version` (`INT NULL`, written only by `docchat_ingestion`, `NULL` on insert) the value under which both children last passed it; Extract sets it on a pass. The API streams an Office source file only while that column equals the deployed constant, and otherwise answers `409 document_rechecking` (ADR 0069). Sweep duty 12 of the ingestion app queues one `reinspect` item per ingested DOCX and PPTX version whose column differs, at most 10 queued or running at once, in one `maintenance` run per logical index, so the first sweep after a deploy that raised the constant starts the work. The item runs `inspect` and `verify-office` over the stored source file: a pass sets the column; a refusal records the item's code, sets `document_versions.office_rules_refused_version` so the sweep doesn't queue the version again under that constant, writes the audit row `document.reinspection_refused` and leaves the column, so the source file stays unserved while its chunks stay searchable. `docchat-ops ingestion list-refused` lists the refused versions, and the admin uploads a corrected file as a new version or deletes the document.

## Alternatives considered

- **Strip the external parts and keep the file.** Rejected: the stored bytes would differ from what the admin uploaded, which breaks a version's identity by the SHA-256 of its bytes (ADR 0034) and the update flow built on it, and a reliable Office Open XML sanitiser is a large component of its own; Office already lets the admin remove a link or object.
- **Accept the file and warn at download.** Rejected: a reader can't judge the risk of a remote template or a UNC path, and Office resolves those as the file opens, before a warning helps.
- **Rely on Office's own protections on the reader's device.** Rejected: they depend on each reader's Office version and settings, which the platform doesn't control.
- **Render Office files to PDF so the stored file never reaches users.** Rejected: Office-to-PDF previews are out of scope for the first version, and the product owner chose details with a download action.
- **Refuse every external relationship, hyperlinks included.** Rejected: ordinary documents carry web links. A Word hyperlink opens on Ctrl+click by default and a presentation's text hyperlink on a click on its text in a slide show, so the reader chooses to follow one; the links that open without that choice, a hover action with an external target and a presentation's shape-level click action with an external target, are refused (decision 2), and so is a VML shape's `href` in a presentation.
- **Deny-lists only: refuse the relationship types, content types, field keywords and program identifiers known to load or run something, and allow the rest.** Rejected: the formats define more constructs than a list of known dangers names, among them an `INCLUDE` keyword, a mail merge, a Strict `w:objectEmbed` and a `hlinkMouseOver` action, and Office keeps adding extensions, so a deny-list keeps missing constructs. A missed entry in a deny-list serves a file that loads or runs something; a missed entry in an allowlist refuses a harmless file under a rule label the admin sees (decision 9).
- **Allow SVG images, as Office writes them for inserted icons.** Rejected: no specification of the allowlists confirms that Office renders an `svgBlip` image without running script, SVG 1.1 defines script, and an `svgBlip` can link its image from outside the package; the admin replaces the graphic with a PNG picture.
- **Check only `[Content_Types].xml`.** Rejected: external relationships and Word fields aren't content types, and an `oleObject` relationship can reach a binary Office 97–2003 part declared under its own content type.
- **Refuse every embedded package.** Rejected: charts keep their data as an embedded workbook, so ordinary decks and reports would be refused; one level of embedded packages checked under the same rules keeps them while refusing what Office would run or fetch.
- **One child and one XML parser for the checks.** Rejected: a flaw in `lxml` or libxml2 that runs code in `inspect` could then write `ok` for any file; a second child under another UID, with the standard library's expat parser, makes a pass of a refused construct take either two independent exploits, one against libxml2 and one against expat, or one exploit against `zlib` or `binascii`, the only two C components both children run on the file's bytes (decision 8).
- **Inspect embedded packages to any depth.** Rejected: every level multiplies the work inside the 120-second `inspect` limit, and a package nested in an embedded package has no ordinary use that justifies it.
- **Run the check in the API before commit.** Rejected: document parsing runs only in the ingestion app, and the ZIP central directory sits at the end of the archive (ADR 0043).

## Consequences

- A stored DOCX or PPTX that a reader downloads can't fetch remote content, resolve a UNC path through a relationship or a `HYPERLINK` field, load an Office add-in or an online video's embedded HTML, load an image or a signature provider that a VML attribute names by URL, run a field that pulls in other files, hand an embedded package to a program other than Word, Excel or PowerPoint, or carry an embedded program: every OLE object, ActiveX control, binary Office 97–2003 embedding, compound-file part, imported chunk, XLM macro sheet, workbook data connection or DDE link, workbook formula that fetches data, opens a link or runs code, PowerPoint action other than a move within the presentation, hover action or presentation shape-level link with an external target, EMF colour-profile record and form-field entry or exit macro is refused, and the one kind of embedding kept, an Office Open XML package one level deep, passes the same macro, external-content, embedded-content, allowlist and layout rules as the file itself. Every relationship type, content type, field keyword, program identifier and PowerPoint action a served file holds is on an allowlist of decision 9. What remains is what the admin can see in the file, and element-level constructs inside allowed parts that no rule of decisions 2 and 6 names.
- Some ordinary business files are refused: a DOCX attached to a template on a network share carries an external `attachedTemplate` relationship, a deck with a linked chart carries an external link, and a report with an embedded binary `.xls` object or a form control carries an embedding. So are a document with an Office add-in, an online video or a form field that runs a macro on entry or exit, a `HYPERLINK` field to a file share, a VML picture that keeps the address of the file its image was taken from, a hyperlink on a VML shape to a file or to a scheme other than `https`, `http` or `mailto`, and an embedded Excel chart object, whose program identifier `Excel.Chart.12` isn't one of the three allowed. The allowlists refuse more: a file with an SVG graphic or icon, a file with printer settings, a Strict file with a VML drawing part (whose Strict relationship type no specification of the list defines; an Office-saved control that carries one is stop condition SC-10), audio or video, a mail-merge main document, a field the list doesn't name (`FILENAME`, `DOCPROPERTY`, `GOTOBUTTON`, `MACROBUTTON` and a bookmark reference written without `REF` among them), and any part of an Office extension that the lists don't name. The admin removes the template link, the link, the object, the control or the graphic, or saves without the feature, and uploads again; the safe text says why the file was refused, and the rule label in the item's failure says which construct.
- An embedded package is read into the `inspect` child's memory, bounded by the outer ZIP caps and the child's memory limit; a chart's workbook is small, so the check stays far inside the 120-second limit.
- Delivering an Office file that a rule refuses takes either one exploit against CPython's `zlib` or `binascii`, the only two C components both children run on the same bytes, or two independent parser exploits in two children under different UIDs: one against libxml2 through `lxml` in `inspect`, and one against expat in `verify-office` (decision 8). The second child costs up to 120 more seconds of the document's parse budget.
- A construct that the rules accept but that turns out to load or run something needs no exploit at all, because both children run the same rule module and the same lists, and so does any other mistake in the rule logic. Three layers bound it. The allowlists bound the parts, relationships, field keywords, program identifiers and PowerPoint actions a file holds (decision 9). Inside an allowed part, the deny rules refuse every construct that the cited specifications describe as loading external content or running code: `macro.type`, `macro.vba`, `ext.rel`, `ext.hyperlink`, `ext.internal`, `ext.webextension`, `field.nested`, `field.hyperlink`, `ext.mailmerge`, `emb.webvideo`, `ext.vml`, `field.namespace`, `field.tracked`, `field.branch`, `ext.hover`, `ext.shapelink`, `ext.reluse`, `emb.emfprofile`, `emb.relationship`, `emb.altchunk`, `emb.activex-type`, `emb.binary-type`, `emb.activex-folder`, `emb.embeddings`, `emb.ole2`, `emb.macrosheet`, `emb.externallink`, `emb.connections`, `emb.querytable`, `emb.ddelink`, `emb.package`, `macro.formfield`, `emb.formula` and `emb.nested`, with the `svgBlip` part of `ct.type`. The residual is a construct inside an allowed part whose loading or running no cited specification describes; it is bounded only by the reader's own Office protections, Protected View and the macro and external-content settings of the reader's Office, which DocChat doesn't control. The single-rule fixtures and the passing controls saved by Office test each rule.
- The check adds one streamed pass over the package's XML parts (field instructions are read in every one), and one over each embedded package, inside the `inspect` child, so it adds no process and no network call.
- Obligations: the rule as a testable statement in 82-security.md; ingestion tests with fixtures in `tests/fixtures/documents/`: `external-template.docx`, `dde-field.docx` and `remote-image.pptx` fail with `external_content_declared`, `ole-package.docx` with `embedded_content_declared`, while a DOCX whose only external relationships are hyperlinks passes; `ole-xls.docx` (an `oleObject` holding a binary `.xls`) and `activex.docx` fail with `embedded_content_declared`, `chart-workbook.pptx` passes, `chart-external-link.pptx` (an embedded workbook with an external link) fails with `external_content_declared`, and `nested-package.docx` fails with `embedded_content_declared`; a unit test that `iterparse` resolves no external entity; the field instruction unit test (84-testing.md: instruction assembly across runs and nested fields, the refusal of `delInstrText`, of field markup inside tracked-change markup or outside the WordprocessingML main namespaces and of a field split across Markup Compatibility branches, `\"` in a `HYPERLINK` or `EMBED` instruction, the keyword after white space and no-break spaces, the `HYPERLINK` target and its switches, and the passing forms); the single-rule document check unit tests (84-testing.md), which hold the one list of single-rule fixtures: at least one fixture per rule label of `14-ingestion.md` section 15.6 item 7, each breaking that rule alone or with the allowlist rule its construct also breaks, so that `broken_rules` returns exactly the labels the list gives and both parsers fail it with the code of the rule it carries, and passing controls saved by current Office in the Transitional and the Strict form, the Word controls each with one comment and one reply; the Office allowlist unit test (the five lists and the custom-show pattern equal `14-ingestion.md` section 15.11, the comment-metadata relationship types and content types of the Word controls are exactly its Word comment metadata entries, and the two layout readers agree); the PowerPoint action and link unit test (the allowed and refused actions, hover actions and shape-level links with an external target, and the elements that may name an external relationship); the metafile record unit test (each EMF colour-profile record, alone and after other records, in an EMF part and inside a WMF escape, and the walks that fail); the embedded formula unit test (each refused function, with and without its prefix, the `|` of a DDE reference, and the same names inside string literals passing); the Office rules version unit test (`RULES_VERSION` is `OFFICE_RULES_VERSION`, and the hashes of `office_rules.py` and `zip_records.py` match the values recorded beside it); the re-inspection integration test (duty 12 queues and runs `reinspect` items, a pass sets `office_rules_version`, a refusal sets `office_rules_refused_version` and writes `document.reinspection_refused`); the rechecking citation integration test (an Office source file whose version's `office_rules_version` isn't the deployed constant answers `409 document_rechecking` and streams nothing); the Office verifier test (a stub `inspect` child that writes `ok` for `ole-package.docx` is caught by `verify-office`, and the item fails with `parse_failed`).
