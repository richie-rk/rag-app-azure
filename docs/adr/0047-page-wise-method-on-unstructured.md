# ADR 0047: Page-wise method on unstructured

- **Status:** Accepted
- **Date:** 2026-10-18
- **Decided by:** Product owner and architect
- **Specified in:** 14-ingestion.md, 01-repository.md, 82-security.md, 84-testing.md, CONTEXT.md
- **Related ADRs:** 0009, 0010, 0046, 0048, 0049, 0051, 0053, 0136, 0152

## Context

The product owner chose two ingestion methods; this one chunks page by page with the open-source `unstructured` library, tables included. Its shape is set: the high-resolution strategy with table structure, inside the ingestion container; one chunk per page of the version's PDF, with a page over the embedding model's input limit split into ordered sub-chunks that keep the page number; each table as an LLM summary followed by the table as sanitised HTML, so it is searchable as prose and exact in structure; and citations anchored to the page. A DOCX or PPTX reaches the method as the PDF the converter of ADR 0152 made from it, so a slide is one page and a Word document has the converter's pages, the same pages its renditions show.

Nothing may be fetched or reported at run time. An index must be reproducible from the exact models that were scanned with the image, ingestion must keep working once outbound traffic is filtered, and no document metadata may reach a vendor's analytics endpoint. Every model the method uses (layout, table structure and its backbone, spaCy) is therefore downloaded at image build, pinned by revision and SHA-256, into a path outside `/home`.

A page can hold more text than the embedding model accepts, and a page dense with tables easily does, so page chunks need a size limit that keeps the page number.

Vendor facts (checked 2026-10-14):

- `unstructured` 0.27.25 and `unstructured-inference` 1.6.13 are Development Status 4 (Beta) and require Python 3.11 to 3.13. Importing `unstructured` pings a telemetry endpoint and each partition call sends an event, unless `DO_NOT_TRACK` or `SCARF_NO_ANALYTICS` is set before import.
- The `hi_res` layout model `yolox` is the Hugging Face repository `unstructuredio/yolo_x_layout`, file `yolox_l0.05.onnx`, fetched with no revision; `UNSTRUCTURED_DEFAULT_MODEL_INITIALIZE_PARAMS_JSON_PATH` (`{model_path, label_map}`) loads a local file with no hub lookup. The table-structure model `microsoft/table-transformer-structure-recognition` loads through `from_pretrained` with no revision; timm's default ResNet-18 weights are `resnet18.a1_in1k`. A missing spaCy `en_core_web_sm` 3.8.0 is downloaded and installed into site-packages at run time. `HF_HUB_OFFLINE` makes the hub client use cached files only.
- PDF pages render inside one process-wide `threading.Lock`; `unstructured-inference` declares the GUI build of OpenCV; torch's Linux wheels pull CUDA packages; the OCR agent is Tesseract.
- `text-embedding-3-large` takes at most 8,192 tokens per input.

## Decision

1. **Engine.** `unstructured` 0.27.25 with `unstructured-inference` 1.6.13, method key `pagewise`, version 1 (ADR 0046). Every partition is `partition_pdf(filename=<part file>, strategy="hi_res", infer_table_structure=True, languages=<ocrLanguages>)` over the version's PDF, the converted PDF of a DOCX or PPTX included; no Office partitioner runs, and a `partition` request whose content type isn't `application/pdf` fails its schema check. Every partition runs in the isolated child process of ADR 0049.
2. **Parameters** (`PagewiseParametersV1`, `extra="forbid"`): `summarizeTables` (boolean, default `true`); `ocrLanguages` (1 to 3 unique values from `eng`, `fra`, `deu`, `spa`, `ita`, `nld`, `por`, default `["eng"]`), limited to the Tesseract packs the image installs and to three so OCR time stays bounded.
3. **Extraction in parts.** Every version's PDF is extracted in parts of `ingestion.pagewise_pages_per_extract` pages (`ops_config`, default 40, range 1 to 200), one Extract call per part: the child copies the part's pages into a temporary PDF with `pikepdf` 10.17.0, partitions it and adds `firstPage − 1` to each element's page number, so a crash resumes at the failed part. A document above `ingestion.max_pages_per_document` (default 2,000) fails with `page_limit_exceeded` before any part is parsed. Each part is written to `ingestion-work/{runId}/{documentId}/{v}/extract/part-{first:05d}-{last:05d}.json` as `{"formatVersion": 1, "method": "pagewise", "pageCount", "firstPage", "lastPage", "pages": [{"pageNumber", "elements": [{"kind", "text", "tableHtml", "headingLevel"}]}]}`, with `kind` one of `text`, `title`, `list_item`, `table`, `header`, `footer` and `other`, in the parser's reading order.
4. **Page assignment.** The child assigns every element to a page before it writes the file: the element's own page plus the part offset; an element without one takes the page of the element before it, or the part's first page when it comes first; a number outside the part is clamped into it. This is the page-wise half of the page rule in ADR 0048, so every chunk of every format has a page from 1 to the page count of the version's PDF.
5. **Tables.** Each table's `text_as_html` passes `nh3.clean()` (`nh3` 0.3.7) with the tags `table`, `caption`, `thead`, `tbody`, `tfoot`, `tr`, `th`, `td` and `br`, the attributes `colspan` and `rowspan` on `th` and `td` and `scope` on `th`, no URL schemes and comments stripped; `colspan` and `rowspan` values outside 1 to 1,000 are removed after cleaning, and every other element keeps only its text. When `summarizeTables` is true, Enrich asks the table-summary deployment for a plain-text summary of each table (`reasoning_effort: "low"`, `max_completion_tokens: 2000`, at most 300 visible tokens, at most `ingestion.table_summary_concurrency` (default 4) calls in flight per document), saved to `enrich/table-summaries.jsonl`, keyed by the SHA-256 of the sanitised HTML, after every 16 finished tables, so a retried Enrich resumes after the last saved batch and Chunk reads every summary from that file. A filtered or unusable summary leaves the table indexed as HTML alone with a warning (ADR 0051).
6. **Chunks.** One chunk per page: the page's elements in reading order joined by blank lines, `header`, `footer` and `other` elements kept as text, and each `table` element as its summary, a blank line and its sanitised HTML (the HTML alone without a summary). An empty page gives no chunk. `headingPath` is the page's `title` elements so far, at most 8, each cut to 200 characters (empty when the page has none).
7. **Size guard.** Tokens are counted with the physical index's encoding (`cl100k_base` for `text-embedding-3-large`, from the image's pre-filled `tiktoken` cache). Content above 8,000 tokens, 192 below the model's input limit, splits into ordered sub-chunks: at element boundaries first (each sub-chunk filled up to 8,000 tokens), then, for one element above 8,000, at sentence boundaries (`(?<=[.!?。！？])\s+`), then at token boundaries (decoded slices of 8,000 tokens). A table above 8,000 tokens splits between `</tr>` boundaries with its header rows repeated. Every sub-chunk keeps the page number and heading path.
8. **DOCX and PPTX sources.** A converted PDF carries the Office file's text in its text layer, which `hi_res` reads as it reads any PDF's, so items 3 to 7 apply unchanged and the method adds no OCR pass of its own over page images of an Office file. Each slide of a deck is one page, a Word document is cut at the converter's page breaks, and a Word heading enters the chunk's `headingPath` when the layout model reads it as a title on its page; the citation names the page.
9. **Ordinals** run 0, 1, 2 and on in document order. Zero chunks fail the item with `no_extractable_text`; more than 100,000 with `chunk_limit_exceeded`.
10. **Models pinned and offline.** `apps/ingestion/models.lock.json` pins, by repository, revision (commit hash) and SHA-256 of every file: the layout model `unstructuredio/yolo_x_layout` (`yolox_l0.05.onnx`, loaded from a local path through `UNSTRUCTURED_DEFAULT_MODEL_INITIALIZE_PARAMS_JSON_PATH=/opt/docchat/models/layout/params.json`); the table-structure model `microsoft/table-transformer-structure-recognition`; its backbone `timm/resnet18.a1_in1k` (`model.safetensors`, loaded by timm from the Hugging Face cache); and spaCy `en_core_web_sm` 3.8.0, installed from its release wheel with SHA-256 `1932429db727d4bff3deed6b34cfc05df17794f4a52eeb26cf8928f7c1a0fb85`. `apps/ingestion/image/fetch_models.py` downloads each file at its pinned revision during the image build, checks every hash, writes the Hugging Face cache layout under `/opt/docchat/models/hf` (with `refs/main` pointing at the pinned commit) and fails the build on any mismatch. `/opt/docchat` is made read-only (`chmod -R a-w`). The image sets `HF_HOME=/opt/docchat/models/hf`, `HF_HUB_OFFLINE=1`, `HF_HUB_DISABLE_TELEMETRY=1`, `DO_NOT_TRACK=true`, `SCARF_NO_ANALYTICS=true` and `OMP_NUM_THREADS=1`, and installs `libmagic1`, `poppler-utils`, `tesseract-ocr` with the packs `eng`, `fra`, `deu`, `spa`, `ita`, `nld` and `por`, and `libglib2.0-0`; OpenCV is `opencv-python-headless` 5.0.0.93 through a uv override that removes `opencv-python`, torch comes from the CPU wheel index and the build fails if any `nvidia-*` distribution is installed. LibreOffice is in the image only as the converter of ADR 0152, run by the `convert` child; the method itself never starts it, and no pandoc is installed.
11. **Offline self-check.** The image build's last step, `RUN --network=none`, converts fixture DOCX and PPTX files with the `convert` command and partitions a fixture PDF (with a table and a scanned page) and both converted PDFs through the parsing runner as the child's user, with the request flag `failOnNetwork`: `parse_worker` installs an audit hook (`sys.addaudithook`) that ends the child with exit code 3 on any `socket.getaddrinfo` or `socket.connect` event, and with `HF_HUB_OFFLINE=1` any lookup of an uncached file raises, so a model that tries to download fails the build. It asserts that the PDF's table element carries `text_as_html`. A stage-1 spike runs the same check with `docker run --network none` before stage 1 closes.
12. **GA alternative.** `unstructured` is a Beta library, used because the product owner named it. The GA alternative is the recursive method on Document Intelligence (ADR 0048), which is also the default method `adminGetIndexOptions` offers; ADR 0009 lists this dependency.

## Alternatives considered

- **The `fast` or `ocr_only` strategies.** Rejected: the method needs the `hi_res` strategy with table structure, the path that gives each table its HTML (`text_as_html`), which the image's self-check asserts.
- **Models fetched on first use and cached on the instance.** Rejected: a run-time download ties ingestion to Hugging Face's availability and to an open outbound path, loads whatever the repository's main branch holds that day, and leaves no record of the model that produced an index.
- **Pinning by revision without file hashes.** Rejected: a hash catches a corrupted or substituted download at build time; the revision alone doesn't.
- **One chunk per page with no size guard.** Rejected: an over-long page would fail the embedding call or lose text to truncation.
- **Splitting every page into passages of a set size.** Rejected: the product owner asked for page-wise chunks; bounded passages are the recursive method's job.
- **Tables as text only, or as Markdown.** Rejected: the summary makes a table searchable as prose and the HTML keeps it exact in structure; Markdown can't carry merged cells.
- **The native Office partitioners, `partition_docx` and `partition_pptx`.** Rejected (ADR 0152): a second parser would read the hostile Office file beside the converter, and its pages would need mapping onto the converted PDF's pages that readers see; one parse of the converted PDF gives every chunk the page its rendition shows.

## Consequences

- Page-wise chunks can reach 8,000 tokens, so a prompt keeps fewer of them under chat's token budget than it keeps 512-token passages; that is why `recursive` is the default for new indexes.
- `hi_res` parsing is CPU-heavy (the child allows 30 seconds a page within a part's 1,200-second limit) and every `partition` child loads the layout and table-structure models again; 40-page parts spread that start-up cost and keep a crash's loss to one part.
- Every model or library upgrade that changes chunk output is a new method version and a re-ingest of every page-wise index (ADR 0046); model pins move only through `fetch_models.py --update <repository> <revision>` and a reviewed pull request.
- The Beta library is a supply-chain risk the product owner accepted; CI's image scan (ADR 0136) and Dependabot pull requests that pass the ingestion suite and the offline self-check are the controls.
- Telemetry stays off, and nothing in the method needs outbound access, so egress filtering can close outbound traffic later with no change here.
- Tests: on `tables.pdf`, one chunk per page with each table as summary then sanitised HTML; on `scanned.pdf`, OCR text from every page with the expectation file's page numbers; on the converted PDFs of `headings.docx` and `slides.pptx`, one chunk per page, page numbers from 1 to the converted PDF's page count, the heading paths of the titles on each page, and one page per slide with both tables summarised; a 20,000-token page split into sub-chunks of at most 8,000 tokens that keep the page; the sanitiser removing scripts, styles, event attributes, links and images and dropping `colspan` 0 and 5,000; `blank-scan.pdf` failing with `no_extractable_text` at stage `chunk`; page numbers within 1 to the page count, with an unnumbered element taking the previous page and an out-of-range one clamped; the image self-check passing with no network.
